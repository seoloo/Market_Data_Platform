# 16 — H2 제안 및 사전 등록 선별 (2026-09-22)

**상태: 사용자 승인 대기.** H1(D11)이 그랬듯 가설 확정은 사용자 결정 사항이다.

---

## 1. H1 에서 배운 것 하나

우리는 **전체 파이프라인을 다 만든 뒤에** edge 가 없다는 걸 알았다.
Phase 1~3 전부를 통과하고 Phase 4 에서야 "거래 0건"이 나왔다.

다음 가설은 **순서를 뒤집는다.**

```
H1 방식:  가설 → feature 구현 → 전략 → 엔진 → 백테스트 → 기각   (수 주)
H2 방식:  가설 → 사전 등록 → 원자료 선별 → 통과해야만 구현      (수 일)
```

인프라는 이미 있다. 새 정보원이 **선행 예측력을 갖는지**만 먼저 확인하면 되고,
그건 전략 코드 없이 edge table + embargo + 검정력 도구만으로 가능하다.

## 2. H2 (제안)

> **BTC 무기한 선물에서 레버리지 포지셔닝이 한쪽으로 극단적으로 쏠리면, 그 쏠림이
> 해소되는 과정에서 반대 방향으로 가격이 움직이는 경향이 있으며, 그 크기는 2~6시간
> 안에 왕복 거래비용을 초과한다.**

### 왜 H1 과 종류가 다른가

H1 의 5개 feature 는 전부 **가격에서 파생된** 값이었다. 같은 정보를 다섯 가지 방법으로
바라본 것에 가깝고, 실측에서 아무것도 나오지 않았다 (15 §6).

H2 는 **가격이 아닌 데이터**를 쓴다 — 누가 얼마나 들고 있고, 얼마를 지불하며 버티고
있는가. 차트 패턴이 아니라 **무기한 선물의 구조적 성질**이다.

| | H1 | H2 |
|---|---|---|
| 정보원 | 가격·거래량 (파생) | 미결제약정·funding·테이커 플로우 (비파생) |
| 메커니즘 | 추세 지속 (행동적) | 포지션 청산 압력 (구조적) |
| 검증 horizon | 2~24h (24h 는 측정 불가) | **2~6h** (검정력 확보 구간) |
| 반증 방법 | 사후 백테스트 | **사전 등록 선별** |

### 메커니즘 (왜 그럴 것이라 기대하는가)

무기한 선물은 만기가 없다. 그래서 현물과의 괴리를 **funding 지불**로 강제 수렴시킨다.

1. 가격이 오르면 레버리지 롱이 쌓인다 → 미결제약정 증가 + funding 양수 확대
2. 롱이 숏에게 계속 지불한다 → 버티는 비용이 누적된다
3. 작은 하락에도 증거금이 부족한 포지션부터 강제청산 → 매도가 매도를 부른다
4. 쏠림이 클수록 3의 연쇄가 길다

이건 가설이 아니라 거래소 설계의 결과다. **가설인 부분은 "그 되돌림 크기가 비용을
넘는가"** 하나뿐이다. 그래서 반증이 명확하다.

> ⚠ 반대 가능성도 명시한다: 쏠림은 **정보**일 수도 있다 (다들 사는 데는 이유가 있다).
> 그러면 H2 는 부호가 반대로 나오고, 그것도 유효한 결과다. 선별은 양방향을 다 본다.

## 3. 데이터 — 이미 확보 가능함을 확인했다

`data.binance.vision` 의 `futures/um/daily/metrics/BTCUSDT/` 에 **5분 단위**로 있다
(2026-09-22 확인, 2021-01 이후 전 구간 존재).

```
create_time, symbol, sum_open_interest, sum_open_interest_value,
count_toptrader_long_short_ratio, sum_toptrader_long_short_ratio,
count_long_short_ratio, sum_taker_long_short_vol_ratio
```

| 컬럼 | 의미 |
|---|---|
| `sum_open_interest` | 미결제약정 (BTC) — 쌓인 포지션의 총량 |
| `sum_toptrader_long_short_ratio` | 상위 트레이더 명목가 롱/숏 비 |
| `count_long_short_ratio` | 전체 계좌 수 기준 롱/숏 비 (군중) |
| `sum_taker_long_short_vol_ratio` | 테이커 매수/매도 거래량 비 (공격적 주문 불균형) |

`funding_rates` **7,305건은 이미 적재되어 있다** (2020-01~2026-08, 결측 0건).

일별 파일뿐이라 월별 벌크가 없다 → 2021-01 이후 약 2,100개 파일. 캔들 백필과 같은
체크섬 검증 경로를 재사용하면 된다.

**데이터 시작이 2021-01 이므로 TRAIN 은 2021~2022 로 유지된다** (H1 과 동일 구간).

## 4. 사전 등록 선별 — 코드를 쓰기 전에 이 문서로 고정한다

### 4.1 후보 신호 (5개, 결과를 보기 전 고정)

전부 **causal 정규화**만 쓴다 (전체 표본 통계 금지).

| ID | 정의 | TF | 근거 |
|---|---|---|---|
| `F1_funding_extreme` | funding rate 의 30일 causal 백분위 | 8h | 쏠림 유지 비용 |
| `F2_oi_surge` | OI 1시간 변화율의 7일 causal z | 5m | 신규 레버리지 유입 |
| `F3_oi_price_divergence` | OI 증가 × 가격 정체 (부호 곱) | 5m | 흡수 — 신규 포지션이 가격을 못 밀면 갇힌 것 |
| `F4_taker_imbalance` | `sum_taker_long_short_vol_ratio` 의 7일 causal z | 5m | 공격적 주문의 방향 쏠림 |
| `F5_crowd_divergence` | `count_long_short_ratio` z − `sum_toptrader_long_short_ratio` z | 5m | 군중과 상위 트레이더의 괴리 |

### 4.2 선별 절차

1. 위 5개를 각각 **단독으로** 5분 시점마다 계산한다.
2. 각 신호의 causal 백분위 상·하위 10% 구간에서 **2h / 4h / 6h 선행수익**을 잰다.
3. **embargo = horizon** 으로 중첩을 제거한다 (15 §4 의 교훈).
4. 평균과 표준오차, 양수 비율을 낸다. 부호는 양방향 모두 기록한다.

전략 코드·점수식·사이징을 **하나도 만들지 않는다.** 원자료의 조건부 평균만 본다.

### 4.3 통과 기준 (미리 고정 — 나중에 낮추지 않는다)

| 기준 | 값 |
|---|---|
| 필요 edge | 평균 − 2SE > **18bps** (왕복 13 + 마진 5) |
| 최소 독립 표본 | 신호당 **n ≥ 200** |
| horizon 일관성 | 2h·4h·6h 중 **최소 2개**에서 부호가 같고 하나 이상이 기준 통과 |
| 연도 일관성 | 2021 과 2022 **각각** 에서 부호가 같아야 함 (한 해가 전체를 만들면 실패) |
| 단조성 | 신호를 5분위로 나눴을 때 극단 분위가 중간 분위보다 나아야 함 |

### 4.4 중단 기준 (D5 미정 항목에 대한 답을 겸한다)

- **5개 신호 모두 통과 실패** → H2 기각. 조합 탐색으로 넘어가지 않는다.
  (5개를 다 실패하고 나서 조합을 뒤지는 것이 곧 과최적화다.)
- **1개 이상 통과** → 통과한 신호만으로 최소 전략을 구성하고 Phase 2 로 복귀.
- H2 도 기각되면 **세 번째 가설을 만들지 않고 사용자와 접근 자체를 재검토한다.**

## 5. 별도 레버 — 비용 구조 (가설과 독립)

어떤 가설을 쓰든 18bps 기준은 높다. 이건 전략이 아니라 **체결 방식**의 문제다.

| 항목 | 현재 (taker 왕복) | post-only 진입 시 |
|---|---:|---:|
| 진입 수수료 | 4.5bps | **2.0bps** (maker) |
| 청산 수수료 | 4.5bps | 4.5bps |
| 슬리피지 | 4.0bps | **1.0bps** (지정가) |
| **왕복** | **13.0bps** | **7.5bps** |

기준이 18 → 12.5bps 로 낮아진다. 기준을 **완화**하는 것이 아니라 비용을 **실제로**
줄이는 것이므로 다른 성격의 변경이다.

대가: 지정가는 체결이 보장되지 않는다 (07 §3.1 이 낙관적 처리를 경고한다).
미체결률을 보수적으로 가정하고 백테스트해야 하며, **H2 선별 통과 이후에** 다룬다.
지금 도입하면 무엇이 효과를 냈는지 분리할 수 없다.
