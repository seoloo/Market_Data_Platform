# 10 — 개발 로드맵 및 MVP 범위 (L, M)

## 1. 원칙

- 각 Phase 에는 **종료 게이트**가 있다. 게이트를 통과하지 못하면 다음 Phase 로 가지 않는다
- 게이트를 낮춰서 통과시키지 않는다. 통과하지 못하면 **되돌아가서 가설을 바꾼다**
- 실거래 자금 투입은 Phase 8 이전에 없다

```
P1 기반 → P2 전략코어 → P3 백테스트 → P4 검증 ┐
                                              ├─ [게이트 실패 시 P2 로 복귀]
P5 거래소연동 → P6 Paper → P7 Testnet → P8 소액실거래 → P9 실거래 → P10+ 확장
```

- 매일 Parity Test 자동 실행

**병행 산출물 — 대시보드 (D10 / [14-ui-and-packaging.md](14-ui-and-packaging.md))**

| 항목 | 내용 |

| 화면 | 요약 / 자산곡선 / **달력(일별 손익)** / 거래목록 / **거래상세(판단근거)** |
| `dashboard.py` | 엔트리포인트 |

### Phase 9 — 실거래 (단계적 확대)

- 자본을 한 번에 늘리지 않는다. 예: 4주마다 이전 규모의 1.5배 이하
- 각 단계마다 지표 재확인. DD 한도 도달 시 규모 축소
- 월 1회 전략 리뷰: 실거래 성과 vs 백테스트 기대치 비교 (편차가 크면 원인 규명까지 확대 중단)

| 순서 | 항목 | 선행 조건 |
|---|---|---|
| 10 | 거시 캘린더 → surprise 스코어링 | consensus 데이터 자체 수집 1년+ |
| 11 | 뉴스 파이프라인 (게이트 용도) | 라이선스 확보 |
| 12 | FOMC 문서 LLM 분석 | 11 완료 |
| 13 | Elliott 파동 카운팅 (실험) | 구조 feature 가 유효함을 먼저 입증 |
| 14 | Trailing stop, 부분 익절 | 기본 전략 안정화 |
| 14b | 대시보드 진단 화면 확장 (veto 분포, regime 분해) | 실거래 데이터 축적 |
| 15 | 가중치 walk-forward 최적화 | 등가중 대비 개선 입증 가능한 데이터량 확보 |
| 16 | 다중 심볼 (ETH 등) | 단일 심볼 6개월 안정 운용 |

**각 확장은 반드시 A/B 로 검증한다**: 기능 off 백테스트 vs on 백테스트를 out-of-sample 에서 비교.
개선이 잡음 수준이면 **넣지 않는다**. (원 명세 §19-5 요구사항)

## 3. MVP 에서 제외할 기능 (M)

| 제외 항목 | 이유 | 대체 |
|---|---|---|
| **Elliott Wave 파동 카운팅** | 재현 불가·repainting·조합 폭발. 백테스트-실거래 불일치의 최대 원인 | swing 구조 + 피보나치 위치만 (→ 06 §7) |
| **뉴스 수집·LLM 분석** | 백테스트로 검증 불가 (LLM이 결말을 안다). 구현 복잡도 대비 검증 가치 낮음 | Phase 11에서 **게이트 용도**로만 |
| **거시 surprise 스코어링** | consensus 과거 데이터 확보 불가 | 캘린더 블랙아웃만 (게이트 G6) |
| **FOMC 문서 AI 분석** | 위와 동일 + 연 8회 이벤트로 표본 부족 | Phase 12 |
| **가중치 자동 최적화** | 과최적화 생성기 | 등가중 고정 |
| **가변 포지션 사이징** | 자유도 증가. 고정 사이징이 먼저 검증되어야 함 | `size_multiplier = 1.0` 고정 |
| **Trailing stop** | 백테스트 재현이 까다롭고 파라미터가 늘어남 | 고정 SL/TP |
| **피라미딩 / 분할 진입** | 상태 복잡도 급증, 복구 로직 난이도 상승 | 심볼당 포지션 1개 |
| **지정가 진입** | 체결 시뮬 불확실성 | 시장가만 |
| **다중 심볼 / 다중 거래소** | 검증 안 된 전략의 확장은 무의미 | BTCUSDT 단일 |
| **웹 대시보드** | MVP(Phase 1~5) 에는 불필요 | Telegram + SQL 쿼리 → **Phase 6 에서 구현** (D10) |
| **매매 엔진 exe 로 실거래** | Windows 절전·재부팅으로 신호청산이 멈춘다 | 실거래는 Linux VPS + systemd (D10) |
| **지표 15종 전부** | 상관 중복 + 표본 부족 | feature 5개 |
| **1분 스캘핑** | 비용 구조상 개인이 이기기 어려움 | 보유기간을 먼저 결정 (→ 12-critique) |

### MVP 에 **반드시 포함**되는 것

데이터 수집·무결성 / feature 5개 / bias-trigger 스코어링 / 히스테리시스 정책 /
비용 게이트 / Risk Engine 전 게이트 / 거래소 측 보호주문 / 멱등 주문 / reconciliation /
상태머신 / 백테스트 엔진 + 검증 프로토콜 / decisions 저널 / Telegram / 워치독

> MVP를 "작게" 만드는 것은 기능을 줄이는 것이지 **안전장치를 줄이는 것이 아니다.**
> 위 목록에서 안전 관련 항목은 하나도 뺄 수 없다.

## 4. 일정 감각

| Phase | 낙관 | 현실 |
|---|---|---|
| P1 기반 | 1주 | 2주 |
| P2 전략코어 | 2주 | 3주 |
| P3 백테스트 | 2주 | 3주 |
| P4 검증 | 3주 | **6주~ (반복)** |
| P5 거래소 | 2주 | 3주 |
| P6 Paper | 4주 | 4주 (단축 불가) |
| P7 Testnet | 1주 | 2주 |
| P8 소액 | 4주 | 4주 (단축 불가) |
| **합계** | **19주** | **27주+** |

P6/P8 의 4주는 **달력 시간**이므로 개발 속도와 무관하게 단축할 수 없다.
전체적으로 **실거래까지 최소 6개월**을 예상하는 것이 현실적이다.
