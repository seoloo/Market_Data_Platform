# 23 — H3 사전 등록 (2026-09-22)

> **이 문서는 선별을 실행하기 전에 작성했다.** 결과를 보고 기준을 바꾸면 사전 등록의

> ([16](16-h2-proposal.md) §3 의 2022 결측 정정이 그 예다).

## 1. H3

> **BTC 무기한 선물 시장에서 심볼 간 포지셔닝 쏠림의 차이는 이후 2~6시간의 상대
> 수익률 차이로 이어지며, 그 크기는 왕복 거래비용을 초과한다.**

H2 와 무엇이 다른가 — **묻는 질문이 다르다.**

| | H2 | H3 |
|---|---|---|
| 질문 | "BTC 가 오를까" | "19개 중 어느 게 **상대적으로** 셀까" |
| 잡음 | 시장 전체 방향 (6h SD 123bps) | 종목 고유 움직임만 (6h SD 약 50bps) |
| 포지션 | 단방향 | **롱숏 (시장 중립)** |
| 표본 | 연 190개 | 연 약 1,460개 |

정보원은 H2 와 같다 (포지셔닝 지표). **바꾼 것은 지표가 아니라 실험 설계다.**

## 2. 후보 신호 5개 (결과를 보기 전 고정)

매 리밸런스 시점에 **그 시점 거래 가능한 모든 심볼**을 신호값으로 정렬한다.
전부 causal 정규화만 쓴다.

| ID | 정의 | 근거 |
|---|---|---|
| `X1_rel_funding` | funding rate 의 횡단면 순위 | 가장 비싸게 유지되는 쏠림 |
| `X2_rel_oi_change` | OI 1시간 로그변화의 횡단면 순위 | 신규 레버리지가 몰린 종목 |
| `X3_rel_taker` | taker 매수/매도 비의 횡단면 순위 | 공격적 주문이 쏠린 종목 |
| `X4_rel_crowd_gap` | (군중 롱숏비 z − 상위 트레이더 롱숏비 z) 횡단면 순위 | H2 의 F5 교차 버전 — 단일 심볼에서 유일하게 구조를 보였다 |
| `X5_rel_reversal` | 직전 6시간 수익률의 횡단면 순위 | **벤치마크.** 문서화된 단기 역전 효과. 가격 파생이지만 횡단면은 H1 과 다른 검정이다 |

**방향을 미리 정하지 않는다.** 상위 k 롱 / 하위 k 숏 포트폴리오의 부호를 결과에서 읽는다.

## 3. 포트폴리오 구성

| 항목 | 값 |
|---|---|
| 다리 크기 k | 3 (상위 3 롱 + 하위 3 숏) |
| 가중 | 등가중 |
| 리밸런스 | horizon 마다 (2h / 4h / 6h 각각 별도 측정) |
| 중첩 제거 | **embargo = horizon** ([15](15-h1-postmortem.md) §4) |
| 수익 정의 | `(롱 평균 − 숏 평균) / 2` — 자본 대비 |

비용이 자본 대비 변하지 않는 이유: 자본을 6개 포지션에 나눠 담으므로 명목가 합이
자본과 같고, 각 포지션이 자기 명목가에 대해 비용을 낸다.

## 4. 유니버스 — 생존 편향 제거 (필수)

[22](22-multi-symbol-pivot.md) §5 에서 2023-01 상장 12개 중 **6개가 폐지**됨을 확인했다.
오늘 목록으로 과거를 재면 숏 수익이 통째로 빠진다.

1. 유니버스는 **각 시점에 실제로 거래 가능했던 심볼**로 만든다.
2. 폐지 심볼도 **살아 있던 기간만큼** 포함한다.
3. 유동성 하한을 쓸 경우에도 **그 시점 기준**으로 판단한다.

## 5. 통과 기준 (미리 고정 — 나중에 낮추지 않는다)

| 기준 | 값 |
|---|---|
| **필요 edge** | 평균 − 2SE > **22bps** (알트 보수 기준) |
| 참고 지표 | 18bps (BTC 기준) 도 함께 보고하되 **판정은 22bps** 로 한다 |
| 최소 표본 | **n ≥ 200** (아래 해석 참조) |
| horizon 일관성 | 2h·4h·6h 중 **2개 이상** 부호 동일 + 하나 이상 기준 통과 |
| 연도 일관성 | 선별 구간인 **2023·2024 각각** 부호 동일 |
| 단조성 | 5분위 평균이 극단에서 단조 |

**판정 결합 방식 명시 (2026-09-22, 결과 파일 열람 전)**: 위 표의 조건은 서로 따로
참고하는 지표가 아니라 한 신호의 최종 통과 조건이다. 즉, 같은 horizon이
`평균 − 2SE > 22bps`, `n ≥ 200`, 5분위 단조성, TRAIN 연도 부호 일관성을 모두
만족하고, 다른 horizon 하나 이상이 그 horizon과 같은 부호여야 통과한다.

처음 문구의 `2023·2024·2025`는 §7의 데이터 분할과 충돌했다. 2025는 선별에 쓰면
안 되는 **VALIDATION**이므로 TRAIN 판정에는 2023·2024만 사용한다. 통과 신호가
나올 때에만 2025에서 방향과 효과를 정의 그대로 한 번 재현한다. 이 정정은 H3 실행
프로세스가 돌아가는 동안 했지만, 결과 JSON이 생성되거나 수치를 열람하기 전이었다.
기준을 낮춘 것이 아니라 기존 표의 조건과 구간 분할을 실행 가능한 한 문장으로 묶은
것이다.

**"최소 표본" 의 해석 확정 (2026-09-22, 실행 전)**: 처음에 "검정력 계산에서 나온 필요
표본 이상" 이라고만 적었는데 이는 효과 크기에 따라 달라져 코드로 옮길 수 없다.
그 요구는 사실 `평균 − 2SE > 기준` 검사가 이미 강제한다 — 표본이 적으면 SE 가 커져
통과하지 못한다. 따라서 이 항목의 역할은 **표본이 극히 적을 때의 우연**을 막는 것으로
한정하고, H2 와 같은 **200** 으로 고정한다.

왜 22bps 인가: BTC 왕복 13 + 마진 5 = 18 이지만, 알트는 5분 레인지가 BTC 대비
최대 2.1배다 ([22](22-multi-symbol-pivot.md) §3 실측). 슬리피지를 2배로 잡아 22 로 둔다.
**비용을 낙관하는 것이 이 프로젝트에서 두 번 문제가 됐다** ([20](20-signal-time-fills.md)).

## 6. 중단 기준

- **5개 전부 실패** → H3 기각. 조합 탐색으로 넘어가지 않는다.
- **1개 이상 통과** → VALIDATION 에서 **정의 그대로** 1회 재현.
  이번에는 재현 검정의 **검정력을 먼저 계산**한다 —
  1년 재현을 등록했다가 검정력 부족으로 판정 못 한 것이 H2 의 실수였다
  ([18](18-h2-validation-result.md) §2).
- **재현 실패** → H3 기각.
- **H3 도 기각되면 네 번째 가설을 만들지 않는다.** 그때는 접근 자체를 접는다.

측정하지 않고 멈춘다** (`MIN_COVERAGE`). 실제 적재율은 결과 JSON 에도 남긴다.
