# 01 — 요구사항 재정리 (A)

## 1. 시스템 목적

> 여러 독립적인 시장 신호를 수집·수치화하고, **비용과 위험을 고려한 일관된 규칙**에 따라 거래하며,
> 모든 결과를 기록하여 **전략의 통계적 우위가 실제로 존재하는지를 지속적으로 검증**하는 시스템.

이 목적문에서 도출되는 우선순위:

1. **기록과 재현성** > 수익
2. **손실 통제** > 수익
3. **검증 가능성** > 기능 개수
4. **백테스트-실거래 일치** > 백테스트 성능

## 2. 비목적 (Non-goals) — 명시적으로 하지 않는 것

| 비목적 | 이유 |
|---|---|
| BTC 가격 예측 정확도 극대화 | 예측 정확도와 수익성은 다른 문제. 비용 후 기댓값이 기준 |
| 고빈도 거래(HFT) / 지연시간 경쟁 | 인프라·수수료 구조상 개인이 이길 수 없는 영역 |
| LLM에게 매매 판단 위임 | 재현 불가, 백테스트 불가, 비결정론적 |
| 초기부터 다중 거래소 / 다중 심볼 | 복잡도만 증가, 검증되지 않은 전략의 확장은 무의미 |
| 자동 파라미터 최적화 (초기) | 과최적화 생성기가 됨 |

## 3. 기능 요구사항

### FR-1 데이터
- FR-1.1 Binance USD-M Futures BTCUSDT의 1m/5m/15m/1h/4h/1d 캔들 수집·저장
- FR-1.2 과거 캔들 백필(backfill) 및 무결성 검증(결측봉·중복봉·시각 정렬)
- FR-1.3 Funding rate 이력 수집
- FR-1.4 실시간 WebSocket 캔들/체결/사용자 데이터 스트림, 끊김 시 REST 갭 보정
- FR-1.5 모든 시각은 UTC epoch milliseconds로 저장. 로컬 타임존 사용 금지

### FR-2 전략
- FR-2.1 **마감된** 봉만 사용하여 전략 평가 (형성 중 봉 사용 금지)
- FR-2.2 다중 타임프레임 신호를 **느린 층(Bias)** 과 **빠른 층(Trigger)** 으로 분리 (→ 06 문서)
- FR-2.3 `direction`, `long_score`, `short_score`, `risk_score`, `confidence_score` 산출
- FR-2.4 진입은 70점 임계값, 청산은 반대 방향 점수의 엄격한 역전으로 분리 (D12)
- FR-2.5 모든 요소는 config로 개별 on/off 가능
- FR-2.6 Strategy Core는 순수 함수 — 시간·네트워크·DB·난수 접근 금지

### FR-3 리스크
- FR-3.1 Risk Engine이 신규 진입에 대한 **최종 거부권**을 가짐
- FR-3.2 Risk Engine은 **청산을 막을 수 없음** (안전 방향 동작은 항상 허용)
- FR-3.3 포지션 크기는 계좌 위험 기준(risk-based sizing)으로 산출. 레버리지는 결과값
- FR-3.4 거래소 측 보호 주문(reduce-only stop)이 **항상** 존재해야 함
- FR-3.5 일일 손실 / 누적 DD / 연속 손실 / 거래 횟수 한도 도달 시 자동 정지
- FR-3.6 킬 스위치 (외부에서 즉시 신규진입 차단, 선택적 전량 청산)

### FR-4 비용
- FR-4.1 maker/taker fee, funding, slippage를 백테스트와 실거래 판단에 **동일하게** 반영
- FR-4.2 `expected_edge <= expected_cost + minimum_required_edge` 이면 진입 금지
- FR-4.3 수수료율은 config 또는 거래소 API에서 취득 (하드코딩 금지)

### FR-5 실행
- FR-5.1 결정론적 `clientOrderId` 기반 멱등 주문
- FR-5.2 재시작 시 거래소 상태를 **진실의 원천(source of truth)** 으로 하여 로컬 DB 동기화
- FR-5.3 중복 진입 원천 차단
- FR-5.4 주문 응답 유실 시 재주문 전 실제 주문 상태 조회
- FR-5.5 부분 체결 정확 처리

### FR-6 기록
- FR-6.1 모든 평가 시점의 점수·구성요소·설정 해시·코드 버전 저장
- FR-6.2 임의 과거 거래에 대해 "왜 그 거래를 했는가"를 재구성 가능
- FR-6.3 config 버전 관리 (해시 → 전체 설정 스냅샷)

### FR-7 백테스트
- FR-7.1 실거래와 **동일한 Strategy/Risk 코드 경로** 사용
- FR-7.2 Look-ahead / future leakage 구조적 차단
- FR-7.3 상위 타임프레임 전략의 봉 내부 경로는 1m 데이터로 해소
- FR-7.4 Train / Validation / Out-of-sample 분리, Walk-forward 지원
- FR-7.5 시장 regime별 성과 분해

### FR-8 운영
- FR-8.1 Telegram 즉시 알림 및 일일 리포트
- FR-8.2 헬스체크·워치독·자동 재시작 (systemd)
- FR-8.3 구조화 로깅 (JSON lines)

## 5. 제약

- 개발 환경: Windows 11 / 운영 환경: Linux (x86_64), Python 3.11+
- 초기 거래소: Binance USD-M Futures (One-way position mode, Isolated margin 권장)

## 6. 성공 기준 (Phase 0 관점)

시스템의 성공은 "수익"이 아니라 다음으로 정의한다:

1. 임의의 과거 거래 1건을 골라 그 판단 근거를 **완전히 재구성**할 수 있다
2. 백테스트가 내린 결정과 라이브가 내린 결정이 **동일 입력에서 100% 일치**한다
3. 프로세스를 임의 시점에 죽였다 살려도 **포지션 상태가 정확히 복구**된다
4. 전략이 out-of-sample에서 **비용 반영 후** 양의 기댓값을 보이는지에 대해 **정직한 답**(그것이 "아니오"라도)을 낼 수 있다

> 4번의 답이 "아니오"일 가능성이 현실적으로 높다. 그 경우 실거래로 넘어가지 않는 것이 이 시스템의 올바른 동작이다.
