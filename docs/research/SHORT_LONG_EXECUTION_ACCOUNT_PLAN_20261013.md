## 4. ‘숏 청산 확인’의 정확한 정의

각 종목의 `FLAT_SETTLED` 증거는 다음을 **모두** 갖춰야 한다.

1. 이번 계좌/환경/종목의 신선한 원격 signed 선물 수량이 **정확히0**.
   step 이하 잔량 허용은 로컬/원격 대조 오차 규칙이지 숏을0으로 지우는 규칙이 아니다.
2. 해당 episode의 숏 신규/청산/정정/취소 요청에 IN_FLIGHT·UNKNOWN이 없음.
   기존 신규 숏 잔여 주문은 취소 **접수**가 아니라 종결 확인과 누적 체결 반영까지 완료.
3. 원격 주문 목록과 원주문/체결 대조가 일치하고, 로컬 누적 체결은 감소하지 않음.
4. 전송 조정자에 미종결 claim/늦게 복귀할 구 작업자가 없음. lease 만료·프로세스 종료는
   네트워크 취소/미접수 증거가 아니다. 조기 부재 NOT_PLACED 금지.
5. 같은 심볼에 소유권 불명 주문/포지션이 없음. 있으면 신규 롱을 막고 수동 확인.
6. 원격0 확인 **후** 자기 잔여 스톱/청산 주문을 대조·정리. 숏 잔량이 있을 때 보호부터 취소하지 않음.
7. 조회 시작/완료/수신 시각·정보 품질·주문 세대/범위·config/code/snapshot 식별자를 남김.
   여러 조회의 시간이 다르면 한 원자적 snapshot이라고 부르지 않음.

`FILLED`, `CANCELED`, `done=True`, 주문 전송 성공, WS 연결 정상 중 하나만으로 인정하지 않는다.
스톱 자동 정리는 원격 증거로 확인하지, API 호출 없이 있다고 가정하지 않는다.
최소수량 미만 잔량은 `SHORT_RESIDUAL`로 보호·대조를 유지한다. 일반 시장가 dust 청산 예외를 만들지 않는다.
기존 비상 스톱/보호 실패 예외는 실제 해당 조건에서만 적용하고 평범한 복귀에 확대하지 않는다.

## 5. 상태·취소·시간 계약

```text
LONG_TARGET_VALID → CANCEL_OLD_SHORT_OPEN → SHORT_CLOSING
     → FLAT_UNSETTLED → FLAT_SETTLED → COOLDOWN → LONG_RECHECK
     → LONG_ORDER_PENDING → LONG_PARTIAL → LONG_TARGET_REACHED
```

| 상태/사건 | 신규 롱 | 허용 작업과 다음 조건 |
|---|---|---|
| SHORT_CLOSING / SHORT_RESIDUAL | 금지 | 확인된 숏에 reduce-only 정리·잔량 보호, 동일 UNKNOWN CLOSE 추정 재전송 금지 |
| FLAT_UNSETTLED | 금지 | 현재0이어도 미해결 OPEN/취소/claim/늦은 응답 대조 |
| FLAT_SETTLED | 아직 금지 | 증거 영속 저장 뒤60분 시계 시작 |
| COOLDOWN | 금지 | 남은시간·최신 유효 목표 유지 여부 관찰, 신규 숏도 이 episode에서 억제 |
| LONG_RECHECK | 조건부 | 최신 목표·이미 산 수량·지갑 현금·예약액·계좌/데이터/실행 위험 모두 재검사 |
| LONG_PARTIAL | 남은 승인량만 | 첫체결과 완전체결 구분, 미체결 잔량 재평가·현재 목표0이면 취소 후 원래 축소 규칙 |
| 목표0/결측/만료 | 금지 | 대기 롱 취소. 이미 시작한 숏 위험축소/보호·대조는 계속 |
| HALTED/DEGRADED/DB·시계 실패 | 금지 | 확인 수량 보호·위험축소 허용, 자동 정상 복귀/추정 주문 금지 |

`cooldown_start_ms = max(마지막 확인된 숏 체결 시각, FLAT_SETTLED 관측·기록 시각)`.
미확보 체결시각을0으로 채우지 않는다. 더 늦은 확인 시각으로 보수 시작하고 출처를 남긴다.
`eligible_ms >= cooldown_start_ms + 3,600,000`이며 계좌의 다른 더 긴 cooldown/정지를 함께 검사한다.
재시작·UTC 날짜 변경으로 시계를 새로 시작하거나 줄이지 않는다. UTC 역행/오차 불명은 신규 진입 거부.

신호 시간과 실행 시간을 분리한다. **마감일봉 목표는 원래 시각**, 숏 신호도 원래 마감4h 시각.
분봉 reevaluation은 새 RSI/롱 신호 생산이 아니라 남은 주문 의도의 실행 자격 검사다.
목표 변경은 버전/유효 시각이 있는 새 결정. 오래된 목표로 늦게 매수하지 않는다.
현재 일일 실행기에 minute polling/새 예약 작업을 몰래 추가하지 않는다.

## 6. 멱등·전송 소유권·가격 한도

- episode ID는 비밀값 없는 계좌 별칭/환경/전략판본/종목/원래 유효 목표시각으로 결정론적 생성.
  재시작 시각·PID·매분 시각을 새 의도 ID로 쓰지 않는다.
- leg/purpose/attempt와 불변 파라미터 hash를 영속 연결. 같은 ID/다른 수량·가격이면 거부.
- 두 다리 공통 조정자가 한 의도에 원자적 dispatch claim을 한 번만 부여. HTTP는 transaction 밖.
  늦은 세대 응답은 증거로 남겨도 HALTED 해제/누적량 감소/현금 예약 해제를 못 함(C12/C13).
- 조회/새 순수 평가100회는 신규 주문100회가 아님. attempt 증가는 원격 종결 확인·새 Risk 승인·
  남은수량/시도예산이 있을 때만. UNKNOWN에서는 번호를 바꿔 같은 뜻의 주문을 우회하지 않음.
- 주문 목록의 working stop은 보호와 거래 상태를 구분해 다루지만, 해당 포지션/세대 소유권은 계속 확인.
- 숏 CLOSE는 BUY/reduce-only, 현물 LONG은 BUY LIMIT. 시장가 추격은 이 새 계약에 포함하지 않음.
- 최초 episode 기준 가격 ±0.3%와 매시도 quote 기준 한도를 구분. **총한도 밖 재가격 금지**.
  quote stale/필터 결측/최소수량·명목 미달이면 시도하지 않으며 해당 사유를 기록.
- 부분 청산은 보호 유지, 부분 매수는 승인된 잔량만. 수량은 Decimal/step 내림, 체결 ID별 한 번 반영.
- 자동 신규 노출 시도 예산/최대 대기창/새 목표 때 가격 한도 재설정 규칙은 구현 전 고정할 미정 항목이다.
  기존240분 파일럿이나 manager의3회를 수익 보고 임의 조합하지 않는다.
  신규 매수 예산 소진은 EXPIRED_UNFILLED/partial 기록, 위험 축소 자체의 허용을 없애지 않는다.

운영 연결 전에 신선도/조회 일관성·취소 종결/소유권 증거를 adapter별 확정해야 한다.
현재 코드의 정상경로 단위시험 통과를 다중 프로세스 전송 원자성·정전·5초 개입 보장으로 확대하지 않는다.

## 7. 지갑별 회계와 현금 예약 — 이전 공유 cash의 보완

연구 quote는 USDT로 제한하되 **현물 지갑과 USD-M 지갑을 별도**로 둔다.
이 설계는 업비트 원화/토스/주식 실계좌를 연결하거나 통화를 합산하는 작업이 아니다.

`equity = spot_cash + Σ(spot_qty×spot_mark) + futures_wallet_cash + Σ(signed_fut_qty×(mark−entry))`.
증거금/미체결 예약은 가용현금에서 빼고 equity에서 두 번 빼지 않는다.
숏 수량은 음수, funding cash는 `−signed_qty×settlement_mark×rate`로 보유 시점에만 반영한다.
수수료는 체결별 자산/금액을 확정하며 다른 자산 fee 환산시점 불명은0 비용으로 채우지 않는다.

- 현물 신규 매수 재원은 **spot_cash**뿐. 미체결 BUY의 잔량 가격한도+fee 예약액을 차감.
- 선물 short 청산으로 futures cash가 풀려도 spot_cash를 늘리지 않는다.
  이체가 없으면 여전히 현물 재원이 아니며 미확인 입금/이체를 가용현금으로 간주하지 않는다.
- 실제 초기 지갑 배분·자산 이동은 이번 범위 밖. 연구 초기 배분 비율도 아직 **UNSET**.
  모든 비교군의 초기 지갑 배분·총자본·거래 조건이 같아야 하며, 결과를 보고 배분을 바꾸지 않는다.
- BASE도 동일 선물 유휴지갑을 유지해야 비교가 공정하다. 기존100% 현물 가능 T/v2 결과는

## 8. 증거금10%·위험·역할별 한도 감사

현행 config는 margin_allocation0.10, risk_per_trade0.01, margin buffer1.5다.
`risk/sizing.py:182`는 증거금 cap을 적용하지만, 이전 고정 숏 파일럿의 별도 min 식에는 이 cap이 없다.
1x에서 명목0.25equity는 증거금0.25equity가 필요할 수 있으므로,
‘위험1% 적용’만으로 ‘증거금10% 적용’을 대신하지 않는다. 이전 문서의 전체 Risk 미검증에
이 구체적 차이를 추가하며 **원래 손익/판정은 소급 수정하지 않는다**(Current C14).

향후 한도 일치 계좌에서 고정 숏 희망 명목의 상한:

`N <= min(원래0.25E 희망, 비용포함1% 위험상한, leverage×0.10E,
          futures 가용잔고/1.5×leverage, 총노출 남은공간, 거래소필터상한)`.

1x를 유지하면 증거금 cap만으로 **N≤0.10E**가 된다. 목표0.25E를 채우려고 레버리지를 올리지 않는다.
예: E=10,000 USDT, 희망2,500이라도 증거금 상한은1,000. futures 가용잔고가900이면
1.5배여유로 명목≤600, 거기에 비용위험/총노출/step을 추가 적용한다. 이것은 합성 사이징 설명이지 성과다.

각 종목 최대50%/합계100% 현물 목표·원래 리밸런스밴드는 유지하지만 가용 spot_cash는 추가 현실 제약이다.
계좌 일손실2%·누적DD30%·4연패/240분 등 현행 항목을 정식 통합 전에 역할별로 매핑한다.
T/v2의 전향 중단25% 등 더 엄격한 현행 별도 계약을 ‘공통30%’로 몰래 완화하지 않는다.
G5/G6/G7·경제 달력·edge/필터·보호/청산tier가 불명인데 새 진입을 통과시키지 않는다.
전향 T/v2와 연구 min 식/총한도의 정확한 역할별 적용은 미정 등록부에 남긴다.

이 엄격한 지갑·증거금 보완은 과거 파일럿의 단순 격자 변경과 다르다.
순수 실행 빈도 효과를 보려면 **두 대조군 모두 같은 보완 한도/지갑/역할 정책**을 써야 한다.
정식 비교 준비 전에는 자료 부족·0거래와 전략 기각을 구분한다.
