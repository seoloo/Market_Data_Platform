후속: [무료 과거 복원 경로 재평가](FUNDAMENTAL_FREE_HISTORY_FEASIBILITY.md). 아래는 당시 조회/계약 검사 기록이며 최신 자료 경로/다음 작업은 후속과 Current를 따른다.

## 1. 무료 가격 경로: 이번 실제 요청 결과

Twitter 한 종목, 2022-10-01~10-31 요청 범위, 공급자 두 곳에 각 1회만 요청했다.
[manifest](fundamental-terminal-chain-manifest.json)에 정확한 URL·응답 상태·bytes·SHA256·실제 취득 ms를 보존했다.

| 경로 | 실제 응답 | 판정 |
|---|---|---|
| Yahoo 공개 chart | HTTP 404, `result=null`, 해당 종목 자료 없음 | 이번 주소/요청으로 OHLCV 미확보. 종목 가격/수익 0으로 대체 금지 |
| Stooq 공개 CSV 주소 | HTTP 200이나 JavaScript 브라우저 확인 HTML | CSV/가격 데이터가 아님. 확인 코드를 실행하거나 접근 제한 우회하지 않고 중단 |
| SEC 합병 계약 | HTTP 200, 합병 대가와 지급 절차 원문 | 사건 근거만. 일별 가격·배당/분할·실제 지급 파일 아님 |

잘못된 ticker 매핑·다른 제공 경로 가능성까지 배제한 전수조사는 아니다.
무료 종료 가격이 세상에 없거나 유료 구매만이 해법이라는 결론은 내리지 않는다.
하지만 **이번 두 요청은 어느 것도 검증 가능한 가격 시계열을 주지 않았다**.
최근 정상 종목 목록/ETF 평가액/화면 일부 행으로 종료 구간을 임의 메우지 않는다.
공개 주소 조사에서는 인증 계정·API 키·유료 상품을 사용하지 않았다.
그 뒤 사용자 승인에 따라 기존 KIS 인증으로 아래 **시세만** 조회했다. 금융계좌 조회나 주문 요청은 없다.

### 1.1 승인된 기존 KIS API 확인

[한국투자증권 공식 일별 시세 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/dailyprice/dailyprice.py)를 확인하고,
기존 `KisOverseasReadOnly`의 `/uapi/overseas-price/v1/quotations/dailyprice`(`HHDFS76240000`) 경로만 사용했다.
`TWTR / NYS / GUBN=0 / MODP=0`으로 `BYMD=20221031`, 마지막 거래 구간의 `20221027`을 각각 한 번 조회했다.
**둘 다 HTTP 200 / rt_cd=0 / MCA00000이나 output2 가격 0행**이었다. 인증/요청 성공과 자료 확보는 다르다.
장 종료 이후 기준일 때문에만 비었다고 설명할 수는 없지만, 심볼 삭제·공급자 매핑·다른 경로의 가능성을 판별한 것은 아니다.
이 두 요청만으로 KIS의 모든 종료 종목 지원 여부를 단정하지 않는다. 빈 응답을 가격 0이나 손실로 처리하지 않는다.

요청 가드는 해당 시세 GET와 기존 OAuth 인증 POST 외 경로를 거부하도록 두었다.
계좌번호를 요청에 쓰지 않았고 조회 객체의 주문 활성화는 false였다. 계좌·잔고·주문 호출 0건.
키/토큰/계좌값·인증 응답·헤더·응답 전문은 출력/연구 파일에 저장하지 않았다.
기존 Git 제외 인증 캐시를 통상 인증 절차로 사용했으며 운영 설정은 변경하지 않았다.
manifest에는 당시 관측한 상태 코드·요청 날짜·행 수·취득 ms만 기록했다.
**이 기록은 응답 전문 원본이 아닌 민감정보 제외 진단 요약**이며 원본 29개 수량/해시에 포함하지 않는다.

향후 가격원 채택 전 계약:

1. 당시 거래소/증권 ID/주식 종류와 공급자 심볼 연결. 현재 티커만으로 동일 증권 인증 금지.
2. 일자·세션·통화, raw OHLCV와 수정계수/배당/분할의 정의를 분리한다.
3. 마지막 실제 거래일 및 중단 이후의 행을 검사한다. 평가/forward-fill/무거래 행은 체결 근거가 아니다.
4. 거래 정지 기간을 통상의 누락 거래일로 메우지 않는다. 가격·거래 가능성·종료 대가를 별도 입력으로 둔다.
5. 지정가 체결은 호가/일중 경로·거래량·미체결 검증을 별도로 요구한다. 일봉 확보가 곧 체결 인증은 아니다.
6. 접근 오류/HTML/빈 응답은 자료 상태로 기록하며 가격 행/전략 기각으로 변환하지 않는다.

## 2. 실제 지급 근거: 2영업일은 계좌 입금 보장이 아니다

[SEC Twitter 2022-04-25 합병 계약](https://www.sec.gov/Archives/edgar/data/1418091/000119312522120461/d310843dex21.htm)의
§3.1(c), §3.2(a)~(c), (g)를 대조했다.

- 일반 적격 주식의 54.20 USD 권리와 취소/반대 주식 예외를 구분한다.
- 지급 대행자 자금 예치와 개별 주주의 수령 절차가 따로 규정되어 있다.
- **2영업일은 종이 주권 보유자에게 교환 안내문을 발송하는 기한**이다. 개인 계좌 현금 가용을 T+2로 고정하는 근거가 아니다.
- 전자등록 주식은 종이 주권/서명 안내문 대신 별도 전달 절차가 있고, 지급은 합병 효력과 증빙 수령 중 늦은 때 이후 절차를 따른다.
- 이자 없음·해당 원천세 등 조건이 있다. 전체 개인 계좌의 실제 지급 완료 시각은 원문에 없다.

4월 계약은 예정 조건이지 10월 실제 완료 증거가 아니다. 완료 근거는 기존 10월 8-K/Form 25와 구분한다.
이번에도 개인 현금 가용일은 미확인이고, 계약을 실제 계좌 입금 기록으로 둔갑시키지 않았다.
법률/세무 자문이나 모든 주주 상황의 판정이 아니라 연구 자료의 사용 경계 감사다.

## 3. 연구 전용 순수 검사 구현

[fundamental_market_audit.py](../../src/auto_trading/research/fundamental_market_audit.py)는
I/O·실시간 시계·난수·주문·포트폴리오·NAV·수익 계산 없이 외부에서 검토한 입력의 계약만 검사한다.
[import 계약](../../pyproject.toml)으로 운영/매매 판단 경로에서 새 연구 모듈 import를 금지했다.
기존 제한을 완화하거나 기존 실행 엔진의 회계를 바꾸지 않았다.

### A. 현금 권리 감사

`CashClaim`은 검토한 적격 일반 보통주의 수량/대가·실제 효력/확인 시각·출처를 받는다.
계약 발표만으로 실제 권리 발생을 인증하지 않도록 확인 시각이 효력 이전이면 거부한다.
`CashReceipt`는 동일 증권의 실제 순입금·입금/가용/확인 시각·출처를 별도로 받는다.

| 당시 상태 | 반환 | 제한 |
|---|---|---|
| 실제 효력/확인 전 | `None` | 법적 권리도 미인증 |
| 권리 확인, 지급 증거 없음/미래에만 있음 | gross 권리·spendable `None` | 현금 가용을 모르며, 가용 0으로 확정한 것도 아님 |
| 입금 확인, 가용 시각 전 | gross 권리·확인된 가용액 0 | 자금이 도착해도 아직 재투자 가능하다고 가정 금지 |
| 입금과 가용 모두 확인 | gross 권리·확인된 net 금액 | 세전 권리와 순입금을 중복 합산하지 않음 |

다른 증권 입금·효력 이전 입금·역전 시각·음수/비유한 금액·검토 대가 초과 입금은 거부한다.
법적 권리 금액은 위험/회수가능성/세금을 반영한 NAV 평가액이 아니다.
여러 분할 지급·비현금 교환·파산·반대 주주·환전·복수 통화/세금 원장은 이번 구현 범위가 아니다.
기존 계좌에 현금을 넣거나 수익률을 계산하는 기능도 아니다.

### B. 명부 변경 체인의 누락 검사

`MembershipAnchor`는 **같은 지수의 두 장마감 공식 명부**, 검토된 증권 ID·세션 마감/확인 시각·출처를 요구한다.
`ETF_HOLDINGS`, 미확인/미래 가용 명부, 아직 마감되지 않은 명부는 공식 지수 검사에서 거부한다.
따라서 지난 SPY 505행을 공식 S&P 명부로 자동 채택하지 않는다.

`MembershipChange`는 지수·사건 ID·시행 세션·추가/삭제 증권·가용 시각·출처를 받는다.
알려진 해당 구간의 사건만 날짜/ID 순으로 대조한다. 미래/미확인 사건을 과거에 적용하지 않는다.
같은 사건의 동일 재전달은 중복 적용하지 않으나 다른 버전은 임의 선택하지 않고 거부한다.
없는 증권 삭제·이미 있는 증권 추가·동일 세션 중복 변경·타 지수 혼합은 거부한다.
한 지수의 퇴출을 500+400 합집합 퇴출로 해석하지 않고 지수별로 별도 검사해야 한다.

단순 행수 대신 종료 기준 명부와 **빠진 증권 ID / 잘못 남은 증권 ID**를 비교한다.
예: `{A,B}`에서 A→C만 적용하고 B→D 사건을 빠뜨리면, 종료 `{C,D}`에 대해 빠진 D/남은 B를 반환한다.
입력 순서를 바꿔도 같은 결과다. 알려진 후기 자료로 역사 상태 복원이 가능하더라도
그 자료가 과거 의사결정 시점에 이미 가용했다고 인증하는 것은 아니다.

**중요한 한계:** 중간 A→C→A 두 사건이 모두 빠지면 시작/끝 명부가 같을 수 있다.
회귀 테스트로 이 반례를 고정했다. `matched=True`는 전 구간 완전성 PASS가 아니다.
완전성을 주장하려면 독립 공식 중간 기준점/전체 사건 범위·정정 버전·주식 종류/분할 등의 근거 목록이 따로 필요하다.
자동 완전성 인증·공식 명부 수집기·정정본 선택기·영구 증권 마스터는 아직 없다.

## 4. 원자료·검증

새 원본/실패 응답 **3개, 493,048 bytes(약 0.47 MiB)**를 Git 제외 보존, 누적 **29개**.
기존 파일 삭제/덮어쓰기 없음. 연락처는 승인된 SEC 요청에만 사용하고 manifest/코드/보고서에 저장하지 않았다.
실패 응답도 정상 시장 자료와 구분해 보존했다. Stooq HTML의 코드를 실행하지 않았다.
Git 복제만으로 원본 전체를 재현할 수 없다. 같은 주소의 후속 응답이 같다고 보장하지 않는다.

[테스트](../../tests/research/test_fundamental_market_audit.py)는 합성 입력만 사용한다.
54.20은 사례의 금액을 참고했지만 수량·순입금·UTC ms·지수/증권 ID는 통제된 합성 값이며,
실제 TWTR 입금/정산일이나 실제 S&P 명부를 인증하는 fixture가 아니다.
현금 권리·입금·가용 분리, 미래 지급/변경 무관성, ETF 명부 거부, 누락·충돌·중복·동일 수량 다른 구성,
끝 명부 일치로 놓치는 왕복 변경 반례를 검사한다. 오류를 막는 단위 검사이지 경제적 우위 검정이 아니다.

검증: 새 합성 테스트 **35건** 통과. 전체 pytest **2,668건**(177.28초), leakage **90건**(18.48초),
strict mypy **421파일**, ruff check/format **586파일**, import 계약 **5/5** 통과.
초기 타입 검사의 테스트 `replace(**dict)` 오류 4건은 필드를 명시하는 호출로 고쳤고 기준/ignore를 완화하지 않았다.
새 3개 해시/bytes·오류 응답 내용, 기존 26개 해시 불변, 문서 링크·JSON·연락처 비보관·변경 범위 확인.
새 표본 결과/PNL 골든은 만들지 않았고 기존 전략·운영 코드와 골든은 변경하지 않았다.

## 5. 사용자 선택 반영 — 과거 복원 유지, 이번 조회 범위 종료

자료 게이트는 **DATA_NOT_READY**다. 연구 가설은 시험하지 않았으며 REJECT가 아니다.
새 도구가 있다고 미확인 실제 시각/종목 ID/가격을 합성 입력처럼 만들어 넣지 않는다.

검토했던 두 경로와 이번 사용자 선택은 다음과 같다. A가 승인되었고 B로 임의 전환하지 않는다.

| 선택 | 다음의 구체적 범위 | 비용·표본/시간 위험 |
|---|---|---|
| A 과거 복원 계속 — **사용자 선택** | 기존 KIS 시세만 승인되어 TWTR 두 날짜 확인 완료, 모두 0행 | 이번 경로로 가격 미확보. 공급자 식별·배당/분할·종료 현금 회계/가용 정책 결정 필요 |
| B 전향 동결 관찰 설계 — 미선택 | 구성·공시 수신 시각·정정 버전 기록 명세/독립 표본·검정력 계획 | 여러 분기 이상 기다릴 수 있으며 검정력 별도 계산. 자동 수집/예약을 켜지 않음 |

**다음 Phase 0: 과거 복원 안에서 종료 가격원과 공식 명부의 확보 가능 경로를 재평가한다.**
