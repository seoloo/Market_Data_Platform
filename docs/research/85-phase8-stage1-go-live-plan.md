## 3. 체크리스트 — 거래 키 만들기 (L2, 사용자가 직접)

**L1 승인 뒤에** 만든다. 에이전트는 키를 만들거나 입력하지 않는다. 키 값은 채팅에 붙여 넣지 않는다.

1. Binance → **API 관리** → API 만들기 → "시스템 생성". 이름은 `auto-trading-live-spot` 처럼 **거래용임이 보이게** 짓는다.
2. **IP 제한: "신뢰할 수 있는 IP 만 허용"** → 집 공인 IP 하나. 지금 읽기 전용 키에 넣은 IP 와 같다.
3. 권한은 **두 개만** 켠다:
   - ✅ Enable Reading
   - ✅ Enable Spot & Margin Trading
4. 나머지는 **모두 끈다**: ❌ Enable Withdrawals · ❌ Enable Margin Loan, Repay & Transfer · ❌ Enable Futures · ❌ Permits Universal Transfer.
   "Enable Symbol Whitelist" 는 켜도 된다 — 켜면 BTCUSDT·ETHUSDT 만 주문할 수 있다.
5. **지금의 읽기 전용 키는 그대로 둔다.** 그림자 운영이 그 키로 "읽기 전용인가"를 매일 본다. 읽기 전용 키에 거래 권한을 더하면 그림자 점검이 CRITICAL 을 낸다(51 §2).
6. `.env` 에 **새 이름**으로 넣는다(이름은 L3 를 만들 때 확정, 제안: `BINANCE_LIVE_TRADE_API_KEY` · `BINANCE_LIVE_TRADE_API_SECRET`). `.env` 는 git 에 올라가지 않는다.
7. 수수료를 **BNB 로 내기는 첫 주 동안 끈다.** 실행기는 USDT·매매 코인 수수료만 USDT 로 환산한다. BNB 로 내면 비용 기록에 "환산 안 함"이 남아 매일 대조가 어려워진다.
8. 키가 새거나 의심되면: **API 관리에서 그 키를 삭제**한다. 삭제는 즉시 효력이 있고, 실행기는 −2015 로 주문을 못 내고 멈춘다(fail-closed).

## 4. 첫 주문은 사람이 보고 보낸다 (L3 를 만들 때 넣을 절차)

1. 입금 → 현물 지갑에 시작 금액만 있는지 Binance 앱으로 확인.
2. **첫날은 예약 작업 없이 사람이 터미널에서 실행한다.** 실행기는 먼저 **계획만** 보여 준다(주문 0건): 종목·방향·수량·지정가·목표 비중·그날 Paper 목표.
3. 사람이 Paper T/v2 의 같은 날 목표와 맞는지 보고, 맞으면 같은 명령을 "보내기"로 다시 실행한다.
4. 체결 뒤 Binance 앱의 주문 내역에서 client ID(`<tag>-<결정일>-<종목>-B|S`)·수량·평균가를 대조한다.
5. 이상 없으면 그때 **예약 작업 한 줄**을 등록한다(L5, 21:12 KST — 데모 T/v2 자리. 데모는 멈추거나 시각을 옮긴다).

"계획만" 단계는 데모 실행기에 없는 기능이다. **L3 와 함께 만든다**(실거래 어댑터 없이도 데모에서 먼저 시험한다).
T/v2 는 추세가 꺾여 있으면 목표가 0 이라 **첫날 주문이 없을 수 있다.** 그러면 첫 주문이 나오는 날까지 매일 2~3 을 한다.

## 5. 멈출 조건

### 5.1 이미 자동으로 멈추는 것 (코드에 있음)

| 상황 | 실행기의 동작 |
|---|---|
| `data/HALT` 파일이 있음 | 그날 새 주문 없이 목표만 기록(HALTED). 위험 축소도 하지 않는다 — 사람이 판단 |
| 결과를 모르는 주문이 조회로 해소되지 않음 | 그날 새 주문 없음(DEGRADED) |
| 전날 결정 기록이 없음 (PC 가 꺼져 하루 빠짐) | 오래된 목표로 체결하지 않음(NO_PRIOR_DECISION) |
| 키 거부(−2015, IP 바뀜) · 거래소 점검 | 주문이 나가지 않음. 다음 날 다시 시도 |

### 5.2 사람이 `data/HALT` 를 만드는 조건 (제안 — 사용자 확정)

| # | 조건 | 왜 |
|---|---|---|
| H-a | 21:20 점검에 **CRITICAL** 이 하나라도 있다 | 원장·주문 경로가 어긋났다는 뜻이다 |
| H-b | Binance 주문 내역에 **DB 에 없는 주문**, 또는 같은 의도의 주문이 2 건 | 중복·외부 주문 (데모 K1 과 같은 기준) |
| H-c | 실행 뒤 **미체결 주문이 남아 있다** (다음 실행 전까지) | 추격 뒤 남은 수량 0 이어야 한다 (K1) |
| H-d | 보고서의 평가액과 Binance 앱 평가액이 **1% 넘게** 다르다 | 잔고를 잘못 읽고 있다 |
| H-e | 하루 체결 비용(IS)이 **30bp 초과** | 연구 가정 15bp 의 두 배. 비용 가정이 틀렸을 수 있다 |
| H-f | 계좌 낙폭이 **25%** 에 닿는다 | 백테스트 MDD 15.9% 를 크게 넘는다. 전략이 과거와 다르게 움직인다는 신호 |

H-f 는 **계좌 자동 정지가 아니다.** TRADING_CORE 의 "누적 DD 30% → HALTED" 는 **현물 실행기(`live_t2.py`)에 아직 구현돼 있지 않다.**
L3 를 만들 때 이것을 실행기에 넣을지(넣으면 T/v2 검증 결과와 다른 규칙이 하나 더해진다) 사용자가 정한다. 그 전까지는 사람이 본다.

### 5.3 멈춘 뒤

- `data/HALT` 는 **새 주문만** 막는다. 이미 든 코인은 그대로 있다.
- 다 팔고 싶으면 **Binance 앱에서 직접 판다.** 다음 실행은 실제 잔고를 진실로 보고 맞춘다(재시작 복구).
- ⚠ **HALT 를 지우면 다음 실행이 목표 비중으로 다시 산다**(추세가 살아 있으면). 밖에 있고 싶으면 HALT 를 그대로 둔다.
- 재개는 원인을 적은 뒤에만 한다. 자동 해제는 없다(TRADING_CORE).

### 11.2 L3(실계좌 어댑터)를 만들기 전에 사용자가 정할 것

| # | 결정 | 권고 (결과 보기 전) | 이유 |
|---|---|---|---|
| A1 | 시작 금액 | **5,000 USDT** (§2) | 설계 10,000 의 절반 = 위험 절반. 과거 최악 MDD 15.9% → 약 −795 USDT, 최악의 하루 −6.8% → 약 −340 USDT. 앞으로는 더 클 수 있다 |
| A2 | 계좌 낙폭 30% 자동 정지를 `live_t2.py` 에 넣나 | **넣는다 — "새 매수 금지 + 알림"만, 자동 매도 없음** (`data/HALT` 와 같은 동작) | 지금은 사람이 보는 H-f(25%)뿐이다. T/v2 백테스트 최악 15.9% 라 과거 경로에서는 한 번도 닿지 않는다 → 검증 결과를 바꾸지 않는 안전장치 |
| A3 | 일 손실 2% 규칙을 T/v2 현물에 쓰나 | **쓰지 않는다** | TRADING_CORE 의 2% 는 선물 진입 게이트, O 규칙에서는 "노출 증가 금지"로만 쓴다(50). 현물 T/v2 는 검증에 없던 규칙이고, 하루 2% 손실은 변동성상 자주 온다 |
| A4 | 쉬는 현금 Simple Earn 예치(문서 29 C1) | **첫 4주는 하지 않고, 4주 뒤 별도 단계로** | 실행기는 **현물 지갑 잔고만** 자본으로 본다 — USDT 를 Earn 으로 옮기면 실행기 눈에 자본이 줄어 매수를 줄인다. Earn 잔고를 자본에 넣고 매수 전에 꺼내는 코드·데모 시험이 필요하다. 크기: 5,000 중 약 70% 가 쉰다고 보면 1,000×7.08% + 2,500×3.08% ≈ **연 150 USDT (월 약 12)** — 첫 주 위험을 늘릴 만큼 크지 않다 |
| A5 | 첫 주문 방식 | **첫날은 사람이 "계획만" 보고 보내기** (§4) | 실행기에 "계획만" 단계가 아직 없다 → L3 와 함께 만들고 데모에서 먼저 시험 |

### 11.3 승인 뒤 순서 (사용자 · 에이전트)

1. (에이전트) L3 실계좌 현물 어댑터 + "계획만" 단계 + (A2 를 고르면) 30% 정지 → 데모에서 시험 → 테스트·검사 통과 뒤 커밋
2. (사용자) 거래 키 만들기 — §3 (현물 거래·읽기만, 출금 금지, 집 IP 제한, 새 이름으로 `.env`). 키 값은 채팅에 붙여 넣지 않는다
3. (사용자) 현물 지갑에 시작 금액만 입금. 따로 들고 있을 코인은 Funding 지갑으로 (§2)
4. (사용자 + 에이전트) 첫날: 계획 확인 → 보내기 → Binance 앱 주문 내역 대조 (§4)
5. (사용자) 예약 작업 1줄 등록(21:12 KST, 데모 T/v2 자리 — 데모는 멈추거나 시각 이동). 그림자 `--allocation` 을 시작 금액으로
6. (사용자) 첫 주 매일 5분 대조 (§7) → 둘째 주부터 21:20 텔레그램만 매일

### 11.4 멈추는 방법 (외워 둘 것)

- **PC 에서:** `data\HALT` 파일 만들기 → 새 주문만 막힌다. 다 팔려면 Binance 앱에서 직접. HALT 를 지우면 추세가 살아 있을 때 다시 산다 (§5.3·§6)
- **밖에서:** Binance 앱 → API 관리 → **거래 키 삭제** (즉시 주문 경로가 끊긴다)
- 자동 해제는 없다. 원인을 적은 뒤 사람이 재개한다
