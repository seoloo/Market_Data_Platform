# 92 — Binance 스테이킹 캐리 (WBETH·BNSOL 보유 + 같은 수량 무기한 숏) 과거 평가 — 사전 등록

작성: 2026-09-26 (Opus) · 상태: **사전 등록 · 계좌 수익·펀딩 합계 미계산 · 판정은 사용자 승인 뒤 1 회.**
선행: [90](90-staking-eth-sol-feasibility.md)(타당성·자료 감사, Sol/Astra) · [91](91-binance-staking-historical-observation.md)(환산비율 관찰: WBETH +2.69%/년 ETH, BNSOL +6.32%/년 SOL).
사용자 (2026-09-26): 90·91 "이거 바탕으로 계속 이어가보" → 선택: **증거금 50%** · 통과 기준 **USDT 예치 이자보다 높음** · 헤지 **매주** 조정.

## 1. 질문

Binance 한 거래소 안에서 **WBETH(또는 BNSOL)를 들고 같은 코인 수량만큼 USD-M 무기한 숏**을 유지했다면(가격 방향 대체로 상쇄),
2024-09-13 ~ 2026-08-31 동안 **계좌 전체 기준 비용 후 수익**이 같은 돈을 USDT 예치(연 3.08%, 문서 29)에 둔 것보다 높았나 — 그리고 **청산 위험 없이** 유지됐나.

- 수익원: 스테이킹(환산비율) + 숏이 받는 funding − 비용. 스테이킹 몫은 91 로 거의 정해져 있고 **funding 이 결과를 가른다.**
- 대조군 **B0**: 같은 규칙, 스테이킹 없는 현물 코인(환산비율 1 로 고정) — 스테이킹 기여 = C − B0.
- 업비트 SOL(사용자 실제 보유, 두 거래소 자금 분리)은 이 문서 범위 밖이다 — 향후 지급분 전향 관찰(90 §5.4).

## 2. 규칙 (고정, 자산별 따로: ETH 계좌 · SOL 계좌, 각 초기 10,000 USDT)

| 항목 | 값 |
|---|---|
| 구간 | **2024-09-13 00:00 UTC ~ 2026-08-31 00:00 UTC** (91 과 같다. BNSOL 출시 전 제외) |
| 가격 | 현물 = `binance_spot` 1h 종가(DB, 17,208 봉 결측 0) · 숏 평가 = mark 1h 종가, 스트레스 = mark 1h **고가** (90 §5.4 스냅숏) |
| 환산비율 | 91 과 같은 고정 스냅숏(SHA-256 확인). 매시각 그날 UTC 00:00 비율을 쓴다(계단) |
| 시작 | 자본의 **50%** 로 현물 코인을 사서(C 는 비율로 WBETH/BNSOL 전환) 보유, **50%** 는 선물 지갑 USDT. 숏 수량 = 코인 환산 수량 |
| funding | 각 정산 시각(`fundingTime`)에 직전 숏 수량 × 정산 `markPrice` × `fundingRate` — 양수면 숏이 받는다 |
| 평가 | 계좌 = 코인 환산 수량 × 현물 종가 + 선물 지갑(시간마다 mark 로 손익 반영) |
| **매주 조정** | 매주 월요일 00:00 UTC: 계좌를 현물 50 / 선물 지갑 50 으로 되돌리고(현물 매매로 옮김) 숏 수량 = 코인 환산 수량 |
| 긴급 조정 | 어느 시간이든 mark 고가에서 **선물 지갑 ÷ 숏 명목 ≤ 25%** 이면 그 시간 종가에 매주 조정과 같은 방식으로 즉시 조정 |
| **청산** | mark 고가에서 선물 지갑 ÷ 숏 명목 **≤ 1%** 면 청산으로 기록하고 그 경로를 끝낸다(보수적 유지증거금 — 이 규모의 실제 tier 보다 높다) |
| 비용 (판정) | 현물 편도 **0.15%**, 무기한 편도 **0.095%** (프로젝트 기준). 시작·조정·끝 매매 모두. 참고 줄: 0.11% / 0.023% |
| 끝 | 2026-08-31 00:00 UTC 에 모두 청산(현물 매도·숏 환매 비용 포함) |
| 연수익 | CAGR = (끝 자본 ÷ 10,000)^(365/717) − 1 |

## 3. 판정 (자산마다 C 에 대해, 전부 통과해야 그 자산 PASS)

| # | 기준 |
|---|---|
| S1 | CAGR(C, 판정 비용) **> 3.08%** (같은 돈의 USDT 유동형 예치 가정, 문서 29) |
| S2 | **청산 0** — 구간 전체에서 mark 고가 기준 선물 지갑 ÷ 숏 명목이 1% 이하로 내려간 시간이 없다 |

**최악의 경우 먼저 보고:** 선물 지갑 여유 최저치와 그 시각, 계좌 MDD(시간 종가), 최악의 30 일, 30 일 누적 funding 이 음수였던 가장 긴 기간, 긴급 조정 횟수.
그다음: CAGR(C·B0), 스테이킹 기여(C − B0), funding 합계, 비용 합계, 91 의 세 구간별 수익, 현실 비용 참고 줄.

**PASS 의 뜻:** "이 2 년 한 경로에서, 비용 후 예치 이자보다 벌었고 청산에 가지 않았다." 통계적 우위 증명이 아니다(2 년 한 경로, funding 은 국면을 탄다 — K 연구에서 연 23% → 2~3% 로 줄었다).
**PASS 여도** 다음은 별도 Paper/데모 전향 관찰(사용자 승인)이다. 실거래 아님.
**실패 시:** 증거금 비중·조정 주기·긴급 문턱을 바꿔 같은 자료로 다시 판정하지 않는다.

## 4. 먼저 적는 한계

- **WBETH·BNSOL 시장 가격 = 환산비율 × 코인 가격**으로 본다. 실제 시장 할인·유동성·전환/환매 대기(ETH 며칠, SOL 약 2~3 일)는 넣지 않았다 — 조정 때 WBETH 를 시장에서 판다고 가정한다. 할인이 크면 C 가 과대평가된다.
- 유지증거금은 보수적 1% 한 줄로 단순화했다(과거 tier 이력 없음, 90 §5.4). 1 시간 안의 경로 순서는 모른다 — 고가를 먼저 맞았다고 본다(보수적).
- Binance "다중 자산 모드"(WBETH 를 증거금으로 쓰기)는 넣지 않았다 — 현물과 선물 지갑을 나눠 둔다(더 보수적, 자본 효율 낮음).
- ETH·SOL 은 독립 표본 2 개가 아니다(같은 시장). 717 일 · 주간 조정 약 102 회.
- 노출: funding 의 대략적 수준은 K·M(문서 10·13)에서 다른 구간·종목으로 본 적이 있다. 이 구간 ETH·SOL 의 funding 합계와 계좌 수익은 **아직 계산하지 않았다.**
