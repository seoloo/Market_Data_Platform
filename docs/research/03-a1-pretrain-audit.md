# 03 — A1 TRAIN 실행 전 정합성 감사 (2026-09-23)

> **성과 열람 전 기록.** 이 작업에서 TRAIN/VALIDATION/TEST의 방향별·순손익 평균을
> 계산하거나 읽지 않았다. [02 사전등록](02-a1-preregistration.md)의 원문과
> 이전 추정치는 보존한다. 이 문서는 코드·규칙 불일치를 드러내는 감사이며,
> 통과 기준을 소급 변경하는 승인이 아니다.

> **상태 갱신:** 2026-09-23 사용자 승인으로 [02 §11](02-a1-preregistration.md#11-train-결과-열람-전-개정-2026-09-23-사용자-승인)에
> T2·TRAIN/T4·손절/비용 정의를 성과 열람 전에 고정했다. 아래 미해결/제안
> 문단은 승인 전 감사 이력으로 보존한다.

## 발견 1 — 레인지 정의가 달랐다

02 §3.1은 현재 종가가 **직전 6시간의 고가/저가**를 넘어야 한다. 과거 측정 코드는
직전 6시간의 **종가 극값**을 사용했다. 이는 더 많은 신호를 만들므로 사전등록과
동일한 전략이 아니었다. A1 공통 feature와 측정 스크립트를 고가/저가 기준으로
고쳤다. 이 변경 후 이전 원 트리거 1,874개, 거래 가능 615개는 유효하지 않다.

## 발견 2 — 손절 유지 요구와 WIDEN 충돌

사용자의 기존 요구는 손절가를 임의로 멀리 옮기지 않고 포지션 크기를 줄여
거래당 위험을 관리하는 것이다. 02 §3.2/§8은 `min_stop_distance=1%` 미만
손절을 1%로 **WIDEN**한 수치를 사용했다. A1 전용 `REDUCE_POSITION`은
`2σ × √24` 손절 자체를 유지하고, 1%를 **사이징 분모의 하한**에만 적용한다.
H1 기본 WIDEN 설정은 변경하지 않았다. 이것은 성과를 보고 고른 파라미터가
아니며, 사용자 요구와 실제 집행 가능성을 맞춘 구현 수정이다.

## 방향 평균을 열지 않고 다시 잰 설계 숫자

`scripts/measure_trigger_conditions.py`와
`scripts/measure_a1_design.py --preserve-stop`으로 트리거 수, 손익 **표준편차**,
트리거 직후 움직임 비용 대리치만 재측정했다. 연구 스크립트의 한도 근사는
실제 G1~G7 게이트/체결 재생과 동일하지 않으므로 아래 거래 수는 **예상치**다.

| 항목 | 주 arm | 수축 없는 대조군 |
|---|---:|---:|
| 원 트리거 | 1,510 | 4,175 |
| 2h 거래 가능 예상 | 526 | 964 |
| TRAIN / VAL / TEST 예상 | 227 / 160 / 139 | 425 / 279 / 260 |
| 전체 2h 손익 SD | 79.31bps | 110.99bps |
| TRAIN 2h 손익 SD | 95.64bps | 136.15bps |
| 왕복 비용 대리치 | 19.91bps | 22.69bps |

OOS `n=100`에서 탐지 가능한 주 arm **총 효과**는 42.44bps,
위 비용을 단순 차감한 **순 효과**는 22.54bps다. TRAIN 대조군 차이의
2SE 대리치는 18.32bps다. 이들은 성과 결과가 아니라 사전 설계 입력이다.
실제 엔진의 체결·funding·게이트가 적용되면 바뀔 수 있다.

A1 설정의 진입 전 비용 추정은 원래 H1 기본값(수수료 9bps + 예상 슬리피지
4bps = 13bps)이어서 위 트리거 비용 대리치보다 낮았다. `config/a1.yaml`에서
예상 슬리피지를 왕복 11bps로 올려 **20bps**로 만들었다. 이는 19.91bps
대리치보다 약간 보수적이며, 체결 재생의 동적 슬리피지 모델 자체는 바꾸지 않는다.

## TRAIN 실행 전에 발견한 두 가지 — 2026-09-23 사용자 승인으로 해소

1. **T2 단위 충돌:** 02 §5의 40.9bps는 검정력 계산상 **총 효과**인데,
   §7 T2는 `순기댓값 평균 ≥ 40.9bps`로 적었다. 기존 T2를 그대로 유지하면
   의도보다 높은 문턱이다. 정정 수치 기준으로 총효과 `≥42.44bps`와
   순효과 `≥22.54bps` 중 어느 통계를 T2로 삼을지 명시해야 한다.
   성과 열람 전에 사용자가 **비용 전 42.44bps**를 선택했다. 적용 기준은
   [02 §11](02-a1-preregistration.md#11-train-결과-열람-전-개정-2026-09-23-사용자-승인)이다.
2. **2020 표본 부재:** 기존 G5 변동성 게이트는 1시간봉 **365일** 이력이
   있어야 하며 데이터는 2020년 1월부터 시작한다. 현재 피드/스냅샷은
   warm-up 미충족이면 판단을 만들지 않으므로 2020년에는 실제 A1 진입이
   불가능하다. 02 §7 T4의 `2020·2021·2022 각 연도 부호` 판정과 충돌한다.
   게이트를 완화하지 않았다. 실행 전 더 이른 신뢰 가능한 1시간봉 이력의
   확보 가능성을 점검했고, 사용자가 TRAIN/T4 재등록을 승인했다.

### 2026-09-23 추가 확인 — 데이터·연도별 표본 (성과 미열람)

- DB의 Binance USD-M BTCUSDT 1h·5m 첫 봉은 모두 `2020-01-01 00:00 UTC`다.
  저장된 2019년 1h 봉은 0개다. A1 설정의 G5 스냅샷 요구치는 안전 여유를
  포함해 **1h 8,824봉**이며 최초 충족 시각은
  **2021-01-02 15:59:59 UTC**다. 따라서 현재 데이터로는 2020년 T4 표본이 0이다.
- [Binance 공식 공개 데이터 도구](https://github.com/binance/binance-public-data/blob/master/python/README.md#download-klines)는
  현물·USD-M·COIN-M 봉 다운로드 범위를 `2020-01-01`부터 안내한다.
  [Binance 자체 회고](https://www.binance.com/en/blog/all/421499824684900356)는
  BTC/USDT 선물이 2019-09-09 시작했다고 기록한다. 상품 출시와 공개
  아카이브 이력은 다르며, 2019년 API 복원 가능성은 검증하지 않았다.
- 수정된 고가/저가 신호와 손절 유지·한도 근사를 그대로 사용한 **예상**
  2h 거래 수는 주 arm `2020:65 / 2021:75 / 2022:87`, 대조군
  `2020:112 / 2021:155 / 2022:158`이다. 즉 2021~2022 TRAIN으로
  재등록할 경우 주 arm **162**, 대조군 **313** 예상이다. 실제 G1~G7 및
  체결 후 수치는 더 적을 수 있다. 수익 평균은 열지 않았다.

**재등록 제안 — 2026-09-23 사용자 승인·02 §11에 반영됨:** G5를 낮추거나 현물로 2019년을
대체하지 않는다. TRAIN을 `2021-01-03 ~ 2022-12-31`로, T4를
`2021·2022 각 연도 부호`로 바꾸고 VALIDATION/TEST 경계는 유지한다.
T2는 두 선택지가 있다. (a) 원문 `순기댓값 ≥40.9bps`를 보수적으로 유지;
(b) 사용자 C8 선택지 1의 본래 의미에 맞춰 **총효과 ≥42.44bps**로 단위를
정정하고 T1의 비용 후 2SE 하한 양수 조건은 그대로 유지. 사용자는 (b)를
승인했고 TRAIN 결과 전에 고정했다.

**TRAIN 결과는 아직 실행하지 않았다.** T2·기간 충돌은 해결됐지만
[04 G6 감사](04-a1-g6-readiness.md)의 PIT 거시 일정이 없어 실행할 수 없다.
R3의 2배 비용은 사전 추정 20bps의 2배인 **40bps**로 §11에 고정했다.
