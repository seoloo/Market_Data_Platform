3. 기존 코드에서 확인한 중요한 차이
E01 현물/선물 manager가 자기 저장소 상태를 봄. 두 경로 공통 진입 차단/현금 예약 없음.
E02 CappedResult.done은 최소미만 잔량에서도 True, 원격flat 증거 아님.
합성 requested0.005/filled0.004/remainder_below_min → done=True/산술잔량0.001.
실제 거래소 잔량 사건이 아니라 반환값 의미만 확인.
E03 선물 submit_capped는 재시도마다 새 mark±0.3%, 기본3회. 최초 총한도는 별개.
E04 부재 조회로 NOT_PLACED가 되는 경로: in-flight POST/취소가 있으면 조기 확정하면 안 됨(C12).
E05 응답 누적체결 그대로 적용/저장소 update에 세대·CAS 비교 없음. 역순 결과 방어 필요(C12).
E06 일반 SpotOrderManager는 시장가, T/v2는 예외 추격. 새 복귀에 자동 상속하지 말 것.
E07 OverlayFuturesExecutor는 max(quantity,0)의 롱 오버레이 경로. RSI signed숏 직접 주입 금지.
E08 청산후60분과 계좌의 더 긴 cooldown을 구분. 확인 전에 시작하거나240분을60분으로 축소 금지.
E09 기존 WAL/NORMAL·행별 기록은 두 다리 전송 원자성/정전 내구성 인증이 아님(C13).
E10 이전 연구의 공유cash/1x·목표25% min 식에 증거금10% cap이 없다(C14 신규 등록).
이 차이는 연구 위험 parity 미완료이지 실거래 위반/실사고 확인이 아님. 원래 결과 소급 수정 금지.

4. 원격 청산 완료 계약
숏 수량 정확히0 + 이전 신규/청산/취소 요청 모두 종결·누적체결 반영
+ in-flight/UNKNOWN/미종결claim 없음 + 신선한 포지션/주문 목록/체결 대조
+ 외부소유 주문 없음 + flat확인 후 자기잔여stop 정리 + 증거 영속 저장.
FILLED/CANCELED/done/WS정상/한번의0조회로 대체하지 않는다.
step 이하 잔량도 숏을0으로 지우지 않는다. 최소미만이면 보호·대조/수동 경계.
일반 시장가 dust 청산 예외를 만들지 않는다. 보호부터 취소하고 청산하는 순서 금지.
