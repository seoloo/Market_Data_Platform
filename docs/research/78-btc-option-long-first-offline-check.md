# 78 — BTC 옵션 보호 롱 방식: 오프라인 필요조건 검증

작성: 2026-09-26 · Phase 0. 사용자의 “검증 후 의미 있으면 적용, 아니면 제외”를 **조건부 연구 진행**으로 적용한다. 보호 롱을 현행 거래소 측 스톱과 동등하게 승인하거나 주문 경로에 적용한 것은 아니다. [76의 순차 방식](76-btc-option-long-first-protection-study.md)과 [77의 RFQ 감사](77-btc-option-rfq-api-and-leg-contract.md)를 전제로 한다.

## 사전 구분: 무엇을 통과해야 하는가

| 문턱 | 확인 방법 | 실패/자료 부족 시 |
|---|---|---|
| A. 계약·수량의 단독 숏 방지 | 같은 기초자산·정산자산·만기·콜/풋·계약단위와 올바른 행사가 관계. 거래소 확인 보호 롱에서 타 연구 배정량·잠재 롱 매도량을 빼고, 확정 숏+미체결 숏+`UNKNOWN` 숏의 최대량+신규 제안량을 비교 | 불일치·음수·불명·조회 불완전은 거부. 이것은 **필요조건만** |
| B. 계좌 위험 | 실제 옵션 계정의 최소 수량·롱 매수 비용·독립 숏 초기/유지증거금·기존 포지션·가용잔고·청산 경로를 1% 거래 위험/10% 증거금/1.5배 잔고와 대조 | 계정값이 없거나 만기 손실로 중간 청산 손실을 대체해야 하면 `UNVERIFIED`; 실거래 차단 |
| C. 중단·청산 | 연결·조회 실패, 보호 롱 소멸, 숏 부분 체결, 숏 매수 청산 미체결에서도 거래소 측 보호/비상 청산 규칙의 동등한 안전성을 명세와 장애 시험으로 확인 | 시간 상한과 손실을 증명 못하면 옵션 매도 적용 불가. `LIMIT IOC/FOK` 요청은 청산 완료가 아님 |
| D. 경제성 | 거래 가능 양방향 호가·수량, 다리별 비용, 실제 독립 거래 수를 확보한 후에만 전략을 사전등록. 비용 후 효과와 기존 T/v2 대비 증분을 [현행 80% 검정력](../current/BACKTEST_AND_TESTING.md)으로 검증 | 무료 월 1일 자료로 연중 체결·수익을 추정하거나 가격/문턱을 재조정하지 않음. 부족하면 `DATA_INSUFFICIENT`로 제외/보류 |

순서는 A → B/C → D다. A만 통과해도 **적용 판정은 아니다**. 전략 손익을 먼저 보고 기준을 바꾸지 않는다. 기존 위험 한도와 Paper 일정은 유지한다.

## 실제 수행한 A단계: 연구 전용 검사기

[`option_protection.py`](../../src/auto_trading/research/option_protection.py)는 운영 주문 코드에서 호출하지 않는 순수 진단이다. 수량 네 범주(확정 숏·활성 숏·응답 불명 숏·제안 숏)를 모두 보호 롱 예약에 넣는다. 확정 롱에서 다른 용도로 배정한 양과 아직 실행될 수 있는 롱 매도 주문을 빼며, 계약이 다르거나 원격 상태·수량이 불명이면 거부한다. [`test_option_protection.py`](../../tests/research/test_option_protection.py)는 경계·부분 체결 전이·`UNKNOWN` 보수 예약·만기/행사가 불일치·콜/풋 방향·NaN/결측과 정수 격자 속성 검사를 수행한다.

검사 결과는 `necessary_condition_met`이며 **`live_ready` 같은 출력은 의도적으로 없다**. [import-linter 계약](../../pyproject.toml)은 운영/매매 계층이 이 독립 연구 모듈을 가져오지 못하도록 검사한다. 호출자가 “원격 상태 완전”이라고 잘못 표시하거나 읽기 직후 수동 거래·강제청산이 발생하는 경쟁 조건은 이 순수 함수가 발견할 수 없다. 수량 검증은 계좌 위험·호가 체결·손절·수익성을 증명하지 않는다.

## B/C 반례: 만기 손실 한도 ≠ 중간 청산 손실 한도

다음 수치는 **거래소 실측·추천 주문이 아닌 산술 반례**다. equity 10,000 USDT, BTC 지수 100,000, 0.01 BTC 계약단위 1의 콜 스프레드(숏 K=100,000, 롱 K=110,000)를 가정한다. 숏 매도 체결가 2,000/BTC, 보호 롱 매수가 1,000/BTC라면 순수취액은 `10 USDT`, 만기 이론 최대 손실은 `(110,000−100,000)×0.01−10 = 90 USDT`로 초기 equity의 1%인 100보다 작다. 보호 롱 단독 비용도 10이다. [Binance 옵션 매도 안내의 초기증거금 식](https://www.binance.com/en/support/faq/detail/1ceb77f837344e3085ecf98d9a6a8097)에 ATM·숏 마크 2,000을 대입한 **숏 포지션 초기증거금 예시**는 `(max(100,000×10%, 100,000×15%)+2,000)×0.01 = 170 USDT`; 주문 초기증거금·기존 노출을 합산한 실제 계정 검사는 아니다.

그러나 만기 전에 숏 매수 청산의 실행 ask가 12,000/BTC이고 롱 매도 bid가 0이라면, 두 다리를 즉시 닫는 비용은 `120 USDT`, 초기 순수취 10을 뺀 손실은 **110 USDT**(수수료 제외)다. A단계 수량 불변식과 만기 이론 손실 ≤100이 동시에 성립해도, 이 조기 청산 경로는 계좌 1%를 넘는다. 두 exit 호가는 실제 관측값이 아니며 확률 추정도 아니다. **실행 가능한 가격·시간의 상한이 없으면 만기 식만으로 1%의 계좌 경로 보증을 만들 수 없다는 반례**다. Binance는 일반 계정의 옵션 스프레드 증거금 상계를 기본 지원하지 않고, 강제청산 시 숏을 단계적으로 닫으며 수수료를 부과한다고 설명한다. 따라서 보호 롱의 존재만으로 B/C를 통과 처리하지 않는다.

## 이번 판정과 중단선

`A_OFFLINE_INVARIANT_TESTED / ACCOUNT_PATH_UNVERIFIED / TIMED_EXIT_UNVERIFIED / ECONOMICS_UNTESTED / NO_TRADING_APPLICATION`.

보호 롱 선체결은 숏 선체결 사고를 줄이는 **의미 있는 설계 요소**라서 연구용 진단은 남긴다. 하지만 현재 검증으로는 옵션 매도에 필요한 B/C를 충족하지 못한다. 따라서 **기존 전략·Paper·데모·실거래에는 적용하지 않는다.** B/C를 풀 공식 기능·계정 근거가 확보되지 않으면 이 실행 후보를 제외한다. 그 전에 수익 백테스트를 하거나 유료 자료를 사서 이 결함을 덮지 않는다. B/C를 충족할 수 있더라도 D에서 비용 후 수익과 검정력이 없으면 전략 후보에서 제외한다.

후속 작업이 허용되는 경계: 먼저 공식 옵션 서비스/계정 조건을 읽기 전용으로 확인할 방법을 설계하고, 사용자 별도 승인 범위에서만 실제 계정 자격·잔고·최소 수량을 조회한다. 안전한 옵션 전용 보호·청산 정책은 **근거·장애 시험·사용자 확정이 함께 있을 때만** [TRADING_CORE](../current/TRADING_CORE.md)에 별도 변경한다. 이번 작업에서 계정 접속·주문·정책/위험 한도 변경은 없다.
