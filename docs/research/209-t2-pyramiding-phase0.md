## 2. 가설과 비교군

- H0: 추가 비용·funding·반전 시 이익 반납 때문에 C는 B의 위험 대비 성과를 경제적으로 유의하게 개선하지 못한다.
- H1: 실패한 추세에는 작은 초기 노출만, 계속되는 추세에는 증액 노출을 가져가 개선한다.
- **주 비교 C−B:** B는 아래 C에서 두 추가 진입만 제거한다. 다른 규칙은 전부 같다.
- A는 기존 T/v2와 O/v1 각각. 원래 상품/비용/회계에 따른 역사 재현과 신규 지정가 현실화 비교를 분리한다.
  옛 종가 체결·funding 종가 근사는 새 지정가/실제 정산 모형과 같지 않다.
  A−C 차이를 추가 진입의 인과적 효과로 주장하지 않는다.

## 3. T/v2의 정확한 롱 허용 상태

원천은 `backtest.trend.target_weight(spot_closes, TrendConfig(long_only=True))`다.

```
d = mean(sign(C[t]/C[t−k] − 1), k=20,60,120)
sigma = sample_stdev(최근 60개 일간 log return) × sqrt(365)
w = max(d,0) × min(0.15/sigma, 0.5)
LONG_ALLOWED = w is not None and w > 0
```

최소 **121개 마감 현물 일봉**이 필요하다. 변동성 0이면 w=0, 이력 부족이면 None.
0이 아닌 부호 셋에서는 보통 둘 이상 상승이면 허용하지만, 동률 0도 있으므로
"두 개 상승"으로 코드 논리를 다시 작성하지 않는다.
신호는 **기존처럼 현물** BTCUSDT/ETHUSDT 일봉, 주문·ATR·손익·funding은 **실제 USD-M 무기한**이다.
현재 바의 완성 정보는 `close_ms+1` 이후만 노출한다. `open_ms`는 감사 표의 날짜 라벨이지 판단/체결 시각이 아니다.

최종 사전등록 커밋으로 동결해야 한다. **현재 동결된 운영 전략이나 구현된 백테스트가 아니다.**

### 위험 계약과 기존 구현의 차이

- 합산 현재가격→stop의 양의 가격손실 `sum(q_i×max(mark_i−stop_i,0))`를 사용한다.
  최초 원가 대비 손익이나 다른 종목의 이익으로 상쇄하지 않는다. 현재 equity의 1% 안에
  비용·불리한 funding·비상 체결 여유까지 들어오도록 신규/추가를 축소 또는 생략한다.
- 총 명목은 equity×1.5 이하라는 사용자 상한과 기존 더 엄격한 제약을 **동시에** 적용한다.
  연구의 레버리지 상한은 기존 O와 같은 3배로 제한하고 포지션당 증거금 10%·가용잔고 1.5배 여유·
  청산거리/stop거리≥2·내림 후 오차≤5%도 유지한다. 1.5배가 허용됐다는 이유로 이를 없애지 않는다.
  이 조합에서는 두 포지션의 총 명목 상한이 더 낮아질 수 있다.
- BTC/ETH 동시 의도는 현재 잔여 위험/노출/증거금 예산을 희망 주문 비례로 배분한 뒤 내림.
  남는 단위는 재분배하지 않는다. 한 종목만 유리하게 먼저 채워 위험을 독점하지 않음.
- 일 손실은 UTC 시작 equity 대비 실현+미실현, −2%면 증가 금지; 축소는 허용.
  DD는 평가 고점 대비 −30%면 영속 HALTED, 자동 해제 없음, 지정가로 잔량 청산.
  4연패/240분 cooldown·청산 후60분을 그대로 적용하며 거래 묶음 순손익 기준으로 연패를 센다.
  계좌 정지 후 표본이 줄어든다고 정지를 끄지 않는다.
- 기존 G4 `POSITION_EXISTS`는 추가 진입을 거부하는 단일 포지션 구조다.
  따라서 현행 Risk에 "그냥 추가 주문을 넣는 것"은 재사용이 아니다. 별도 연구 다중종목/추가위험
  계약과 테스트가 필요하며 운영 게이트를 수정하지 않는다.
- C1 `WIDEN`은 미해결이다. ATR stop을 임의로 넓히지 않고 기존 1% 최소거리 미달은 신규 연구에서 거부하는
  보수적 초안으로 둔다. 운영 sizing의 정책을 바꾸지 않는다.
- 보호 공백 5초·등록 실패 청산 예외는 유지. 과거 OHLC는 실제 API 장애/5초 보장을 검증하지 못한다.
  C11 독립 감시 미완료도 이번 연구로 해결됐다고 주장하지 않는다.

## 5. 비용과 회계

- 주판정 편도 **9.5bp = 수수료4.5bp + 기본 불리폭5bp**: 최초/각 추가/청산 실제 명목에 각각.
  지정가 체결 가격을 별도로 모델링할 때 5bp를 두 번 붙이지 않는 회계 계약이 필요하다.
  체결 모델의 5bp 불리 가격 이동과 수수료4.5bp, 또는 reference-price에 합산9.5bp 중
  하나로 구현·수작업 일치 확인한다. 현재 성과 계산은 하지 않았다.
- 비상 stop은 갭/장애에 따른 추가 불리폭을 기본5bp와 분리한다.
  27의 비상 추가1%를 계약 후보로 유지하되 가격 한도가 아닌 STOP_MARKET 예외임을 표시한다.
- funding은 **실제 지급 timestamp 직전 보유 수량×그때 mark×rate**.
  3번 진입한 최종 수량에 과거 전체 funding을 붙이지 않음. 동시 timestamp에서는 기존 보유의 funding→stop/청산→새 진입 순서.
- 수수료·기본 불리폭·비상 추가 불리폭·funding을 따로 기록.
  현실비용0.023%는 참고용일 뿐 9.5bp 주판정을 대체하지 않음.
- 거래 묶음은 최초 체결~최종 청산 **하나**. 추가 주문을 독립 거래/독립 표본으로 세지 않음.

## 7. 검정력·판정 설계와 왜 멈추는가

주지표 후보를 **연환산 Sharpe(C)−Sharpe(B)** 하나로 제한한다.
정책상 최소 의미 폭은 **0.20**으로 제안한다. 복잡한 추가 주문·보호 경합을 감수하려면
기존T/v2의 역사 Sharpe약1.2 대비 작은 수십분의1 개선은 부족하다는 운영상 기준이며,
**실제 참효과가0.20/0.40이라는 추정이나 문헌의 보장값이 아니다**.
최종 채택 초안은 차이의 의존성 보정 단측 하한이0.20을 넘고 계좌/비용/구간 게이트를 함께 통과하는 것이다.
여러 지표 중 수익/CAGR/MDD가 잘 나온 것을 주지표로 교체하지 않음.

Sharpe 차이의 SE는 B/C의 동시 수익, 2~4차 모멘트, 시간 의존성에 달린다.
14의 `2.84/sqrt(years)`는 **한 수익열의 평균/Sharpe** 게이트다.
그 식에0.20을 넣어202년이라고 계산하거나 증분(C−B)의 Sharpe를 Sharpe(C)−Sharpe(B)로
바꾸는 것은 이번 질문의 검정력 계산이 아니다.
[Ledoit & Wolf 원문](https://www.econ.uzh.ch/apps/workingpapers/wp/iewwp320.pdf)은
비정규/시계열 자료에서 Sharpe 차이의 HAC/시간계열 bootstrap 검증을 다룬다.
그 방법도 정상성 등의 가정을 요구하고, 희소한 큰 추세 사례를 새로 만들지는 못한다.

프로젝트 z=2·power0.80 관행을 delta-Sharpe의 근사 정규 계획에 옮기면,

```
필요 SE <= (가정 참 ΔSharpe − 0.20)/(2 + Φ^-1(0.80))
```

| 참 차이 가정(실측 아님) | 필요한 SE 상한 |
|---|---:|
| 0.30 | 0.03519 |
| 0.40 | **0.07038** |
| 0.60 | 0.14076 |

**참 차이에 대한 독립 근거도, paired SE 측정도 없다.** 0.40/0.60을 임의로 기대치로 정해
80% 통과를 선언하지 않는다. 현재 달성 검정력은 **NOT_MEASURED**이며0%로 보고하지 않는다.
추후 적합한 독립 calibration/제한된 파일럿의 권한·경계를 먼저 확정해야 한다.
동일 UTC 날짜 벡터(BTC/ETH, B/C)를 함께 resample하는 paired 시간 블록으로 상관을 보존하고,
TRAIN 내부의 분산/의존성 추정만 검정력에 쓰며 VALIDATION/TEST에서 블록이나 효과를 고르지 않는다.
정확한 bootstrap 블록 길이·studentization·시드·반복수는 calibration 없이 지금 통과된 계약으로 확정하지 않는다.

현행 [Phase 4](../current/BACKTEST_AND_TESTING.md)는 실제 OOS 거래100건 이상을 요구한다.
선택한 후향 TEST는 **신호 상한부터66~68 < 100**, 실제 미사용 BTC/ETH 과거도 없다.
이 거래 수 조건은 Sharpe 추정의 표본 단위와 다르지만 채택 게이트로서 따로 적용된다.
전체 과거136회 합계를 TEST로 옮기거나, BTC/ETH를 독립으로 간주하거나,
추가 주문3개를3거래로 세어 게이트를 우회하지 않는다.
**이 분할/가용 자료로 현행 판정 절차를 완료할 수 없어 Phase 0 DATA_INSUFFICIENT.**
전략이 손실이라는 REJECT도, 모든 통계 설계에서 불가능하다는 수학적 결론도 아니다.
