## 2. 가격과 자료 상태를 분리하는 어댑터 계약

- `OBSERVED`: 출처·시각·OHLCV·정밀도가 유효한 실제 행.
- `KNOWN_SPOT_CLOSED`: 공식 증거로 확인한 중단. 행이 있어도 체결 불가.
- `UNEXPLAINED_GAP`: 원인 미확인 공백/순서/판본 차이. 파일럿 시작 금지.

없는 가격은 None과 availability mask로 표현한다. 실행 OHLCV로 forward-fill하지 않는다.
별도 평가 장부에서만 그때까지 확인된 종가를 stale 표시와 함께 사용할 수 있다.
이는 중단 중 자산의 참 가치나 실제 MDD 인증이 아니다. 미래 재개 가격을 거슬러 사용하지 않는다.
현물 중단 중 stale 계좌 평가로 신규 노출은 거부하고 관측 가능한 선물 청산·보호는 유지한다.
공식 재개 예고를 미래 매수 신호로 사용하거나 미리 유리한 주문을 내지 않는다.
두 군에 동일하게 적용하고 4h 신호·일봉 목표를 수익에 맞춰 재생성하지 않는다.
후일 원인 설명은 자료 감사 증거이지 당시 사용 가능한 예측 feature가 아니다.
전체 중단 경계·원천 대조·어댑터 검증이 끝나기 전 **DATA_NOT_READY**를 유지한다.

## 3. 대기·시간창·시도 예산

60분 대기·240분 시도창은 달력 시간으로 흐른다. 중단 중 시계를 멈추거나
만료 뒤 새 240분을 주지 않는다. 거래 불가면 전송 없이 VENUE_CLOSED로 기록한다.
거래 가능·ACK·대기·위험을 통과해 실제 모형 제출을 한 경우에 시도 예산을 쓴다.
제출 후 가격 한도/0거래량/재원으로 미체결이면 시도에 포함한다.

복귀 BUY 최대 3회는 **목표 판본의 의도 예산**이다. 부분체결·주문 객체 제거·재평가로
0회로 초기화하지 않는다. 다음 일봉 목표 판본에서만 새 기준가·수량·창·3회를 부여한다.
원 복귀 요청은 유지하고 판본 갱신 수와 제출 수를 따로 기록한다.
4h군은 240분 창 안에 격자 기회가 한 번만 있을 수 있다는 구조도 보고한다.

## 4. 회계·실행 초안에서 확인한 보완점

- 조각마다 체결 가격·fee 차감 후 equity의 총 명목/종목 비중 cap·현물 지갑 재원을 재검사한다.
  복리 비용의 정확한 손절 손실도 검사해 근사식보다 큰 경우 더 엄격한 값으로 위험 예산을 제한한다.
  선물 미실현 손실은 신규 가용 재원을 줄이고, 미실현 이익을 현물 cash로 이체하지 않는다.
- 두 종목이 같은 분에 stop된 뒤 수ms funding이 오더라도 해당 종목 거래 묶음에 귀속한다.
  positive credit 생략/negative debit 유지라는 기존 보수적 순서 규칙은 그대로다.
- 봉 끝 보유량만 low/high에 곱하면 중간 포지션 위험을 놓친다. 실행 분의 전·후 보유·현금을
  각각 검사한다. 이는 관측 4h peak 기준의 보수적 스트레스 대리이며 실제 tick MDD 상한 인증이 아니다.
  사후 high/low 스트레스를 당시 위험 차단이나 수량 계산으로 역유입하지 않는다.
- 중단 중 stale 평가 수·보유 노출·선물 보호/청산을 따로 기록한다. 미관측 위험을 낮은 MDD로 확정하지 않는다.

## 5. 롱 수익 누락의 설명 기록

양수 목표 전환 전체와 숏 충돌 복귀 사건을 구분한다.
복귀마다 요청 → 숏 청산 → 정확한 0/ACK → 60분 완료 → 첫 매수 →
목표량 완료/시도 소진/창 만료/목표 소멸의 시각을 기록한다.
사유는 VENUE_CLOSED / STALE_VALUATION / SHORT_REMAINS / ACK_PENDING / COOLDOWN /
GRID_WAIT / CAP_MISS / CASH_SHORTAGE / RISK_VETO / ATTEMPT_EXHAUSTED /
WINDOW_EXPIRED / GOAL_ZERO / END_UNRESOLVED로 나눈다.
거부 평가 수와 독립 요청 수를 구분한다. 분별 평가 수를 거래 수로 부풀리지 않는다.
놓친 상승은 사후 설명값이며 신호로 쓰지 않는다. 사건별 이동 대리와 계좌의 실제 순증분도 구분한다.
