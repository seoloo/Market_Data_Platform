## 2. 실제 사례: 지수 퇴출 ≠ 상장폐지 ≠ 마지막 거래 ≠ 정산

### A. Twitter — 세 날짜가 다르다

[S&P 2022-10-27 공고](https://press.spglobal.com/2022-10-27-Arch-Capital-Group-Set-to-Join-S-P-500-RXO-to-Join-S-P-MidCap-400-Bread-Financial-Holdings-to-Join-S-P-SmallCap-600)는
TWTR→ACGL의 S&P 500 교체 시행을 **2022-11-01 장 시작 전**으로 정했다.
공고 당시 인수는 10-28 예상 완료로 설명했다. 예상 사건과 실제 완료를 분리한다.
[SEC 8-K](https://www.sec.gov/Archives/edgar/data/1418091/000119312522272772/d411753d8k.htm)는
합병 완료 **2022-10-27**, NYSE 거래 정지 **2022-10-28 장 시작 전**,
일반 보통주의 주당 현금 수령 권리 **54.20 USD**(공시 예외 조건 존재)를 설명한다.

이 원문은 **실제 계좌 지급일·비용·주식 수·총수익 완성 자료가 아니다**.
주당 현금 권리를 지수 퇴출일의 시장가 체결이나 현금 도착으로 가정하지 않는다.
지수 퇴출까지 거래 가능하다고 두면 이미 정지된 종목에 주문하는 오류가 생긴다.
끝나는 기업을 목록에서 지우거나 종료 수익을 0/−100%/마지막 종가로 채우지 않는다.
유니버스 편입일·거래 정지·증권 취소·수령 권리·실제 현금 가용일은 별도 사건이다.

### B. American Airlines / Etsy — 지수 퇴출만으로 상장폐지 판정 금지

[S&P 2024-09-06 공고](https://press.spglobal.com/2024-09-06-Palantir-Technologies,-Dell-Technologies,-and-Erie-Indemnity-Set-to-Join-S-P-500-Others-to-Join-S-P-MidCap-400-and-S-P-SmallCap-600)의
시행일은 **2024-09-23 장 시작 전**이다. AAL은 S&P 500→400, ETSY는 500→600으로 이동한다.
공고 날짜부터 새 지수 구성으로 바꾸지 않는다. 이 이동 공고는 상장폐지 증거가 아니다.
현재 로컬 목록에서 TWTR은 두 지수 모두 없음, AAL은 현재 400에만, ETSY는 둘 다 없음.
이는 현재 파일의 관찰이지 전체 당시 구성이나 회사 가치/투자 수익의 판단이 아니다.
500+400 합집합이라도 지수 내부 이동·600으로 빠진 종목·신규 편입을 정확히 연결해야 한다.

### 역사 복원 계약 — 제안, 아직 자동 재생 없음

1. 기준 세션의 **완전한 동시대 구성 명부**와 증권 식별 연결을 확보한다. 기준일/수집일/출처 해시를 분리한다.
2. 대상 기간의 변경·정정 공고를 빠짐없이 연결한다. 수량이 맞는다고 완전성이 증명되는 것은 아니다.
3. `announced_at_ms`(모르면 unknown), `effective_session`, 장전/장후 시행 구분, 실제 `first_seen_at_ms`를 보존한다.
4. 공고의 ticker·거래소·주식 종류를 당시 증권에 연결한다. CIK는 기업 식별이지 한 주식 종류의 영구 증권 ID가 아니다.
5. 기준선도 동일 당시 유니버스를 사용한다. 편입/퇴출에 따른 필수 매매·종료 사건·비용을 계산한다.
6. 종료 증권의 거래 가능성·정산 경로가 미확인이면 그 구간은 **TERMINAL_SETTLEMENT_UNVERIFIED**.
   손실기업만 누락시켜 통과시키거나 전체 기업 실패를 특정 행 0으로 감추지 않는다.

이번 SP 공고의 날짜를 임의 UTC 자정으로 바꾸거나 2026 수집 시각을 과거 first-seen으로 쓰지 않았다.
주석/사건 수동 검토를 자동 이벤트 파서가 완성됐다는 주장으로 확대하지 않는다.

## 3. 실제 회계 기준 변경 — 이름만 바꾸면 안 되는 이유

Microsoft 같은 회계기간 **2016-07-01~2017-06-30**의 연결 합계를 대조했다.

| 표준 fact / 제출본 | 매출(백만 USD) | 영업이익(백만 USD) | 해석 |
|---|---:|---:|---|
| 2017 10-K `0001564590-17-014900` | 89,950 (`SalesRevenueNet`) | 22,326 | 당시 보고값 |
| 2018 10-K `0001564590-18-019062`의 2017 비교열 | 96,571 (`RevenueFromContractWithCustomerExcludingAssessedTax`) | 29,025 | 새 기준으로 재작성된 비교값 |

실제 SEC JSON과 [2017 원문](https://www.sec.gov/Archives/edgar/data/789019/000156459017014900/msft-10k_20170630.htm),
[2018 원문](https://www.sec.gov/Archives/edgar/data/789019/000156459018019062/msft-10k_20180630.htm)의 연결 재무표를 대조했다.
[2018 공식 연차보고서 Note 1](https://www.microsoft.com/investor/reports/ar18/index.html)은
2017-07-01부터 수익인식 기준을 조기 적용하고 전기 표시를 다시 작성한 이유를 설명한다.
동일 기간의 차이를 새 사업 성장으로 계산하지 않는다.

**중요 보완:** [2017 공식 연차보고서 Note 1](https://www.microsoft.com/investor/reports/ar17/index.html)의
`Expected Impacts to Reported Results`에도 조정 후 매출 96,571이 이미 공개되어 있었다.
따라서 이 금액 자체가 2018년에 처음 알려졌다고 주장하면 틀린다.
2017의 예상 조정 **주석**과 2018의 재작성 **표준 fact**는 정의·버전·출처가 다르다.
주석을 이용하려면 당시 원문에서 별도 정의로 추출/검토해야 하며, 2018 fact를 과거 accession으로 바꾸지 않는다.

현재 스냅숏의 선택된 CFO 표준 태그에는 원래 2017 accession의 이 기간 행이 없고,
2018 비교열에는 39,507이 있다. 그러나 **2017 원문 현금흐름표에도 39,507이 있다**.
API 표준 fact 결측을 당시 공시 자체의 결측/현금흐름 0으로 오해하지 않는다.
이 표본은 최신 companyfacts만으로 원문 전체를 복원할 수 없음을 보여준다.
원문 추출 경로는 별도 검증 과제이며 이번에 표준 fact를 임의 생성하지 않았다.

### 태그 재고 관찰 — 이 숫자는 커버리지 PASS가 아니다

기존 보관 JSON만 조사, 추가 기업 전체 수집/성과 열람 없음.

| 기업 | 현재 매출 태그 행수 / 기간 최소 start | 옛 SalesRevenueNet 행수 / 최소 start |
|---|---|---|
| Apple | 117 / 2016-09-25 | 210 / 2006-10-01 |
| Microsoft | 134 / 2015-07-01 | 173 / 2008-07-01 |

기간 최소 start는 **그 시기에 현재 태그가 이미 알려졌다는 뜻이 아니다**.
나중 공시의 비교열이 더 오래된 기간을 설명할 수 있으므로 accession/접수/가용을 함께 검사한다.
제품/서비스 일부 태그나 `Revenues`도 보이지만 합계 태그로 자동 대체/합산하지 않는다.

## 4. 처리 기준 — 연구 설계안, 자동 매매 필터 아님

| 구분 | 처리안 | 이번 구현 상태 |
|---|---|---|
| 이름 변경만 있고 정의/단위/연결 범위가 동일하다는 원문 증거 | CIK·기간·accession·basis별 제한적 alias 승인 기록 | 전역 alias 없음, 증거 registry 설계 전 |
| ASC606 등 인식 기준 변경 | 당시 보이는 같은 기준으로 전기/당기 비교가 가능한 경우만 계산, 불가하면 ACCOUNTING_BASIS_BREAK | 기존 순수 계산기는 다른 basis 혼합 거부, 실제 사례 회귀 추가 |
| 인수/분할/연결 범위 변화 | reported totals와 organic 개선 분리, 해당 시점 주석 경고 유지 | 자동 organic 보정/영구 기업 제외/성과 맞춤 가중치 없음 |
| 회계 추정·일회성 비용·재분류 | 영향 범위/적용 기간·출처 확인, 미확인 상태를 별도 표시 | 135 수동 경고 유지, 숫자가 같아도 모든 항목 동일 기준 인증 아님 |
| 표준 fact 누락 / custom·주석에만 존재 | 원문 검토 가능 여부를 구분, 불확실한 비교는 보류 | 0 대체/후기 비교값 소급/임의 standard fact 생성 없음 |

`basis_id`는 단순 기업명/연도 이름이 아니라 검토한 기간/측정/회계 정의의 인증 범위를 표시해야 한다.
다른 기준으로 매출 분모와 영업이익 분자를 섞으면 이익률도 잘못된다.
경고를 발견한 뒤 과거 수익이 좋게 나오도록 기업/기간을 선별하지 않는다.
모델 제외/수동 검토의 최종 규칙·검토 실패율·임계값은 성과 열람 전 사전등록에서 확정한다.
회계 경고는 결과를 본 뒤 덧붙이는 예외 규칙이 아니라 데이터 품질 설계 과제다.

## 6. 다음 작업 — 결정 전에 유한 범위의 실제 자료 점검

**Phase 0 — 무료 동시대 기준 구성 명부와 종료 증권 가격·정산 경로의 제한 표본 감사**.
과거 기간을 임의로 골라 이미 성공한 전략을 찾는 작업이 아니라, 사전 정의한 자료 계약의 실현 가능성을 확인한다.
공식 출처의 구성 명부 기준점 1개를 찾고, 그 시점 이후 변경 체인의 완전성 확인 경로를 점검한다.
