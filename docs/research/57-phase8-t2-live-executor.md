## 1. 무엇이 준비됐나

`execution/live_t2.py` 의 `LiveT2Runner` — Paper 와 **같은 판단**(신호·1 일 지연·밴드 5%p·오래된 목표 금지)을 **거래소 실제 잔고**로 크기를 정해
**지정가 L240**(42 §7: 1호가 post-only, 최대 4 시간, 남은 수량 시장가)으로 체결한다.

| 규칙 | 구현 |
|---|---|
| 선기록 | 그날 결정 기록(`paper_days`)을 주문보다 먼저, 주문마다 PENDING 을 거래소 호출 전에 커밋(`spot_orders`) |
| 멱등 | 주문 ID = `<tag>-<결정일>-<종목>-<B/S>`(추격 `…m`). 같은 날 몇 번을 돌려도 주문 1 건 |
| 결과 모름 | 조회로만 해소. 거래소에 없으면 NOT_PLACED 로 닫고 **다시 보내지 않는다** |
| 재시작 | 대기 중 죽어도 다음 실행이 DB 의 미해결 지정가를 **이어받아** 남은 시간만 기다리거나, 시간이 지났으면 취소 뒤 추격 |
| fail-closed | 조회가 안 되는 주문이 남으면 그날 새 주문 없음(DEGRADED) |
| 긴급 정지 | `data/HALT` 가 있으면 새 주문 없음(HALTED) — 51 §5 와 같은 스위치 |
| 알림 | 예약(연구·주문·이유) · 체결(대기·중간가 대비 비용·수수료) · 추격 · 정지·장애 |

## 2. 장애 시험 (`tests/execution/test_live_t2.py`, 가짜 거래소 9 건, 모두 통과)

| # | 상황 | 확인 |
|---|---|---|
| 1 | 첫날 → 둘째 날 | 첫날 목표만 기록(NO_PRIOR_DECISION), 둘째 날 maker 체결, 예약·체결 알림 |
| 2 | 같은 날 재실행 | 새 주문 0 |
| 3 | 대기 중 강제 종료 → 10 분 뒤 재시작 | 이어받아 체결, 중복 주문 0 |
| 4 | 강제 종료 → 5 시간 뒤 재시작(제한 시간 지남) | 취소 뒤 시장가 추격, 미해결 0 |
| 5 | 긴급 정지 파일 | HALTED, 주문 0, 알림 |
| 6 | 전송 결과 모름 + 실제로는 접수됨 | 조회로 이어받아 체결 |
| 7 | 전송 결과 모름 + 거래소에 없음 | NOT_PLACED, 다시 보내지 않음 |
| 8 | 조회 장애가 남음 | 다음 날 DEGRADED, 새 주문 0 |
| 9 | post-only 3 번 거절 | 시장가 추격 |
