# 235 — AG + 숏 2 배 · 3 배 (설명용 후향, 사전 고정)

2026-10-15 Claude. 사용자: "혹시 ag3 + 숏2배 ag4 + 숏2배, 숏3배도 확인해줄래?".
상태: **계산 전 고정**. §1 ~ §4 는 결과 전에 커밋한다.

## 1. 무엇을

[232](232-ag-short-own-gate.md)는 숏 배율을 1 배와 최대(AG3 = 3 배, AG4 = 4 배)만 봤다. 사이 값을 본다.

| 계좌 | 숏 배율 |
|---|---|
| AG3 + 숏 2 배 | 2 |
| AG4 + 숏 2 배 | 2 |
| AG4 + 숏 3 배 | 3 |

엔진 · 자료 · 비용 · 숏 규칙 · OWN 차단은 232 그대로(Codex 교정판 엔진 `c9f99b2`, 입력 `96dc977…`, 2020-06 ~ 2026-08,
4 민감도 BASE · COST2 · THIN · ACK5). 엔진 Case 는 1 배 · 최대만 등록돼 있어, SHORT_MAX 계좌의 숏 배율만 다른 값으로
보이게 하는 계좌 하위 클래스(`src/auto_trading/research/ag_short_lev_235.py`)를 쓴다. 배율은 손익 배수가 아니라
크기 상한(증거금 10% × 배율)이다 — 거래 위험 1% · 남은 증거금 한도는 그대로.

**대조 검사**: 같은 방법으로 AG3 + 숏 **3 배**를 돌려 232 의 AG3 SHORT_MAX 4 계좌와 순손익이 정확히 같아야 한다.
다르면 결과를 쓰지 않고 멈춘다.

## 2. 판정 (232 규칙 그대로, 설명용)

각 계좌의 `(AG + 숏 순손익) − (AG 만 순손익)` 이 BASE · COST2 둘 다 > 0 → **후향 기여 유리**, 둘 다 ≤ 0 → **불리**,
엇갈리면 **혼재**. BASE · COST2 숏 합 30 건 미만이면 **표본 부족**. 232 의 1 배 · 최대 결과와 한 표로 함께 보고한다.
