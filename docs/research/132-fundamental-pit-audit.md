## 1. 이번 범위와 접근 경계

SEC 공식 API/개발자 FAQ를 재확인했다. 공개 데이터는 무료이지만 요청자 식별 헤더와 접근 정책을 지켜야 한다.
사용자에게 **SEC 요청에 표시해도 되는 연구용 연락처**를 요청했다. 답변 전 개인정보를 외부에 보내지 않았다.
131에서 확인한 HTTP 403의 원인은 미확정이며, 연락처를 추가하면 해결된다고 보장하지 않는다.
이번에는 재요청·우회·벌크 다운로드·유료 구매 없이 로컬 감사 기반을 구현했다.

## 2. 구현한 것

연구 전용 [fundamental_pit.py](../../src/auto_trading/research/fundamental_pit.py).
I/O·네트워크·실시간 시계·난수·종목 순위/매수 신호 없음. 금액은 Decimal, 시각은 UTC epoch ms.
기존 import-linter 독립 연구 계약에 이 모듈을 추가하여 core/features/strategy/risk 및
execution/exchange/app에서 가져오지 못하게 했다. 연구 실행기까지 금지하는 계약은 아니다.

| 기능 | 검증한 내용 |
|---|---|
| `select_as_of` | 기업/태그/통화/기간 일치 후 당시 가용한 최신 접수본만 선택. 정정 공시는 가용 시점 이후에만 반영 |
| 결측·충돌 | 결측 `None`과 실제 0 구분. 최신 동일 시점의 값/회계 기준 충돌은 도메인 예외로 중단. 다른 통화/태그로 대체하지 않음 |
| `quarter_from_ytd` | 동일 시작일·기업·개념·통화·확인된 회계 기준의 누적값 차감. Q4 연간−9개월 포함. 이전 누적 결측은 0으로 간주하지 않음 |
| `trailing_year` | 정확히 4개 연속 분기만 합산. 빈 분기·중복·겹침·다른 회계 기준을 거부 |
| `growth_pct` / `margin_pct` | 기간/통화 정합성, 미래 가용 시점 차단, 0 이하 분모 거부. 비율은 퍼센트 단위 |
| 감사 출처 | 합산/차감에 사용한 모든 공시 ID와 가장 늦은 가용 시각 보존, 입력 순서에 의존하지 않는 출력 |

기간 폭 61~121일(분기)·335~395일(1년)은 SEC frames와 같은 넓은 sanity 검사다.
**이 폭만 맞으면 진짜 회계 분기라고 인정하는 것은 아니다.** 회계 달력 식별은 원문 정규화 단계에서 확인해야 한다.
현재는 기간 수익률이나 성과에 맞춘 파라미터가 아니며 특이 결산기 처리를 자동 추측하지 않는다.

## 3. 입력 계약과 아직 구현하지 않은 것

`Concept`: 10자리 CIK, taxonomy, 정확한 tag, unit.
`PeriodValue`: 기간 시작/끝, Decimal 금액, accepted_at_ms, available_at_ms,
원문 대조로 확인한 basis_id, source_accessions.

- accepted_at_ms는 **접수 시각**이지 공개/실시간 이용 가능 시각의 자동 대체값이 아니다.
- available_at_ms는 다음 거래일·공개 지연 등을 확인한 외부 입력이다. 이 모듈이 NYSE 달력/DST/공개 지연을 추정하지 않는다.
- basis_id는 누적값 차감/합산의 회계 비교 가능성을 원문으로 확인한 표식이다.
  단순히 CIK+회계연도를 같은 문자열로 붙였다고 비교 가능성이 증명되지 않는다.
- 표준 태그 간 전환/의미 확인, 과거 submissions 연결, 원자료 다운로드/정규화, 회계 달력과 기업 원문 대조는 **미구현**이다.
- 출력 함수는 종목 점수·매수 조건·보유/매도 규칙·수익성 결과를 만들지 않는다. 운영에 연결하지 않는다.

즉 **계산 기반의 합성 검증 완료**이지 실제 SEC 자료를 읽는 전체 PIT 파이프라인이 완성됐다는 뜻이 아니다.

## 4. 합성 검산 결과

누적 현금흐름 10 / 25 / 40 / 60 → 분기별 10 / 15 / 15 / 20 → 최근 1년 60.
누적값을 그대로 더한 135를 최근 1년 현금흐름으로 쓰지 않는다.
전년 50 → 현재 60의 성장률 20%, 동일 기간 영업이익 12 / 매출 60의 이익률 20%를 Decimal로 검산했다.
모두 **가상 회계 숫자**이며 기업/주가/계좌 성과가 아니다.

정정 값에 여러 난수를 대입하는 hypothesis 검사를 포함해,
8월에 가용한 정정값이 6월 판단에 영향을 주지 않고 8월 이후에는 반영되는지 확인했다.
입력 순서를 바꿔도 동일한 결과가 나오는지, 접수 후 아직 가용하지 않은 자료가 제외되는지도 확인했다.

  이후 사용자 명시 승인으로 타입 선언/재노출/불필요한 ignore만 정리했다.

최초 오류 때문에 일시 보류했던 커밋은 전체 재검증 후 타입 정리와 연구 기반을 논리 단위별로 나눈다.
기준 코드 99dcc6a, 변경 전 작업 트리는 깨끗했다. 골든/실제 연구 결과 변경 없음.
