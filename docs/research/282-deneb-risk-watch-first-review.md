## 전량 매도 확인의 의미

사용자의 추가 확인은 **“그냥 다 매도 했어 매도 하고 정지했지”**였다.
따라서 Deneb 보유분을 전부 매도하고 정지한 행동으로 기록했다.
신규 매수만 멈춘 경우와 명확히 구분한다.

- 처음의 ‘행동 범위 미확인’ 기록을 지우지 않고, 새 정정 기록을 연결했다.
- 매도 범위는 사용자 확인이며, 거래소 체결 원장 대조를 마쳤다는 뜻은 아니다.
- 정확한 매도일·체결가·수량·비용·세금·환율은 아직 미확인이다.
- 이번 진술은 10월 18일에 남긴 과거 행동의 설명이다. 매도 당시에 작성된 예측 기록으로 소급하지 않는다.
- 복귀 계획은 미정이다. 정지 해제·재매수·실제 자금 이동을 실행하지 않았다.

향후 대조해야 하는 것은 ‘규칙대로 계속 운용한 경로’와 ‘실제 전량 매도 후 대기한 경로’다.
두 경로의 시작 자산과 입출금·비용·세금·환율이 맞아야 차이를 계산할 수 있다.
TQQQ 가격이 81.29달러에서 68.21달러로 내려갔다는 사용자 진술만으로,
Deneb 전체에서 얼마를 지켰는지 계산하지 않았다.

## 기록·재생·보호 구조

원장은 `data/research/deneb_watch_282/watch.sqlite3`에 두고,
원문은 내용 SHA256을 이름으로 저장했다. 원장·원문은 Git 밖이며,
최종 요약과 수동 입력 JSON만 이번 커밋에 포함한다.

- 공시 사실·분석 가설·사용자 행동 진술·기존 장부·실패를 다른 종류로 저장한다.
- 관측 시각·공개 시각·실제 저장 시각을 구분한다. 날짜만 알면 뉴욕 날짜 종료를 보수적 경계로 쓴다.
- 나중에 가져온 자료는 과거 시점의 보고서에 나타나지 않는다.
- SQL UPDATE/DELETE는 막고, 정정은 새 기록으로 추가한다.
- 같은 ID·같은 내용은 중복 저장하지 않으며 같은 ID의 내용 변경은 거부한다.
- 원문 해시·연결 해시·기록 순서를 확인한다. 외부 공증이나 원장 말미 삭제 방지까지 보장하지는 않는다.

첫 수집 원장에는 **27개 기록**이 있다. 사실 15개·실패 6개·기존 장부 1개·행동 진술 2개·가설 3개다.
36개 항목의 확보 상태와 기록 개수는 서로 다른 개념이다.
예를 들어 SOFR 여러 날짜를 저장해도 독립적인 위험 항목이 여러 개 늘지는 않는다.
원문·파생 근거·기존 장부 사본의 고유 해시 10개를 검증했다.

## 수동 사용과 다음 순서

자동 갱신·텔레그램 발송·UI 표시는 연결하지 않았다. 수동 갱신은 프로젝트 환경에서 실행한다.

```powershell
.venv/Scripts/python.exe -m scripts.deneb_risk_watch collect
.venv/Scripts/python.exe -m scripts.deneb_risk_watch report
.venv/Scripts/python.exe -m scripts.deneb_risk_watch verify
```

새 판단은 `note --input <JSON>`으로 기록한다. 실제로 지금부터의 새 결정일 때만
`--decision-now`를 쓴다. 기록 명령은 행동을 실행하지 않는다.
과거 사용자 진술을 이 옵션으로 다시 넣어 사전 예측처럼 만들지 않는다.

다음 우선순위는 지표 조합 탐색이 아니다.

1. 사용자 매도 체결과 동일 출발점의 계좌 원장을 맞춰 ‘정지’의 실제 효과를 비교할 준비를 한다.
2. 미확보인 가치평가·시장 집중·기업 현금/만기·실적 전망의 출처, 공개 시점, 사용권을 먼저 감사한다.
3. 앞으로의 판단은 사유·반대 근거·복귀 계획을 그때 기록해 사후 설명과 구분한다.
4. 자료와 독립 표본이 모인 뒤에만 신규 납입금 연구의 검정력과 사전등록 가능성을 다시 판단한다.

검증 결과는 [validation.json](../../reports/deneb_watch_282/validation.json)에 별도로 기록한다.
기존 Deneb 실행기·정지 파일·보유 장부·280 기록의 여섯 보호 대상은 작업 전후 해시가 일치한다.
실계좌 조회·주문·기존 전략·Paper·알림·예약·위험 한도는 이번 작업에서 변경하지 않았다.
