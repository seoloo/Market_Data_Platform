# 84 — 지금 PC 를 상시 실행 환경으로 쓰기: 점검 결과와 설정 (2026-09-26)

작성: 2026-09-26 (Claude) · 상태: **PC 읽기 점검 완료 · 일일 점검에 PC 상태 한 줄 추가 · 설정 변경은 사용자가 실행(아래 명령)**
사용자 결정 (2026-09-26): "1순위하자 근데 … 수익도 안났는데 구매하는 건 좀 그렇게 일단 지금 pc로만 해야할 것 같은데".
**새 장비·서비스 구매 없음.** 시스템 설정은 에이전트가 바꾸지 않고, 사용자가 실행할 명령만 적는다.

## 1. 결론 먼저 — 실거래 1단계는 지금 PC 로 할 수 있다

| 이유 | 설명 |
|---|---|
| 하루 한 번 거래 | T/v2 는 매일 21:00 한 번 판단하고 체결한다. 그 시각에 PC 가 켜져 있으면 된다. 사용자는 저녁에 집에 있다(실행 시각을 저녁으로 옮긴 이유) |
| 놓치면 거래하지 않는다 | 하루를 놓치면 다음 실행이 오래된 목표를 체결하지 않고 새 목표만 정한다(fail-closed). 잘못 사고팔지 않는다 |
| 현물이라 청산이 없다 | 1단계는 레버리지 없는 현물이다. PC 가 꺼져도 강제 청산으로 계좌가 날아가지 않는다 |
| 2단계(선물)는 거래소 스톱 | 선물 비상 스톱은 **거래소에 걸려 있어** PC 가 꺼져도 작동한다. 처음부터 거래소 측 보호 주문을 고집한 이유다 |

**남는 위험은 하나다: PC 가 며칠 꺼져 있으면 추세가 꺾여도 팔지 못한다.** 그래서 꺼진 것을 빨리 알고(§4), 필요하면 휴대폰 Binance 앱으로 직접 판다.

## 2. 점검 결과 (2026-09-26 오전, 읽기만)

| 항목 | 상태 | 판단 |
|---|---|---|
| 기기 | 데스크톱(배터리 없음), 유선 랜 | ✅ |
| 전원 설정 | 전원 연결 시 절전·최대 절전 **안 함** | ✅ |
| Windows 업데이트 재시작 | 사용 시간 07~01시 → 재시작은 01~07시에만 | ✅ 21시대와 겹치지 않는다 |
| 절전 | 밤 23:48~00:35 에 절전(사용자가 재운 것으로 보인다), 아침에 깨어남 | ✅ 21:20 점검 뒤라 문제없다 |
| **비정상 종료** | **최근 7일 4회** (09-20 07:25 · 09-21 06:02 · 09-21 19:27 · 09-26 06:24) — 전원이 갑자기 끊기거나 전원 버튼을 길게 눌러 끈 기록(Kernel-Power 41) | ⚠ **확인 필요** |
| 예약 작업 11개의 로그인 조건 | 모두 "**로그인해 있을 때만** 실행" | ⚠ 갑자기 꺼진 뒤 로그인하지 않으면 21시 작업이 돌지 않는다 |
| 놓친 작업을 켤 때 실행 | 6개는 켜짐, **5개는 꺼짐**(데모 T/v2·O/v2·Elliott, 그림자, 선물 실행기 훈련) | ⚠ |
| 절전에서 깨워 실행 | 11개 모두 꺼짐 | ⚠ 21시 전에 PC 를 재우면 작업이 밀린다 |
| 공인 IP | Binance 키는 IP 제한이다. 집 공인 IP 가 바뀌면 키가 거부된다(−2015) | ⚠ 바뀌면 알림이 필요하다 |

**비정상 종료 4회가 가장 큰 문제다.** 멀티탭 스위치나 전원 버튼으로 끄시는지 확인해 주세요.
- 그렇다면 Windows 의 "시스템 종료"나 "절전"을 쓰면 된다.
- 직접 끈 적이 없다면 정전이나 전원 문제일 수 있다.

전원이 끊기면 실행 중이던 작업과 DB 쓰기가 중간에 끊긴다. 설계상 선기록·재시작 복구가 있지만, 자주 겪을 일은 아니다.

## 3. 사용자가 실행할 설정 (PowerShell, 1회)

**① 놓친 작업은 켤 때 실행, 절전 중이면 깨워서 실행** — 권장
(상주 실행기 `Demo_EW` 는 시간마다 다시 띄우므로 깨우기에서 뺀다. 매시간 PC 가 깨지 않게 하기 위해서다.)

```powershell
Get-ScheduledTask -TaskName "AutoTrading_*" | ForEach-Object { $s = $_.Settings; $s.StartWhenAvailable = $true; if ($_.TaskName -ne "AutoTrading_Demo_EW") { $s.WakeToRun = $true }; Set-ScheduledTask -TaskName $_.TaskName -Settings $s | Out-Null }
```

**② 로그인하지 않아도 실행** (선택 — 관리자 PowerShell)

"사용자가 로그온했는지 여부에 관계없이 실행, 암호 저장 안 함"(S4U)으로 바꾼다. 갑자기 꺼졌다 켜진 뒤 로그인 화면에 멈춰 있어도 21시 작업이 돈다.
- 창이 뜨지 않고 뒤에서 돈다.
- 인터넷·텔레그램·`.env` 읽기는 그대로 된다.
- **먼저 한 작업으로 시험**한 뒤 전체에 적용하는 것을 권한다.

```powershell
$p = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType S4U -RunLevel Limited
Set-ScheduledTask -TaskName "AutoTrading_Paper_Watchdog" -Principal $p
Start-ScheduledTask -TaskName "AutoTrading_Paper_Watchdog"
```

시험한 작업의 '마지막 결과'가 0 이면 나머지에도 적용한다.

```powershell
Get-ScheduledTask -TaskName "AutoTrading_*" | ForEach-Object { Set-ScheduledTask -TaskName $_.TaskName -Principal $p | Out-Null }
```

**③ 정전 뒤 자동으로 켜기** (선택): 메인보드 BIOS 의 "AC Power Recovery / Restore on AC Power Loss" 를 "Power On" 으로 바꾼다.
기종마다 메뉴 이름이 달라 사용자가 직접 확인한다. ② 와 함께 쓰면 정전 뒤에도 사람 없이 저녁 작업이 돈다.

## 4. 알아차리기 — 일일 점검에 추가한 것 (코드)

**PC 상태 한 줄** (`ops/pc_health.py`, 21:20 텔레그램):

```
PC: 작업 11개 · 실패 0 · 밀림 0 · 비정상 종료 1회(24시간) · 마지막 부팅 09-26 06:24 · 설정 남음(놓치면 켤 때 실행 꺼짐 5 · 로그인 필요 11)
```

경고(WARN)로 올리는 것:
- 예약 작업의 마지막 결과가 실패일 때 (상주 실행기의 "이미 실행 중"은 정상)
- 매일 작업이 26시간 넘게 돌지 않았을 때
- 지난 24시간 안에 비정상 종료가 있었을 때

§3 설정을 마치면 "설정 남음"이 사라진다. 조회는 PowerShell **읽기**만 한다(`Get-ScheduledTask` · 이벤트 로그 41번 · 마지막 부팅).

**공인 IP 변경 알림** (그림자 운영): 실계좌 키가 −2015 로 거부되면 "집 공인 IP 가 바뀌었을 수 있다 — Binance API 관리에서 키의 IP 목록을 확인"으로 적는다.
실거래 때도 같은 원인이면 주문이 안 나가고(fail-closed) 같은 알림이 필요하다.

## 5. 텔레그램 21:20 점검이 오지 않으면

1. PC 가 켜져 있는지, 로그인 화면에 멈춰 있지 않은지 본다.
2. 켜면 "놓치면 켤 때 실행"(§3 ①)이 밀린 작업을 돌리고 점검이 온다.
3. 며칠 못 켜는데 추세가 크게 꺾였으면(가격 급락이 이어지면), 실거래 단계에서는 **휴대폰 Binance 앱으로 직접 판다.**
   다음 실행이 거래소 잔고를 진실로 보고 맞춘다(재시작 복구).

## 6. 한계

- 집 전원·인터넷·PC 고장에는 대비가 없다. 수익이 확인된 뒤 장비·서버를 다시 검토한다(사용자 결정).
- 원격 알림은 PC 가 켜져 있어야 온다. 꺼진 동안은 "점검이 오지 않았다"는 사실이 유일한 신호다.
- 무료 외부 감시 서비스(정해진 시각에 신호가 없으면 알려 주는 방식)로 이 빈틈을 메울 수 있다. 외부 계정이 필요하고 사용자가 원할 때만 검토한다.
