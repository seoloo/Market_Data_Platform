# 29 — 새 수익 후보 비교 (2026-09-24)

사용자 결정: "대시보드 만든 뒤 새 수익 전략 연구". 절차: [BACKTEST_AND_TESTING](../current/BACKTEST_AND_TESTING.md) 후보 비교(최대 3).
**새 후보의 수익은 계산하지 않았다.** 아래 수치는 이미 판정한 결과(24 §9)에서 비용·노출만 읽은 것이다.

## 0. 출발점 — 무엇이 남았나

| 수익원 | 결과 |
|---|---|
| 단기 방향 예측 (H1·H2·H3·R1·WA·V) | 비용 전 우위 ≈ 0 → 같은 부류 제외 |
| 캐리 (K·M) · 베이시스 (B1·B2, 보류) | 실재하지만 최근 연 2~3% · B2 검정력 부족 |
| 추세 확장 (TA 알트 분산·P1 페어) | 기각 |
| **BTC·ETH 롱 추세 (T/v2) · 1.5배 (O/v1·O/v2)** | 유일하게 통과 — 전향 관찰 중 |

새 방향 예측 우위를 더 찾는 것보다, **통과한 전략이 버리고 있는 돈**을 보는 편이 기대값이 크다. 24 §9 에서 읽은 값:

| (2020-03 ~ 2026-08) | T/v2 | O/v1 |
|---|---:|---:|
| 평균 노출 (자본 대비) | **0.21** | 0.32 |
| → 평균 유휴 현금 | **약 79%** | 약 70% (선물 지갑 증거금 포함) |
| 거래 비용 부담 (연, 평균 자본 대비) | **2.4%** | **3.5%** |
| funding (연) | — | 2.5% |

비용은 가정값(현물 편도 0.15% = 수수료 0.10% + 슬리피지 0.05%, 선물 0.095%)이다. 현금 이자는 0 으로 두었다.

## 2. 권고

**1순위 — C1 유휴 현금 수익.** 가장 크고 가장 확실하다. 자본의 약 4분의 3이 평균적으로 놀고 있다.
다만 수익률이 아니라 **상품 위험**의 문제다 — 원금이 Binance 에 묶이고, 금리가 바뀌며, 급할 때 바로 못 뺄 수 있다.
연구는 (1) 보수적 금리 가정으로 T/v2·O/v1 에 더했을 때 크기, (2) 재조정 시 상환 지연이 생기면 무엇이 달라지는지,
(3) 상품 조건(유동형·상환 한도·실제 금리)을 사용자 계좌에서 확인 — 이 셋이다.

**2순위 — C2 체결 비용 절감.** 확실하지만 실측이 필요하다. BNB 수수료 할인(현물 25%·선물 10%)만으로도
비용 일부가 줄고 이것은 연구가 아니라 설정이다. 지정가 체결은 실제 호가에서만 측정할 수 있어 Phase 8 소액 실거래와 묶인다.

**3순위 — C3 금 추세.** 유일한 **새 수익원**이지만 검정력이 빠듯하고 외부 데이터가 필요하다.

셋 다 "큰 수익"을 새로 만들지는 않는다. C1·C2 는 이미 있는 전략의 새는 돈을 막고, C3 는 분산이다.
**큰 수익을 약속하는 새 방향 예측 후보는 지금 가진 데이터로는 찾지 못했다** — 그것이 지금까지 기각 10건(H1·H2·H3·R1·WA·K·M·V·TA·P1)의 결론이다.

## 3. 사용자 결정과 진행 (2026-09-24)

- 사용자 확인: Binance Simple Earn USDT 유동형 **1,000 USDT 까지 연 7.08%, 초과분 연 3.08%** (앱 화면, 2026-09-24).
- 대략 계산(24 의 이미 본 경로, 전략 규칙 그대로·유휴 현금에만 이자, 선물은 명목 절반을 증거금으로 남김):

| (2020-03 ~ 2026-08) | 이자 없음 | 3.08% | 7.08%(≤1,000)+3.08% | 보수 2% |
|---|---:|---:|---:|---:|
| T/v2 연 수익 | 23.4% | 26.4% | 26.6% | 25.3% |
| O/v1 연 수익 | 33.3% | 36.3% | 36.5% | 35.3% |
| 2025-01 ~ 2026-08 (T/v2 · O/v1) | 3.0% · 3.6% | 5.7% · 6.2% | | |

  금리를 6.5년 내내 같게 둔 가정이다(실제로는 바뀐다). 새 매매 우위의 증명이 아니다.
- 사용자 선택: **"1번 — Paper 원장에 이자 반영 줄 추가"**. 구현: `core/cash_yield.py`(순수 계산), `config/cash_yield.yaml`(날짜별 이자율, 바뀌면 줄 추가),
  대시보드 카드·전략 비교에 "현금 이자 가정" 값. **원장·전략·Paper 실행기는 바꾸지 않는다**(원장 기록 위에서 따로 계산).
- 남은 것: 실제 Earn 예치·상환 자동화는 실거래(Phase 8)와 함께 별도 승인. 이자율이 바뀌면 사용자 확인 뒤 yaml 에 새 줄.
