### 1.1 "선물부터 줄이기"는 지금 O/v2 규칙이 아니다

O/v2 는 추세가 약해지면 현물과 선물을 **같은 비율로** 함께 줄인다.
T/v2 비중 w 가 0.86 이하인 날(과거 거의 전부)에는 현물 = w, 선물 = 0.5w 다.
w 가 0.6 → 0.3 으로 줄면 현물 0.6 → 0.3, 선물 0.3 → 0.15 가 된다. 선물을 먼저 0 으로 만들지 않는다.

"선물부터 줄이기"(예: 20·60·120일 세 신호가 모두 상승일 때만 선물을 들고, 하나라도 꺾이면 선물부터 0)는 **새 변형**이다.
새 사전 등록과 판정이 필요하다. 사용자가 "처음부터 다시 연구하거나 운영 중인 전략을 바꾸자는 뜻은 아니"라고 했으므로 **지금은 만들지 않는다.**
O/v2 관찰(10/23·10/24) 뒤 필요하면 후보로 올린다.

### 4.1 결론: "다리 스톱" 방식으로 공백 없이 교체할 수 있다

매일 교체 순서 (O/v2 실행기 설계안):
1. 새 가격에 **수량 지정 reduce-only 스톱(다리)**, 수량 = 현재 포지션
2. 옛 closePosition 스톱 취소
3. 새 가격에 closePosition 스톱
4. 다리 스톱 취소

어느 순간에도 스톱이 하나 이상 걸려 있다. 끝나면 다시 closePosition 하나만 남는다.
closePosition 을 기본으로 두는 이유는 포지션 크기가 바뀌어도 전체를 닫고, **포지션이 0 이 되면 거래소가 알아서 정리**하기 때문이다(26 §6 실측).
수량 스톱은 포지션이 커지면 일부만 보호하고 평탄해도 남는다. 그래서 교체하는 몇 초 동안만 쓴다.

**대안:** 공백 약 0.1초를 받아들이고 "취소 → 새 closePosition" 만 쓸 수도 있다. TRADING_CORE 의 보호 공백 상한(5초) 안이다.
다만 취소 뒤 새 스톱이 거부되면(예: 그 사이 급락으로 즉시 발동 −2021) 보호가 빈다. 다리 방식은 그 경우에도 다리 스톱이 남는다. **다리 방식을 권한다.**

### 4.2 이 측정이 확인하지 않은 것

- 다리 스톱과 closePosition 스톱이 **같은 순간 둘 다 발동**하는 경우. reduce-only 라 반대 포지션은 생기지 않을 것이다. 발동 훈련으로 따로 확인해야 한다.
- 실계좌(메인넷)의 같은 규칙. 테스트넷과 같다고 가정한다. 2단계 첫날 읽기 조회로 확인한다.

**실계좌 주문 경로는 만들지 않았다.**

### 6.1 하루 순서

1. 정합성 복구. HALTED 면 그날 주문 없음. 밤사이 발동한 스톱을 보고한다.
2. 노출 증가 허용 = 복구 RUNNING · 긴급 정지 꺼짐 · 그날 손실 < 2%. 막혀도 **줄이기와 보호는 계속**한다.
3. 목표 수량 맞추기: 줄이기는 reduce-only(0 이면 CLOSE), 늘리기는 OPEN. 최소 주문 금액 미달인 늘리기는 건너뛴다.
4. 스톱 교체(다리 방식):
   - 다리를 못 걸면 옛 스톱을 유지한다.
   - 새 closePosition 을 못 걸면 다리가 보호한다.
   - 스톱이 하나도 없으면 3회 재시도, 그래도 실패하면 비상 청산·HALTED.
5. 마지막 확인: 롱 포지션마다 거래소 스톱이 있어야 한다.

### 6.2 시험 (가짜 거래소, 15건)

| 상황 | 결과 |
|---|---|
| 첫날 진입 | 포지션 + closePosition 스톱 하나 (다리 안 남음) |
| 사흘 연속 스톱 가격 교체 | 매번 새 가격 하나. **교체 중 스톱 0 인 순간 0회** (취소마다 감시) |
| 같은 가격 | 주문 없이 유지 |
| 줄이기 → 청산 | REDUCE → CLOSE, 스톱 정리 |
| 밤사이 −22% 로 스톱 발동 | 보고서에 발동 기록. 그날 손실 2% 면 재진입 안 함 → 다음 날 허용되면 추세대로 재진입 + 새 스톱 |
| 긴급 정지 스위치 | 늘리기 금지, 줄이기 허용, 스톱 갱신 계속, 상태 DEGRADED |
| 최소 주문 금액 미달 늘리기 | 건너뛰고 기록 |
| 다리 스톱 네트워크 오류 | 옛 스톱 유지(옛 가격이라도 보호) → 다음 날 조회로 해소 뒤 교체 |
