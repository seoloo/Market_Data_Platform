# 232 — AG + 숏, 숏 차단을 숏 자기 손익 기준으로 (설명용 후향, 사전 고정)

상태: **계산 전 고정**. 이 절(§1 ~ §6)은 결과를 보기 전에 커밋한다.

## 1. 왜 다시 하나

Codex 의 AG 숏 배율 연구([교정판](AG_SHORT_LEVERAGE_CORRECTION_20261014.md))는 AG3 · AG4 롱에
고정 RSI7 숏을 붙였지만 **숏 체결 0 건**이었다. 숏 차단 규칙이 *롱 · 숏 · 현금을 합친 계좌*가
고점의 75% 이하가 되면 숏 신규 진입을 **영구** 막는 방식이라, 2020-08 ~ 09 롱 손실로 첫 숏 신호
(2020-09-13) 전에 숏이 꺼졌다. 그래서 'AG 만' 과 'AG + 숏' 이 소수점까지 같았다.

이어진 [롱↔숏 전환 연구](DIRECTION_SWITCH_RESULTS_20261014.md)는 코인 롱을 AG 가 아니라 **T/v2** 로
바꿔 계산했다. 사용자가 원한 'AG 계열 + 숏' 비교는 아직 없다.

## 2. 바꾸는 것 — 숏 차단 규칙 하나

엔진·자료·다른 숫자는 Codex 교정판 그대로 쓴다(코드 `c9f99b2` 의
`src/auto_trading/research/ag_short_leverage_20261013.py`, 입력 ID
`96dc97701d133ab3f4ec261534ed55c4129fd09507b535b884ff0e1c16107235`, 2020-06-01 ~ 2026-08-31,
초기 10,000 USDT, 4 민감도 BASE · COST2 · THIN · ACK5). 엔진 파일은 고치지 않는다 —
새 스크립트가 `Account` 의 `short_halted` 만 바꾼 하위 클래스로 같은 `simulate` 를 돌린다.

| 숏 차단 | 내용 |
|---|---|
| 원래 (Codex) | 계좌 전체 equity ≤ 계좌 고점 × 0.75 → 숏 영구 차단 |
| **OWN (본 판정)** | **닫힌 숏 거래의 누적 순손익**이 자기 고점(시작 0)에서 **계좌 고점 equity × 2.5%** 이상 빠지면 숏 영구 차단. 2.5% = 숏 증거금 한도(equity 10%)의 25% — 원래 '25%' 를 숏 자기 지갑에 적용한 것 |
| NONE (참고 줄) | 별도 숏 영구 차단 없음 |

둘 다 그대로 남는 것: 숏 4 연패 → 240 분 쉼, 숏 청산 뒤 60 분 쉼, 하루 손실 2% 신규 금지,
최초 자본 30% 이하 계좌 정지, 숏 3% 손절 · 48 시간, 증거금 10% · 거래 위험 1%, 지정가 · 부분 체결,
그리고 **롱 목표가 0 보다 큰 코인에는 숏을 내지 않는 규칙**(롱이 쉬는 코인에만 숏).
롱 쪽(AG3 · AG4 목표, 배율, 체결)은 한 줄도 바꾸지 않는다.

## 4. 판정 (OWN 기준, 설명용)

AG3 · AG4 각각, SHORT_1X · SHORT_MAX 각각에 대해 `(AG+숏 순손익) − (AG 만 순손익)` 을 본다.

* BASE · COST2 두 민감도에서 체결된 숏이 합쳐 30 건 미만 → **표본 부족**.
* 두 민감도 모두 차이 > 0 → **후향 기여 유리**, 모두 ≤ 0 → **불리**, 엇갈리면 **혼재**.
* MDD 변화, 숏 자체 순손익, 해마다 숏 손익, THIN · ACK5 결과, NONE 줄은 모두 함께 보고한다.
