# 66 — BTC 옵션 변동성 보험료 + 선물 헤지: Phase 0 타당성 점검

작성: 2026-09-25 · 상태: **Binance 옵션 과거 호가 소표본 실측, 전체 품질·실행 위험 게이트 미충족, 전략 사전등록 전 보류**. 수익률 계산·백테스트·주문·계정 설정 변경 없음.

후속: [67 만기·행사가별 호가 상태와 저장량 소표본 감사](67-btc-option-quote-quality-sample.md). 아래의 “다음 작업”은 이 문서 작성 시점의 기록이며, 최신 인계는 67과 `PROGRESS.md`를 따른다.

## 1. 질문과 연구 경계

BTC 옵션 구매자가 미래 급변을 대비해 지불하는 가격이, 실제 급변 손실과 옵션·선물 거래비용을 뺀 뒤에도 남는가? 경제적 수익원은 **변동성 위험을 인수하는 대가**다. 가격 추세(T/O), 몇 시간 방향 신호(H/WA/FB/LQ/MD), 펀딩 캐리(K/M)와 다르다. 문헌의 BTC 변동성 위험 프리미엄 관찰은 이 계좌의 거래 가능 수익을 보장하지 않는다.

- 대상 연구안: BTC의 정해진 만기·행사가에서 **손실이 구조적으로 제한된 옵션 매도 조합**을 우선 검토하고, 남는 방향 노출을 BTCUSDT 무기한으로 헤지한다. 구체 만기·행사가·헤지 간격은 성과를 보기 전에 사전등록해야 한다.
- 옵션 없이 BTCUSDT 선물만 거래하면 변동성 보험료를 직접 받지 못한다. 옵션 지표로 선물 방향을 정하는 연구는 별도 가설이다.
- 이번 점검은 데이터·비용·위험의 **실행 가능성**만 본다. 기존 Paper/그림자/데모·D22·Elliott에 영향을 주지 않는다.

## 2. 로컬 자료와 공식 API 확인

저장소 `data/external/`과 `src/`, `scripts/`, `docs/research/`에서 옵션 원자료·옵션 전용 적재/백테스트 경로를 찾지 못했다. 현재 DB의 BTC 가격·펀딩만으로 옵션 진입가·청산가·헤지 비용을 재현할 수 없다. 과거 거래 가능 호가를 옵션 이론가나 중간가격으로 대체할 수 없다.

Binance 공식 [Options Market Data API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-options/api/rest-api/market-data)는 심볼별 `klines`, 현재 `mark`·그릭스, 현재 `depth`, 최근 체결, 만기 행사 기록을 문서화한다. `klines`에는 체결 OHLCV가 있지만 당시 최우선 매수·매도 호가와 수량은 없다. 현재 `exchangeInfo`는 당시 상장·폐지 심볼 전체의 시점별 목록을 보장하지 않는다. 이 문서들만으로 다년간의 Binance 옵션 **시점별 거래 가능 호가**가 확보됐다고 판정할 수 없다. 공식 [Binance public-data 도구](https://github.com/binance/binance-public-data/blob/master/python/README.md)는 다운로드 시장을 spot·USD-M·COIN-M으로 설명하며 옵션 아카이브를 열거하지 않는다. 실제 과거 만기 심볼의 API 반환·보존 기간은 별도 실측이 필요하다.

Deribit [공식 역사 API 안내](https://statics.deribit.com/files/DeribitInstitutionalSetupGuide.pdf)는 오래된 옵션 계약·체결 조회를 설명한다. Deribit이 공개한 [2024년 약 6개월의 시간별 옵션 스냅샷](https://insights.deribit.com/education/option-backtest-selling-weekend-vol/)은 연구용 대안이다. 그러나 **Deribit의 호가·체결을 Binance에서 같은 가격으로 거래할 수 있었다고 가정할 수 없다**. 해당 자료만으로 Binance 실행 성과를 판정하지 않는다. 더 긴 호가 이력은 데이터 공급자 계약·비용·라이선스를 확인해야 한다.

### 공개 API 소표본 실측 (2026-09-25, 읽기 전용)

`eapi.binance.com`의 공개 응답을 직접 대조했다. 요청은 공개 시장 데이터 GET뿐이며 키·계정 조회·다운로드/저장은 없었다.

| 조회 | 관측 |
|---|---|
| `/eapi/v1/exchangeInfo` | 현재 거래 중 BTC 옵션 664개. 그중 `BTC-261225-85000-C` 확인 |
| `/eapi/v1/klines` 현재 심볼 `BTC-261225-85000-C`, 2026-09-18~25 일봉 | 8개 반환 |
| `/eapi/v1/exerciseHistory` 2026-09-18 | 5개 반환, 첫 심볼 `BTC-260918-84000-P` |
| `/eapi/v1/klines` **지난주 만기 심볼** `BTC-260918-84000-P`, 만기 전 일봉 | HTTP 오류 본문 `code -1121`: `The symbol is either in PENDING_TRADING status or does not exist.` |
| `/eapi/v1/exerciseHistory` 2025-09-26·2024-09-27·2023-09-29 각각 `limit=5` | 각 0개 반환. **API 보존 정책·기간은 이 소표본으로 단정 불가** |

따라서 공식 캔들 API가 **현재 심볼에는 작동하지만, 확인한 만기 심볼의 과거 캔들은 제공하지 않는다**. 더구나 캔들이 반환되더라도 bid/ask 호가 이력은 아니다.

### 라이선스 자료 감사 (2026-09-25, 읽기 전용)

별도 공급처 [Tardis Binance European Options 안내](https://docs.tardis.dev/historical-data-details/binance-european-options)는 전 종목 수집 시작을 **2023-06-15**로 명시한다. 공개 [거래소 메타데이터](https://api.tardis.dev/v1/exchanges/binance-european-options)를 직접 조회한 결과, 만기된 BTC 옵션도 심볼별 `availableSince`/`availableTo`와 함께 등재되어 있었다. 예를 들어 `BTC-250328-50000-C`는 2024-07-05~2025-03-29로 표기되고, `incremental_book_L2`, `quotes`, `book_snapshot_5`, `book_snapshot_25`, `options_chain`, `book_ticker`, `trades`가 데이터 유형으로 열거된다. 2026-09-25 조회 시 BTC 심볼 항목은 43,833개였으나, 이는 **계약 메타데이터 수**이지 유효 호가 수나 독립 거래 표본 수가 아니다.

[CSV 스키마](https://docs.tardis.dev/downloadable-csv-files/data-types)에 따르면 `options_chain`에는 시각·만기·행사가·bid/ask 가격과 각각의 수량, `quotes`에는 최우선 양방향 호가·수량, `incremental_book_L2`에는 호가 레벨·수량·스냅샷 구분이 있다. 따라서 **Binance에서 관측된 과거 거래 가능 호가를 연구할 자료 경로 자체는 확인**됐다. 단, 데이터 유형 등재만으로 매 시각 양쪽 호가가 존재하거나 특정 수량을 체결할 수 있었다고 볼 수 없다. 실제 파일의 빈 호가·스프레드·갱신 지연·수량·누락 구간을 확인해야 한다.

공급처 안내에 따르면 구형 `depth100` 자료는 2025-12-17까지, 신형 `depth20`과 독립 `bookTicker` 피드는 그날부터 기록됐다. 이 날짜 전후의 정규화 호가를 동일한 품질의 연속 계열로 취급하지 않는다. 메타데이터에는 2025-12-15~17 API 변경에 따른 누락과 2026-08-13 짧은 연결 중단이 사고로 기록돼 있다. 만기 직전·급변 시점에 결측이 집중되는지 별도로 감사해야 한다.

공급처는 매월 1일 CSV와 [원시 HTTP API](https://docs.tardis.dev/api/http-api-reference)의 해당 날짜 자료를 키 없이 제공한다고 설명한다. 안내된 `2024-08-01/BTC-250328-50000-C` CSV 예시 파일은 이 환경에서 HEAD 404·범위 GET 403으로 열리지 않았다. **CSV 접근 실패의 원인은 미확인**이다. 그러나 원시 HTTP API에서는 만기 계약의 실제 행을 읽을 수 있었다. 아래 소표본 점검은 이 무료 API만 사용했다.

### 무료 원시 API 소표본: 호가 존재와 품질의 구분

만기된 BTC 콜·풋 한 쌍씩을 2023·2024·2025·2026년 월 1일에서 골라, 각각 **00:00·06:00·12:00·18:00 UTC의 1분**만 조회했다. 2025-12-17 이전에는 `ticker`의 `bo/ao/bq/aq`, 이후에는 `bookTicker`의 `b/a/B/A`를 사용했다. raw 필터 심볼도 구형은 대문자, 신형은 소문자여야 응답이 왔다. 유효 양방향 행은 bid·ask·양쪽 수량이 모두 양수이고 ask > bid인 경우로 셌다. 다음은 시장 전체가 아니라 **8개 계약·16개의 고정 1분 구간**에 대한 접근/품질 점검이다.

| 날짜·만기 | 행사가(콜+풋) | 호가 행 / 유효 양방향 행 | 한 1분 구간의 콜·풋 중위 스프레드* |
|---|---:|---:|---:|
| 2023-08-01 · 08-04 | 30,000 | 480 / 480 | 06:00: 690 / 1,984 bps |
| 2024-08-01 · 08-02 | 60,000 | 300 / 279 | 12:00: 3,919 / 2,222 bps |
| 2025-12-01 · 12-05 | 85,000 | 479 / 474 | 06:00: 95 / 32 bps |
| 2026-09-01 · 09-04 | 80,000 | 1,396 / 1,383 | 12:00: 165 / 3,269 bps |

\* `10,000 × (ask−bid) / ((ask+bid)/2)`: **옵션 프리미엄 대비 표시 스프레드**이며 BTC 명목 대비 비용이나 전략 왕복 손익이 아니다. 계약별 moneyness·잔존 만기·시장 국면이 달라 연도 간 수익성 비교 자료가 아니다. 선택한 시각/계약은 결과 최적화용이 아니며, 전체 기간의 대표 표본이라고 주장하지 않는다.

원시 `depth100`에서 2023·2025년 선택 계약의 가격·수량 레벨을, `depth20`에서 2026년 선택 계약의 가격·수량 레벨을 실제 확인했다. 반면 2024-08-01 12:00의 선택 콜은 `ticker` 60행이 모두 **동일 bid/ask·수량**이고 24시간 거래량 필드도 0이었다. 그 1분의 `depth100` 응답은 0행이었다. 60행을 60번의 새 거래 가능 호가나 독립 표본으로 세면 안 된다. 가격만 있고 한쪽 수량이 0인 행, 아예 0행인 계약·시각도 관측됐다. 자료 접근은 확인됐지만 **호가의 신선도·실제 체결 깊이·전체 결측률은 미검증**이다.

[공개 가격표](https://tardis.dev/)는 Options/Solo를 월 $700로 표시하지만, [구독 조건](https://docs.tardis.dev/faq/billing-and-subscriptions)에 따르면 Solo는 **CSV 접근만** 제공하며 월 결제는 과거 4개월, 분기 결제는 12개월, 연 결제는 4년 이력이다. 따라서 2023~2026 전체 기간을 확보하려면 표시 월액만 지불하는 것으로는 부족하고 **연 결제 범위의 견적**이 필요하다. Binance BTC만의 별도 판매·계약별 파일 비용·세금·라이선스·총 저장량은 미확정이다. 전체 옵션 채널의 1분 응답조차 수십 MB였으므로 전체 체인 대량 적재는 저장 공간을 고려해 금지하고, 필요한 계약·시각의 파일 크기를 먼저 측정한다. 결제·계정 생성·로컬 원자료 저장은 하지 않았다.

## 3. 비용·증거금·손실 경로

Binance [옵션 매도 안내](https://www.binance.com/en/support/faq/detail/1ceb77f837344e3085ecf98d9a6a8097)에 따르면 BTC·ETH 옵션 매도에는 계정의 long/short 모드가 필요하며, 일반 계정은 옵션·선물 간 포트폴리오 증거금 상계를 제공하지 않는다. 옵션 매도 다리에는 별도의 초기·유지 증거금이 붙고 손실 확대 시 강제청산될 수 있다. 옵션의 먼 행사가 매수 다리나 선물 헤지가 있어도 **거래소가 이를 하나의 저위험 포지션으로 증거금 계산해 준다고 가정하면 안 된다**. 지역·계정별 상품 이용 가능 여부는 확인 전까지 미정이다.

[옵션 수수료 안내](https://www.binance.com/en/support/faq/detail/5326e5de61c34fed98abe28d2f175a23)는 거래·행사·강제청산 수수료를 각각 설명한다. 할인·프로모션·VIP는 계약과 시점마다 달라 실측 계정 요율을 사용해야 한다. 연구의 비용에는 옵션 각 다리의 **실제 bid/ask**, 다리별 수수료, 행사료, 선물 헤지의 수수료·호가 충격·펀딩·재조정 횟수, 강제청산 위험을 포함한다. `mark`/IV 중간값 체결 또는 모든 헤지가 시장가 충격 없이 가능하다는 가정은 금지한다.

선물 델타 헤지는 작은 가격 변화의 방향 노출만 줄인다. 급변 때의 감마 손실·옵션 유동성 소멸·헤지 지연은 남는다. 무한 손실 가능한 무보호 옵션 매도는 이 프로젝트의 거래당 계좌 위험 1%와 맞지 않는다. 손실 제한 옵션 조합을 쓰더라도 다리별 부분 체결과 증거금 증가 경로를 별도로 검증해야 한다. 현 `TRADING_CORE`의 보호주문·1% 위험·증거금 10%·일 손실 2%·계좌 DD 30% 규칙을 옵션까지 어떻게 일관되게 적용할지 아직 정의되지 않았다. 연구 결과를 이유로 한도나 보호요건을 완화하지 않는다.

## 4. 사전등록 가능성 게이트

아래가 충족되기 전에는 매매 규칙을 동결하거나 Train 손익을 열지 않는다.

1. **데이터:** 만기된 계약을 포함한 시점별 옵션 상장 목록, 의사결정 시각의 양방향 호가·수량, 체결/정산 가격, 거래소별 출처·타임스탬프·결측률. 대상 기간과 각 만기별 커버리지 보고. 자료를 얻지 못하면 `DATA_INSUFFICIENT`.
2. **체결:** 같은 시각·같은 수량의 옵션 여러 다리와 BTC 선물 헤지가 실제로 실행 가능한지, 최악 다리 부분 체결·취소·청산 순서까지 모형화. Binance 아닌 거래소 자료는 Binance 호가 검증 또는 그 거래소에서만 가능한 전략으로 분리.
3. **위험:** 계약별 최대 만기 손실뿐 아니라 만기 전 증거금·강제청산·갭·호가 소멸을 계좌 경로로 계산. 현재 위험 원칙과 충돌 시 설계 승인 전까지 종료.
4. **검정력:** 독립 단위는 옵션 다리/일별 관측치가 아니라 포지션 또는 겹치지 않는 만기·위험 사건이다. 손절·헤지·거래비용을 포함한 거래당 손익 SD와 실제 거래 수로 [현행 80% 검정력 게이트](../current/BACKTEST_AND_TESTING.md)를 계산한다. Binance BTC 주간 옵션은 [2022-10-20 상장](https://www.binance.com/en/support/announcement/detail/227969d0a422441f8c391dc67d08dfb1) 이후라, 달력상 주 수가 많아도 독립적인 시장 국면은 훨씬 적을 수 있다. 이전 연구에서 본 2024~2026년을 자동으로 미열람 OOS라 부르지 않는다.
5. **판정 기준:** 순손익의 신뢰하한·T/v2 대비 증분·비용 2배·급등락 손실·청산 0회를 성과 확인 전에 고정한다. 반복 탐색 없이 한 구조만 검증한다.

## 5. 이번 판정과 다음 작업

**판정: 만기 호가 소표본 실측 완료, Phase 0 보류 유지.** 옵션 프리미엄이라는 수익원은 이전 기각 연구와 독립적이다. Tardis의 무료 원시 API에서 2023~2026년 만기 계약의 실제 양방향 호가·수량과 일부 호가창 깊이를 확인했다. 이는 데이터 경로의 존재를 입증하지만, 넓은 스프레드·반복된 구형 티커·빈 호가 구간이 있어 거래 가능한 전체 표본 수를 알려주지 않는다. 로컬에는 원자료가 없고 전체 커버리지·체결 비용·검정력은 미계산이다. 일반 계정의 증거금 상계 부재도 자본 효율과 청산 위험에 직접 영향을 준다. 수익 가능성을 숫자로 제시하거나 전략을 사전등록할 근거는 아직 없다.

다음은 무료 월 1일 자료 안에서 **행사가·만기·시장 국면을 나눈 대표성 감사**다. 반복 티커 대신 호가 변경 시각을 기준으로 신선도·양방향 수량·스프레드·빈 구간을 측정하고, 계약 규격·정산 및 선물 헤지 자료와 시각을 맞춘다. 이는 체결 가능성의 사전 점검일 뿐 손익 탐색이 아니다. 그 결과로 필요한 기간·저장량·연간 라이선스 비용을 산정한 뒤에만 구매 여부를 사용자와 결정한다. 자료 접근이 불가능하거나 품질이 부족하면 옵션 매도 모델은 중단하고, 이미 논의한 **ETF 자금 흐름을 입력으로 쓰는 BTC 선물** 등 선물 전용 후보를 별도로 비교한다. 이 문서의 보류는 옵션 프리미엄이 없다는 기각 판정이 아니다.
