# 28 — BTC 다중 시간대 종합판단 전략 요구사항 (D22)

상태: **사용자 요구사항 확정 · 수치 설계 미확정**  
확정일: 2026-09-22  
우선순위: 이 문서는 기존 H1~H3·R1 전략 정의보다 우선한다. 기존 결과는 삭제하지 않고
기각된 연구 이력으로 보존한다.

## 1. 최종 목적과 거래 대상

최종 목적은 **BTCUSDT 무기한선물을 자동으로 분석·진입·청산하여 비용 후 반복 가능한
수익을 내는 시스템**이다. 방향 예측률 자체가 목표가 아니며, 수수료·슬리피지·funding과
손실 한도를 반영한 실현 가능한 수익성이 기준이다.

- 실제 주문 심볼: **BTCUSDT 한 종목**
- 거래소/모드: Binance USD-M, One-way, Isolated
- 다른 주요 코인: BTC 판단의 시장 맥락으로 사용할 수 있으나 직접 주문하지 않는다.
  참조 심볼 목록과 기여 방식은 성과 열람 전에 별도 사전등록한다.
- 실거래는 기존 Phase 게이트와 사용자 승인을 통과하기 전까지 금지한다.

## 2. 분석 시간대와 역할

| 관점 | 시간대 | 역할 |
|---|---|---|
| 단기 | 15m · 30m · 1h · 2h · 4h | 진입 타이밍, 단기 추세, 과열·되돌림, 패턴 발생 |
| 중기 | 12h · 1d | 현재 포지션의 주된 방향과 시장 구조 |
| 장기 | 1d · 1w | 큰 추세와 역추세 거래 제한 |

1일봉은 중기와 장기를 연결하는 **하나의 공통 입력**이다. 같은 값을 두 번 더해 점수를
중복시키지 않는다. 1m·5m 데이터는 체결 시뮬레이션과 상위 봉 생성에 사용할 수 있지만,
D22 방향 점수의 정식 시간대는 위 8개다.

모든 계산은 마감된 봉만 사용한다. 예를 들어 12시간봉이 형성 중이면 직전 마감 12시간봉까지만
보며, 주봉도 마감되기 전에는 새 값으로 바꾸지 않는다.

## 3. 분석 요소

### 3.1 핵심 추세 — MA/EMA

MA와 EMA를 방향 판단의 중심축으로 둔다. 가격의 평균선 위·아래 위치, 평균선 기울기,
단기·중기·장기 평균선 배열과 교차를 시간대별로 계산한다. 정확한 기간과 점수는 Phase 0의
후속 수치 명세에서 고정하며, 결과를 본 뒤 유리한 기간만 고르지 않는다.

### 3.2 보조지표

- RSI: 과매수·과매도, 되돌림과 다이버전스
- MACD: 추세 모멘텀, signal/histogram 전환
- 일목균형표: 구름대 위치, 전환선·기준선, 선행·후행 관계
- 피보나치: 확정 스윙 기반 되돌림·확장 구간
- 볼린저밴드: 변동성 수축·확장과 밴드 위치

서로 같은 정보를 반복하는 지표는 무조건 합산하지 않는다. 각 지표는 `추세`, `모멘텀`,
`변동성`, `구조` 계열에 배치하고, 같은 계열 안에서 정규화·중복 제한을 적용한다.

### 3.3 차트 패턴과 다이버전스

- 컵앤핸들
- 상승 다이버전스
- 하락 다이버전스
- 확정된 스윙의 HH/HL/LH/LL, 지지·저항

패턴은 사람이 보고 이름 붙이는 방식이 아니라 코드로 재현 가능한 규칙이어야 한다.
우측 봉을 기다려야 확정되는 패턴은 `confirmed_at_ms`를 기록하며, 확정 전 시점의 판단에
소급 적용하지 않는다.

### 3.4 Elliott Wave

- **4시간봉 이상에서만** 계산한다: 4h · 12h · 1d · 1w.
- 단독으로 진입을 만들지 않고, 다른 지표가 만든 방향의 **최종 구조 확인**에 사용한다.
- 복수 카운트가 가능하면 하나를 정답으로 단정하지 않고 시나리오와 신뢰도를 함께 기록한다.
- 확정 피벗만 사용하고, 미래 봉으로 과거 파동 번호가 조용히 바뀌는 구현은 금지한다.
- 최종 역할(확인 가산·반대 시 감점·진입 veto)과 기여 상한은 구현 전에 고정한다.

## 4. 점수 구조

각 평가 시점에 다음을 독립적으로 기록한다.

```text
short_term_score   = 15m·30m·1h·2h·4h 근거
medium_term_score  = 12h·1d 근거
long_term_score    = 1d·1w 근거
technical_long_score
technical_short_score
macro_news_score
confidence_score
final_long_score
final_short_score
```

MA/EMA가 추세의 기반을 만들고 보조지표·패턴이 확인하거나 감점한다. Elliott는 4시간 이상
구조를 마지막으로 확인한다. 시간대가 충돌하면 억지로 한 방향을 선택하지 않고 신뢰도를
낮추거나 `NO_TRADE`로 처리한다.

정확한 가중치, 진입 임계값, 시간대 충돌 규칙은 **아직 확정하지 않았다.** 기존 70점과
기존 5개 지표 가중치는 D22에 자동 승계하지 않는다. 수치표를 Phase 0에서 먼저 작성하고
TRAIN 성과를 보기 전에 버전으로 고정해야 한다.

## 5. 진입·청산·재평가

```text
FLAT
  ├─ LONG 점수와 모든 게이트 충족  → LONG 진입
  ├─ SHORT 점수와 모든 게이트 충족 → SHORT 진입
  └─ 불충분·충돌·뉴스 위험          → 대기

LONG 보유 중 short_score > long_score → LONG 청산
SHORT 보유 중 long_score > short_score → SHORT 청산
```

- 반대 점수 역전은 손익과 관계없이 청산 사유다.
- 청산과 반대 진입을 한 주문으로 처리하지 않는다.
- 신호 청산 후 **60분 동안 신규 진입을 금지**한다.
- 60분이 지난 뒤 첫 평가 가능한 마감 15분봉에서 전체 점수를 처음부터 다시 계산한다.
- 재평가 결과가 충분하면 LONG/SHORT에 진입하고, 아니면 계속 FLAT으로 대기한다.
- 최대 보유시간은 두지 않는다. 다만 이 시스템은 장기투자 시스템이 아니며 점수 역전,
  손절, 리스크 한도와 보호주문으로 포지션을 관리한다.

## 6. 뉴스·거시 요인

대상 예시:

- CPI·PCE·고용지표
- 기준금리·FOMC 결정과 발언
- 유동성·규제·거래소·ETF 등 BTC에 직접 영향을 주는 주요 뉴스

뉴스/거시 계층은 다음 세 결과를 낼 수 있다.

1. 제한된 범위의 LONG/SHORT 방향 기여
2. 불확실성 증가에 따른 점수·포지션 크기 축소
3. 이벤트 전후 `NO_TRADE` veto

기사의 게시시각·수집시각·원문 해시·출처를 보존한다. 수정 기사나 사후 요약을 과거 판단에
사용하지 않는다. 과거 기사 분석에 현재 지식을 가진 모델을 사용한 결과는 진짜
out-of-sample 증거로 인정하지 않는다.

## 7. JEV 도입 위치

JEV는 다음 후보 역할로 설계에 포함한다.

- 뉴스·거시 입력의 구조화 분석기
- 기술적 LONG/SHORT 근거를 다시 검토하는 보조 판단기
- 상충 신호가 클 때 `NO_TRADE`를 권고하는 검증 계층

정확한 JEV 제품·모델·입출력 계약은 아직 미확정이다. 어떤 형태든 직접 주문 권한은 없으며
최종 Strategy → Risk Engine 경로를 우회할 수 없다. 사용 시 모델 버전, 프롬프트 버전,
입력 해시와 원출력을 기록해야 한다.

## 8. 변하지 않는 리스크 규칙

- 거래당 최대 계획손실: equity 1%
- 일일 손실 한도: equity 2%
- 최대 누적 낙폭: 10%
- 증거금 상한: equity 10%
- 레버리지 설계 상한: 10x
- 보호 STOP_MARKET 주문은 거래소에 등록
- 데이터 결측·stale·모델 실패 시 신규 진입 거부
- Risk Engine은 청산을 막을 수 없음

기술지표와 AI 분석이 많아져도 이 한도는 느슨하게 바꾸지 않는다.

## 9. 구현 전 확정해야 할 수치

1. MA/EMA 기간과 배열 정의
2. 각 지표의 파라미터와 계열 내 정규화 방식
3. 단기·중기·장기 블록 가중치 및 1d 중복 방지 공식
4. LONG/SHORT 진입 임계값과 최소 점수 차이
5. Elliott 최종 확인의 기여 상한·veto 조건
6. 컵앤핸들·다이버전스의 결정론적 정의
7. 뉴스 방향 점수 상한과 이벤트별 NO_TRADE 시간
8. JEV의 정확한 정체, 입출력 스키마와 역할
9. 참조할 주요 코인 목록과 BTC 점수 반영 방식

이 값은 구현 전에 문서·config·테스트 기대값으로 동시에 고정한다. 성과를 본 뒤 바꾸면
새 전략 버전으로 분리하고 다시 TRAIN/VALIDATION/TEST 절차를 밟는다.

## 10. 기존 연구와의 관계

H1·H2·H3·R1 기각은 유효한 연구 기록이다. D22는 그 결과를 성공으로 뒤집지 않는다.
다만 D22는 사용자가 새로 확정한 종합판단 시스템이므로 기존 H1의 5개 지표 전략과는 다른
전략 버전이다. 새 전략은 데이터·feature·백테스트 게이트를 다시 통과해야 한다.
