## 연구 절차

가설/경제적 원인 → 명확한 진입·청산·손절/TP 규칙 → 자유도·표본/검정력 검토 → 사전등록 → TRAIN → VALIDATION → 최종 OOS → 판정.
후보는 한 번에 최대 3개, 사용자가 선택한 하나만 구현·실험한다.
후보 표에는 전략명, 가설/시장 논리, 노리는 비효율, 데이터, 진입/청산/stop, 예상 보유/빈도, 비용 취약성, 자유도, 실패 원인, 기존 기각 연구와 차이, 검증·사전 기각 기준, 정보 중복 가능성, **아래 검정력 판정**을 포함한다.
`기존 기각 연구와 차이`는 지표 목록이 아니라 **경제적 수익원의 차이**로 쓴다. 지표만 바꾼 후보는 같은 연구의 재시도다.
우선 비교할 후보 중 하나는 HTF 방향 + 변동성 수축 + LTF 구조 돌파다. 이는 효과가 확인된 전략이나 구현 승인이 아니다.
성과 열람 뒤 RSI/EMA 임계값 미세 탐색, 조건 추가, 신호 반전, 기각 전략 이름 변경, OOS 재튜닝을 금지한다.
관찰 → 새 가설 → 새 버전 → 사전등록 → 별도 OOS가 순서다. 상관을 인과로 주장하지 않는다.
충분한 기준을 통과한 하나는 V1 Candidate로 동결하고 추가 탐색을 멈춘다. 이후 아래 Phase 순서의 실행/Paper/Forward/Testnet/소액 검증으로 전환한다.

## 검정력 게이트 — 사전등록 전 필수

**가용 표본으로 판정할 수 없는 가설은 사전등록하지 않는다.** 신호를 만들기 전에 계산한다.

H1은 선별을 끝낸 뒤, H2는 재현 검정을 끝낸 뒤에야 판정 불가였음을 알았다. 계산 자체는
몇 초면 끝난다. 이 게이트는 그 순서를 강제한다.

### 계산

판정 기준이 `관측평균 − z·SE > 비용`일 때, 참효과 `e`를 확률 `1−β`로 잡아내려면

```
n >= ((z + z_β) · SD / (e − 비용))²      Δ = e − 비용
```

| 기호 | 값 / 의미 |
|---|---|
| z | 2.0 — 이 프로젝트의 `평균 − 2SE` 관행 |
| 1−β | **0.80 기본.** 사전등록에 명시하고 결과를 본 뒤 낮추지 않는다 |
| SD | 관측 단위 **하나**의 표준편차. 측정값만 쓰고 추정치면 그렇다고 적는다 |
| e | 가정하는 효과 크기. 근거 없이 크게 잡으면 게이트가 무력해진다 |
| 비용 | 해당 연구의 왕복 비용. 낙관하지 않는다 |

도구: `src/auto_trading/backtest/power.py` (`plan`, `required_samples`,
`detectable_effect_bps`, `achieved_power`).

### 검정력 0.80을 기본값으로 두는 이유

`n = (2·SD/Δ)²`는 archive/research/22 §6이 쓰던 식이고 **검정력이 정확히 50%다.**
참으로 그만한 효과가 있어도 절반은 놓친다. 같은 기준에서 80%를 얻으려면 표본이 2.02배,
90%는 2.69배 필요하다.

실제 피해 사례가 있다. H2 재현 검정은 TRAIN 효과 34.57bps · 비용 18bps · SD 122.8bps에서
**443개가 필요한데 189개로 사전등록했다.** 그 설계의 검정력은 44%였고, 결과는 예정대로
"0인지 양수인지 구분 불가"였다. 데이터가 아니라 설계가 실패했다.

과거 문서의 50% 표를 새 연구의 기준으로 복제하지 않는다.

### SD와 표본의 정의

선별과 전략은 묻는 것이 다르므로 **같은 계산에 섞지 않는다.**

| | 선별 (screen) | 전략 (strategy) |
|---|---|---|
| 묻는 것 | 조건부 신호 수익이 비용을 넘는가 | 거래 순기댓값이 0을 넘는가 |
| SD | 단면/구간 수익률의 SD | **거래 한 건 손익의 SD** (stop·TP 반영) |
| n | 독립 관찰 수 | **실제 체결 거래 수** |

독립 표본은 중첩을 제거한 뒤의 수다. label 구간이 겹치면 겹치는 만큼 표본이 아니다
(purge/embargo, C4 참조). 5분봉 개수를 독립 표본으로 쓰지 않는다.

전략 쪽 계산은 Phase 4의 `실제 거래 n≥100`과 직접 맞물린다. 후보 비교 시
**필요 거래 수와 그 거래 수에 도달하는 데 걸리는 기간**을 함께 적는다.
하루 진입 한도·같은 방향 연속 제한·보유시간이 그 기간을 결정한다.

### TRAIN 과 OOS 중 **큰 쪽**이 기준이다

전략은 TRAIN 과 OOS 를 **모두** 통과해야 채택된다. 따라서 사전등록에 적을 필요 효과는
둘 중 큰 쪽이다. 보통 OOS 쪽이 크다 — TRAIN 표본은 봉 수로 늘릴 수 있지만
OOS 거래 수는 빈도와 기간이 정한다.

OOS 쪽 계산에는 **손절/TP 를 적용한 거래당 손익 SD** 와 **Phase 4 의 거래 수 요건**을 쓴다.
봉 수익률 SD 로 계산하면 필요 효과를 과소평가한다.

TRAIN 만 보고 사전등록하면, TRAIN 은 통과하지만 OOS 에서 **영원히 확인되지 않는**
크기의 효과를 좇게 된다. 그 구간이 존재하는지 먼저 확인한다.

### 예상 표본에 계좌 정지를 포함한다 (A1 교훈, 2026-09-23)

엔진은 실거래 위험 규칙을 그대로 적용한다. 누적 DD(`MAX_DRAWDOWN`, 당시 10%, 2026-09-24 사용자 정정으로 30%)는 자동 해제가 없으므로
한 번 닿으면 이후 신호가 전부 거부되고 표본이 잘린다. A1은 빈도 한도만 반영한 예상 162건이
실제 102건이 되어 판정 불가로 끝났다. 사전등록의 예상 표본에는 다음을 명시한다.

- 계좌 수준 정지(DD·일 손실·연패 쿨다운)가 연구 실행에 **적용되는지**, 적용되면 표본 절단 위험
- G5(변동성·funding·급변)와 진입 조건의 겹침 — 예: 수축 진입 vs `VOL_TOO_LOW`
- 전략 **우위 측정**(거래당 손익)과 **계좌 위험 규칙**의 검증을 같은 실행에서 할지 분리할지

어느 쪽을 택하든 결과를 보기 전에 정하고, 결과를 본 뒤 정지 규칙을 끄거나 켜서 재판정하지 않는다.

### 판정과 기록

| 결과 | 처리 |
|---|---|
| 가용 ≥ 필요 | 사전등록 진행. 계산 결과를 사전등록 문서에 그대로 적는다 |
| 가용 < 필요 | **사전등록하지 않는다.** 표본을 늘리거나(구간·심볼·빈도), SD를 줄이거나(횡단면·중립화), 비용을 낮추는 설계 변경이 먼저다 |
| 효과 ≤ 비용 | 표본으로 해결되지 않는다. 그 후보는 폐기한다 |

가정한 효과 크기 `e`의 근거를 함께 적는다. 근거가 "이 정도면 좋겠다"이면 게이트를
통과한 것이 아니다. 역방향으로 `detectable_effect_bps`를 계산해
**"이 표본으로 증명 가능한 최소 효과"**를 적는 편이 정직하다.

설계를 바꿔 다시 계산하는 것은 허용한다. 단 **결과를 본 뒤**에 검정력 기준을 낮추거나
효과 가정을 올려 통과시키는 것은 금지한다.

## 데이터 분할과 노출 기록

과거 각 연구의 기간은 RESEARCH_HISTORY 및 사전등록 원문을 따른다. 옛 공통 2019~2022/2023/2024+ 표를 새 연구에 자동 적용하지 않는다.
2024~현재는 과거 스모크·비교·점검에 일부 사용됐다. H3/R1에서 2025/2026 후속 단계를 실행하지 않았다는 사실만으로 프로젝트 전체 미열람 OOS라 부르지 않는다.
새 연구는 데이터 열람·실행 이력, split, 코드/config/data digest, 시도 횟수를 남기고 동결 후 전향적 미열람 구간을 사전에 지정한다.
TRAIN의 추정값만 정규화/edge 추정에 사용. VALIDATION은 사전 제한된 확인, TEST는 최종 1회다.

Walk-forward 기본 창은 TRAIN 12개월 / 다음 3개월 검증. purge/embargo로 label과 포지션 구간 중첩을 제거한다.
**C4:** 무제한 보유 정책에 유한 “최대 보유기간”을 임의 대입하지 않는다. 새 전략 사전등록에서 horizon·경계 포지션 처리·purge 기준을 확정해야 한다.

## 시간·체결·비용

- 마감된 봉만 사용하며 상위 TF는 close 이후에 노출한다. ZigZag는 confirmed_at_ms <= as_of_ms.
- causal rolling 정규화만 사용. 전체 표본 fit, 미래 regime label, 사후 뉴스 수정본을 실시간 입력으로 사용 금지.
- 백테스트도 동일 decide를 호출한다. 기존 엔진은 5분 평가→다음 1분봉 체결 경로이며 새 전략 평가 주기를 자동으로 바꾸지 않는다.
- 동일 봉 내 stop/TP 선후를 알 수 없으면 보수적으로 stop 우선. gap은 손절가 체결 보장이 아니다. 거래량 0은 미체결.
- 진입·청산 수수료, 슬리피지, 실제 보유 시점 funding을 반영한다. funding 간격 변화·부호·강제청산·mark price 한계를 기록한다.
- 시장가 기반을 기본으로 유지. 지정가/메이커 비용만 낮춰 낙관적 체결을 가정하지 않는다. 미체결과 역선택을 별도 검증해야 한다.
- 계좌 회계에는 미실현손익·실현손익·수수료·funding·equity·위험 누적 상태를 포함한다.
- fee 기본값은 당시 설정 입력이지 현재 거래소 요율 사실이 아니다. 연구마다 비용/자료 버전을 고정한다.

데이터 전제조건 실패/파일 누락은 전략 기각이 아니다. DATA_INSUFFICIENT/검증 중단을 결과와 분리한다.
H3의 90% 적재율, 22bps, n≥200 등은 해당 사전등록 기준이며 새 연구의 보편 임계값으로 복제하지 않는다.

## Phase 4 통과 기준 — 유지 / 미해결 분리

다음 모두를 확인하기 전 게이트 통과나 Paper 진입을 선언하지 않는다.

| 항목 | 기존 기준 |
|---|---|
| OOS 성과 | 비용 후 양의 기댓값, 실제 거래 n≥100 |
| 기준선 | 랜덤 분포 95백분위 초과, Buy & Hold 대비 Sharpe 우위 |
| 비용 강건성 | 수수료·슬리피지 2배에도 양의 기댓값 |
| 파라미터/시작점 | 주요 파라미터 ±20%에서 급락 없음, 시작일 ±30일 결론 동일 |
| Walk-forward | 창의 60% 이상 양의 수익 |
| 안전성 | 강제청산 0회, MDD가 TRADING_CORE 한도 이하 |
| 누출/재현 | causal 테스트·결정론·신호 셔플 검사 |
| 심볼 교차 | 다른 심볼 방향 일관성 확인. 실제 다중심볼 거래 승인을 의미하지 않음 |
| 지연 검사 | **C2 미해결:** 옛 문서 “1일/1봉”, “부호 유지/성과 소멸” 충돌 |

C2는 지연 강건성과 셔플 null 검사를 분리해 사전등록 전에 단위·기대 결과를 사용자와 확정한다.
“급락 없음”, 셔플 “성과 소멸” 등의 정량 판정도 성과 열람 전 고정한다. 미확정 조건을 생략한 통과는 금지한다.
스크린 신호 표본 수를 체결 거래 수로 바꾸어 위 n 조건에 대입하지 않는다.

## 지표·감사·테스트

Net expectancy, PF, MDD, Sharpe, 거래 수·승률·R 분포·보유기간, MAE/MFE, 월별/연도별·롱숏·regime 성과, 비용 기여, 거부 사유, 기준선·강건성 결과를 기록한다.

사후 MFE/MAE와 forward-return label은 실시간 feature로 역유입되지 않아야 한다.

| Exchange | FakeExchange 통합, 응답 유실·429·WS 단절·중복·보호주문 실패·kill/restart 주입 |

| Parity | 같은 snapshot에서 진입/청산 시점·결정 일치, fee/funding 일치; 실측 체결 차이만 설명 가능하게 기록 |

누출 테스트를 스킵하지 않는다. 문서만 변경한 작업은 링크/보존성/변경 범위를 검증하고 코드 테스트 실행 여부를 구분해 보고한다.

비적용 규칙을 기록한다. 전체 규칙 계좌 재생·Paper/Testnet/Live에서는 G6를 유지한다.
2023~2026 달력이 없어 계좌 재생을 하지 못했다면 해당 안전성 검증은 미완료다.
우위 측정의 PASS를 전체 Phase 4 통과나 실거래 승인으로 대체하지 않는다.
세부 기준과 구현 대기는 [WA 사전등록](../research/08-wa-preregistration.md)을 따른다.

| Phase | 작업과 종료 조건 |
|---|---|
| 0 설계 | 현재 요구·충돌 해결, 후보 선택 및 성과 열람 전 명세/사전등록. 현재 위치 |
| 1 기반 | 데이터 갭/예외 설명, 재집계 원인 미규명 불일치 0, 설정 해시/품질 검사. 계좌 snapshot 1분 기록·원래 2019 시작 요구는 C3 감사 전까지 완료 단정 금지 |

| 3 Backtest | 합성 체결/fee/funding 수작업 일치, 강제청산, 골든 완전 재현, 보고서 전 항목 |

| 9 실거래 확대 | 단계적 확대·월별 재검토. 편차 원인 확인 전 확대 중단 |
