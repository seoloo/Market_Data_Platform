# 거래 코어와 안전성

기준일: 2026-09-23. 분야: 위험 한도·주문/포지션·실행 안전성.
기존 순수 Risk/전략/Backtest는 구현되어 있지만 거래소 실행 계층은 설계 상태다.

## 전략 인터페이스와 정책 경계

`decide(snapshot: MarketSnapshot, portfolio: PortfolioState, cfg: Config) -> Decision`
동일 입력은 동일 결정이어야 한다. 외부 데이터 수집과 주문 전송은 함수 밖에서 수행한다.
전략이 진입 의도를 내도 Risk의 승인이 있어야 한다. Risk는 청산·위험 축소를 막지 않는다.
모든 평가에는 config_version_id, code_version_id, snapshot_digest, 구성 신호 및 거부 이유를 남긴다.

현재 구현에 남아 있는 D12 정책: 최대 보유시간 강제청산 없음, LONG이면 short_score > long_score, SHORT이면 반대로 엄격히 역전할 때 신호청산, 동점 유지.
손익 부호나 최소 보유시간은 이 청산을 막지 않는다. 손실 중 신호청산을 “익절”로 기록하지 않는다.
청산 후 FLAT을 거치고 재진입을 새로 평가한다. 기존 재진입 대기는 아래 한도표를 따른다.
기존 H1 진입점수 70·스윙/ATR 선택·2R TP는 재현용 구현 상태이며 새 전략에 자동 채택하지 않는다.
새 전략의 진입·청산·손절·TP는 사전등록 필요. D22 8개 시간대/첫 15분봉 재평가 규칙은 제외한다.

## 위험 한도 (유지, 완화 금지)

| 항목 | 한도 / 의미 |
|---|---|
| 거래 위험 | 계좌 equity의 최대 1%. 반드시 다 쓰는 목표가 아님 |
| 증거금 / 레버리지 | equity 10% 상한 / 레버리지 허용 범위 **1x ~ 10x**(사용자 지정, 스키마가 10 초과 거부). 레버리지는 손절 역산 결과값이며 목표가 아니다. 실거래는 단계적: 최초 소액 3x 이하, live 스키마 상한 5x, 10x까지 상향은 실측 뒤 사용자 승인. Phase 8 위험은 설계값의 절반 |
| 일 손실 / 누적 DD | 2% / 10%. 일 손실은 UTC 일 시작 equity 기준 실현+미실현, DD 도달 시 HALTED·자동 해제 금지 |
| 빈도 | **하루 거래 횟수·같은 방향 연속 진입 횟수 제한 없음**. 2026-09-24 사용자 명시 정정. 두 설정은 `null`; 이전의 2회 ‘확정’ 표기는 승인 근거로 취급하지 않는다. 카운터는 관측·과거 재현용으로 유지 |
| 연패 | 4회에서 진입 차단, 대기 240분. 누적 상태 복구 필수 |
| 재진입 대기 | 청산 후 60분. D22 이전부터 존재 |
| 청산 안전성 | 청산거리 / 손절거리 ≥ 2.0, 최소주문 미달·유효하지 않은 stop은 진입 거부 |
| 수량 반올림 | step_size에 내림, 기존 반올림 오차 상한 5% |
| 잔고 여유 | 필요 증거금의 1.5배 가용잔고 |
| 보호 공백 | 첫 체결부터 5,000ms 초과 시 전량 시장가 청산·HALTED |

레버리지 숫자를 목표로 삼지 않는다. 증거금은 최대 손실 보장이 아니며 갭·급변·슬리피지·거래소 장애로 실제 손실이 예상 위험을 초과할 수 있다.

## 손절 우선 사이징: 요구사항과 구현 차이

1. 전략 논리/시장 구조로 손절가를 먼저 정한다. 롱은 진입가 아래, 숏은 위여야 한다.
2. `s = abs(entry - stop) / entry`, 위험예산 `L <= equity * risk_per_trade`.
3. 단위 명목가당 비용 `c`에 진입/손절 수수료·진입/손절 슬리피지·불리한 funding을 포함한다.
4. 비용 포함 상한 `N <= L / (s + c)`. 실제 체결가/방향/수수료 기준 닫힌 해는 sizing 구현에서 계산한다.
5. 증거금·레버리지·거래소 명목가 상한을 적용해 N을 줄이고 수량을 내림한다.
6. 최소 필요 정수 레버리지, 청산거리, 주문 필터를 검증하고 반올림 후 손실을 다시 계산한다.
7. 상한 내 실행이 불가능하면 거래 거부. 위험예산에 맞추기 위해 stop을 넓히지 않는다.

**C1 미해결:** [현재 설정](../../config/base.yaml)은 min_stop_distance=0.01, tight_stop_action=WIDEN이며 [sizing](../../src/auto_trading/risk/sizing.py)이 실제 stop을 넓힌다.
이는 새 사용자 지침과 다르다. 위 원칙은 승인된 목표이며 구현 완료가 아니다.
1% 하한을 유지/자격 제한으로 전환/재설계하는 방법과 schema의 결합 제약은 별도 검토·승인·테스트 전까지 임의 변경하지 않는다.
단순히 포지션만 줄이면 기존 설정 검증까지 해결된다고 가정하지 않는다.
구조적 손절이 ATR보다 거의 항상 넓었던 과거 관찰은 연구 근거이지 “먼 손절이 항상 안전”하다는 일반 법칙이 아니다.

## 진입 게이트 G1~G7

실제 기준값은 [설정](../../config/base.yaml), 경계 비교와 사유는 [gates](../../src/auto_trading/risk/gates.py)에서 추적한다. 여러 실패 사유를 전부 기록한다.

| 그룹 | 거부 상황 |
|---|---|
| G1 시스템 | RUNNING 아님, kill switch, UNKNOWN 주문, reconcile 실패, 실거래 dirty code, 시계 오차 |
| G2 데이터 | stale·결측·warmup 부족·gap·잘못된 가격·과대 spread·mark/last 괴리 |
| G3 계좌 | 일 손실·DD·연패·cooldown, 잔고 부족. 일 진입 횟수 제한은 기본 비활성 |
| G4 노출 | 포지션 존재, 사이징 실패, 명목가/레버리지/반올림 한도, 청산가 근접, 재진입 제한 |
| G5 시장 | 극단 변동성·급등락·funding 결측/극단값·불리한 funding 직전 |
| G6 일정 | 기존 결정론적 거시 일정 blackout 또는 달력 사용 불가. 뉴스 AI 점수와 별개 |
| G7 비용 | 기대 edge 또는 필요 edge 불명, 기대 edge가 비용 포함 기준 이하 |

데이터 결측을 중립 점수/0 funding으로 대체해 통과시키지 않는다.
DEGRADED/HALTED와 진입 금지는 청산·위험 축소를 금지하는 뜻이 아니다.

## 주문 상태·멱등성 (실행 계층 구현 대기)

PENDING_NEW → SUBMITTING → NEW → PARTIALLY_FILLED → FILLED.
CANCELED / REJECTED / EXPIRED는 종결 상태이며 부분 체결분은 포지션으로 계속 관리한다.
전송 timeout/연결 오류는 UNKNOWN: 실패로 단정하지 않고 거래소 원주문을 조회한다.
UNKNOWN이 하나라도 있으면 신규 진입 차단. 조회 실패는 UNKNOWN 유지, 60초 미해소 시 DEGRADED 및 critical 알림.

clientOrderId는 환경·전략 인스턴스·결정 시각·목적·명시적 재발행 번호로 결정론적으로 만든다.
재시작 세션 ID나 현재 시각을 쓰지 않는다. 로컬 의도 확인 → 원격 원주문 조회 → 부재를 확인한 경우에만 신규 전송.
CANCELED/EXPIRED/REJECTED를 원격 확인하고 Risk 재승인·재시도 한도를 만족할 때만 새 번호로 재발행한다.
거래소의 ID 중복 거부만으로 영구 멱등성을 보장한다고 가정하지 말고 로컬 durable intent·체결 대조를 병행한다.

## 포지션 상태·보호주문 (실행 계층 구현 대기)

FLAT → OPENING → 첫 체결 UNPROTECTED → 스톱 확인 OPEN → CLOSING → CLOSED → FLAT.
부분 축소는 OPEN → REDUCING → OPEN. 임의 상태에서 기동/불일치 시 RECONCILING을 거친다.

- 첫 체결 즉시 거래소 측 STOP_MARKET, closePosition=true, MARK_PRICE 기준 보호주문을 등록하는 기존 설계를 유지한다. 실제 API 호환성은 Phase 5에서 확인한다.
- 보호 등록 실패는 최대 3회·총 3초 내 재시도, 실패하면 전량 시장가 청산 후 HALTED. 보호 공백 상한은 별도로 적용한다.
- 부분 체결·청산과 잔여 진입 주문의 경합을 검사한다. 잔여 진입 주문을 방치해 청산 후 다시 노출되지 않게 한다.
- 청산 확인 후 잔여 TP/SL을 정리한다. reduce-only/close-all 제약을 지켜 반대 포지션을 만들지 않는다.
- OPEN에는 거래소 보호 stop이 존재해야 한다. stop은 손실 방향, 심볼당 활성 포지션 최대 1개.
- 로컬/원격 수량 차이는 step_size 이하 허용; 그 이상이면 신규 진입을 막고 대조한다.

## 재시작·정합성 복구

신규 진입 차단 → 거래소 포지션/미체결 주문/최근 체결 조회 → 로컬 주문·체결·위험 상태 복구 → 차이를 risk_events에 기록 → 보호주문 검사/복구 → 불변식 확인 후 RUNNING.
거래소가 진실의 원천이다. 원인 불명 포지션은 기존 orphan_policy=flatten에 따라 정리하되 조회 불명 상태에서 추정 주문을 보내지 않는다.
중복·역순 WS 이벤트를 멱등 반영하고 정기 REST 대조를 수행한다.
독립 watchdog은 보호주문 누락·상태 불변식 위반을 탐지한다. 청산 전송도 실패하면 HALTED 유지·critical 알림·계속 대조하며, “청산 완료”로 허위 기록하지 않는다.
