## 1. 판단 구조 — 왜 그냥 다 더하지 않는가

지표 점수를 전부 더하면 **"4시간은 하락인데 5분이 강해서 합계가 매수"** 가 나옵니다.
그래서 2단계로 나눕니다.

```
   [1단계 — 허가]                      [2단계 — 타이밍]
   B1 4시간 추세                        T1 15분 RSI
   B2 1시간 변동성                      T2 5분 모멘텀
        ↓                                    ↓
   "롱만 가능" / "숏만 가능"            "지금 들어갈 자리인가"
   / "거래 금지"                        점수 -1 ~ +1
        │                                    │
        └──────────── 곱한다 ────────────────┘
                       ↓
        1단계가 롱인데 2단계가 숏 신호 → 0 (진입 안 함)
        1단계가 롱이고 2단계도 롱 → 그 점수 그대로
```

**핵심**: 4시간 추세가 반대면 5분 신호가 아무리 강해도 **무조건 진입 안 합니다.**

## 2. 지표별 상세

### B1 — 4시간 EMA(50) 추세 `[방향 허가]`

**쉬운 설명**: 4시간봉 50개(약 8일)의 평균선 위에 있고, 그 평균선이 올라가고 있으면 "상승장"으로 본다.

| 항목 | 값 |
|---|---|
| 봉 | 4시간 |
| 계산 | ① 가격이 EMA(50) 대비 몇 % 위/아래인가 ② EMA(50)의 기울기 |
| 정규화 | 위 두 값을 최근 **120봉**(20일) 기준 z-score |
| config 키 | `features.b1_trend.*` |

**판정 기준**

| z 값 | 판정 | 결과 |
|---|---|---|
| **z > +0.5** | 상승 추세 | 🟢 **롱만 허용** |
| −0.5 ≤ z ≤ +0.5 | 추세 불명확 | ⛔ **진입 금지** |
| **z < −0.5** | 하락 추세 | 🔴 **숏만 허용** |

```yaml
b1_trend:
  enabled: true
  timeframe: "4h"
  ema_period: 50
  zscore_lookback: 120
  bias_threshold: 0.5        # 이 값 미만이면 진입 금지
```

> **바꾸고 싶다면**: `bias_threshold` 를 낮추면(예: 0.3) 거래 기회가 늘지만 애매한 구간에서도
> 들어갑니다. 높이면(예: 0.8) 확실할 때만 들어가지만 기회가 줄어듭니다.

### B2 — 1시간 ATR 변동성 국면 `[거래 허가 + 크기]`

**쉬운 설명**: 요즘 가격이 얼마나 출렁이는지를 지난 1년과 비교한다. 너무 잠잠하면 수수료만 나가고,
너무 심하면 위험해서 둘 다 거래를 막는다.

| 항목 | 값 |
|---|---|
| 봉 | 1시간 |
| 계산 | ATR(14) ÷ 종가 → 지난 **1년(365일)** 대비 백분위 |
| config 키 | `risk.volatility_gate.*` |

**판정 기준**

| 백분위 | 판정 | 결과 |
|---|---|---|
| **0 ~ 5%** | 너무 잠잠 | ⛔ 거래 금지 (`VOL_TOO_LOW`) |
| 5 ~ 70% | 정상 | 🟢 정상 거래 |
| 70 ~ 98% | 고변동 | ⚠️ 거래는 하되 주의 |
| **98 ~ 100%** | 극단 | ⛔ 거래 금지 (`VOL_TOO_HIGH`) |

```yaml
volatility_gate:
  atr_period: 14
  timeframe: "1h"
  lookback_days: 365
  atr_pct_lower: 0.05        # 이 밑이면 거래 금지
  atr_pct_upper: 0.98        # 이 위면 거래 금지
```

> **이 지표가 특히 중요한 이유**: 변동성이 극단적일 때는 손절이 제값에 체결되지 않습니다
> (급락 중에는 손절가를 지나쳐서 체결됨). 포지션 크기 계산은 "손절이 제값에 된다"를 전제하므로,
> **이 게이트가 그 전제를 지키는 장치**입니다.

### S — 손절 위치 규칙 `[포지션 크기를 결정]`

**쉬운 설명**: 손절을 어디에 둘지가 **포지션 크기를 결정합니다.** 손절이 가까우면 크게,
멀면 작게 잡습니다. 잃는 금액은 언제나 총액의 1%로 같습니다.

MVP 규칙 — 아래 두 후보 중 **더 먼 쪽**(= 더 보수적)을 고른다.

| 후보 | LONG | SHORT |
|---|---|---|
| ① 구조적 손절 | 최근 확정 스윙 저점 − 0.2×ATR | 최근 확정 스윙 고점 + 0.2×ATR |
| ② ATR 손절 | 진입가 − 1.5×ATR(1h) | 진입가 + 1.5×ATR(1h) |

```
stop_price = 둘 중 진입가에서 더 먼 쪽
그 다음 최소 손절폭 1% 를 적용 (더 좁으면 1% 로 넓힘)
```

```yaml
stop:
  mode: "structure_or_atr"
  atr_timeframe: "1h"
  atr_period: 14
  atr_multiple: 1.5
  swing_buffer_atr: 0.2      # 스윙 저점 바로 밑에 두면 노이즈에 걸림
  pick: "wider"              # wider | tighter
```

**손절폭이 포지션 크기를 어떻게 바꾸나** (총액 1,000달러 기준, 잃는 돈은 항상 10달러)

| 손절폭 | 포지션 크기 | 레버리지 | 수수료+슬리피지 | 손실 한도 대비 비용 |
|---|---|---|---|---|
| 1% (최소) | 869달러 | 9배 | 1.30달러 | **13%** |
| 2% | 465달러 | 5배 | 0.69달러 | 7% |
| 5% | 194달러 | 2배 | 0.28달러 | 3% |
| 10% | 98달러 | 1배 | 0.14달러 | 1% |

> **좁은 손절이 공짜가 아닙니다.** 1% 손절은 10달러 예산 중 1.3달러를 수수료로 씁니다.
> 그리고 포지션이 869달러라 급락 시 손절가를 지나쳐 체결되면 피해도 그만큼 큽니다.

---

### ⚠ 헷갈리기 쉬운 것 — "최소 손절폭 1%"의 의미

**"1% 손실이 날 때까지 버틴다"는 뜻이 아닙니다.**

포지션 크기를 계산하는 **분모**일 뿐입니다. 나가는 시점과는 무관합니다.

| 나가는 경우 | 언제 | 손실 크기 |
|---|---|---|
| **점수 청산** (주 경로) | 1분마다 점수 재계산 → 45 아래면 즉시 | **무관.** 0.01%여도, 이익이어도 나감 |
| 시간 초과 | 48시간 넘으면 | 무관 |
| 익절 | 손절폭의 2배 도달 | 이익 |
| **손절 주문** (최후 방어) | 손절가 도달 | 약 10달러 (총액 1%) |

**대부분의 거래는 점수 청산으로 끝납니다.** 손절 주문은 프로그램이 죽어도 작동하도록
거래소에 걸어두는 안전장치입니다.

→ `min_stop_distance` 를 낮추면 "더 늦게 자른다"가 아니라 **"포지션이 커진다"** 입니다.

> **왜 더 먼 쪽인가**: 손절이 멀수록 포지션이 작아집니다. 포지션이 작으면 급락 시
> 손절가를 지나쳐 체결되는 사고의 피해도 작아집니다. 잃는 금액(1%)은 어차피 같으니
> **더 먼 손절이 항상 더 안전**합니다.
>
> **스윙 저점은 "확정된" 것만 씁니다.** 지금 형성 중인 저점을 쓰면 나중에 값이 바뀌어
> 백테스트를 신뢰할 수 없게 됩니다 (repainting).

### T1 — 15분 RSI(14) 되돌림 `[진입 타이밍]`

**쉬운 설명**: 상승장에서 잠깐 내려왔을 때(눌림목) 사는 것이 목표. RSI가 너무 낮으면 추세가
깨진 것일 수 있고, 너무 높으면 이미 늦었다.

| 항목 | 값 |
|---|---|
| 봉 | 15분 |
| 계산 | RSI(14) |
| config 키 | `features.t1_pullback.*` |

**롱 편향일 때 (B1 = 상승)**

| RSI | 판정 | 신호값 |
|---|---|---|
| RSI < 30 | 너무 많이 빠짐 — 추세 이탈 의심 | 0.0 (신호 없음) |
| **RSI 35 ~ 50** | 🎯 **눌림목 — 매수 구간** | **+0.3 ~ +1.0** |
| RSI 50 ~ 65 | 이미 올라가는 중 | +0.2 |
| RSI > 70 | 과열 — 늦음 | 0.0 |

신호값 계산: RSI 35~50 구간에서 `signal = (50 − RSI) / 15`
→ RSI 38이면 `(50−38)/15 = 0.80`, RSI 45면 `(50−45)/15 = 0.33`

**숏 편향일 때 (B1 = 하락)**: 위를 50 기준으로 대칭 (RSI 50~65가 매도 구간)

```yaml
t1_pullback:
  enabled: true
  timeframe: "15m"
  rsi_period: 14
  long_zone:  [35, 50]       # 롱 진입을 노리는 RSI 구간
  short_zone: [50, 65]
  invalidate_below: 30       # 이 밑이면 추세 이탈로 보고 신호 없음
  invalidate_above: 70
```

> **바꾸고 싶다면**: `long_zone` 을 `[40, 50]` 으로 좁히면 더 얕은 눌림목만 노립니다.
> `[30, 50]` 으로 넓히면 깊은 눌림목도 노리지만 추세가 깨진 걸 잡을 위험이 커집니다.

### T2 — 5분 모멘텀 `[진입 타이밍]`

**쉬운 설명**: 눌림목이 **끝났는지** 확인. 아직 떨어지는 중인데 사면 안 되니까,
최근 30분이 다시 위로 돌았는지 본다.

| 항목 | 값 |
|---|---|
| 봉 | 5분 |
| 계산 | 최근 **6봉(30분)** 누적 수익률 → 최근 **288봉(24시간)** 기준 z-score |
| config 키 | `features.t2_momentum.*` |

**판정 기준**

| z 값 | 판정 (롱 기준) | 신호값 |
|---|---|---|
| z > +0.3 | 🎯 반등 시작 | `squash(z, 1.5)` |
| −0.3 ~ +0.3 | 아직 횡보 | 0.0 |
| z < −0.3 | 아직 하락 중 | 음수 → 롱 신호 죽음 |

```yaml
t2_momentum:
  enabled: true
  timeframe: "5m"
  return_bars: 6             # 30분
  zscore_lookback: 288       # 24시간
  min_abs_z: 0.3             # 이 미만은 0 처리
  squash_k: 1.5
```

### T3 — 5분 거래량 확인 `[확인 — 더하지 않고 곱함]`

**쉬운 설명**: 가격만 움직이고 거래량이 없으면 가짜 움직임일 수 있다.
거래량은 **방향이 없으므로** 점수에 더하지 않고, T1+T2 점수에 **곱한다**.

| 항목 | 값 |
|---|---|
| 봉 | 5분 |
| 계산 | 현재 거래량 ÷ 거래량 SMA(20) |
| config 키 | `features.t3_volume.*` |

**판정 기준**

| 비율 | 판정 | 곱하는 값 |
|---|---|---|
| **≥ 1.2배** | 🟢 참여 충분 | **× 1.0** |
| 0.8 ~ 1.2배 | 보통 | × 0.8 |
| < 0.8배 | 🔴 한산함 | × 0.6 |

```yaml
t3_volume:
  enabled: true
  timeframe: "5m"
  sma_period: 20
  strong_ratio: 1.2
  weak_ratio: 0.8
  confirm_strong: 1.0
  confirm_normal: 0.8
  confirm_weak: 0.6
```

> **왜 곱하는가**: 더하면 "거래량이 많으니까 매수" 라는 말이 안 되는 기여가 생깁니다.
> 거래량은 다른 신호를 **강화/약화**시킬 뿐 스스로 방향을 말하지 않습니다.

## 3. 최종 점수 계산

```
1단계 (허가)
   bias_direction = B1 판정        (+1 롱만 / 0 금지 / −1 숏만)
   B2 가 거래 금지 구간이면 → 여기서 끝, 진입 안 함

2단계 (타이밍)
   trigger = squash( 0.5 × T1 + 0.5 × T2 ) × T3
                      └── 등가중 (0.5 / 0.5) ──┘
   squash(x) = x / (1.5 + |x|)   — 값을 -1~+1 로 압축

3단계 (합성)
   bias 와 trigger 의 부호가 같으면  →  direction = trigger
   다르거나 bias가 0이면             →  direction = 0

4단계 (점수 변환)
   long_score  = 50 × (1 + direction)      →  0 ~ 100
   short_score = 100 − long_score
```

### 진입 / 청산 기준선

```
long_score
  100 ┤
      │   🟢 진입 구간
   70 ┤━━━━━━━━━━━ 진입선 (LONG_ENTRY) ━━━━━━━━━━━
      │
      │   ⚪ 유지 구간 — 아무것도 안 함
      │      (이미 롱이면 계속 보유, 없으면 계속 대기)
      │
   45 ┤━━━━━━━━━━━ 청산선 (LONG_EXIT) ━━━━━━━━━━━━
      │   🔴 청산 구간
    0 ┤
```

```yaml
policy:
  long_entry_threshold:  70
  long_exit_threshold:   45
  short_entry_threshold: 70
  short_exit_threshold:  45
```

> **왜 70과 45로 다른가**: 같은 값이면 점수가 70 근처에서 흔들릴 때 진입·청산을 반복하면서
> 수수료만 나갑니다. 진입은 어렵게, 청산은 쉽게 만들어 그걸 막습니다.

## 4. 실제 계산 예시 (숫자로 따라가기)

**상황**: 총액 10,000 USDT, BTC 상승 추세 중 15분봉이 눌림목

| 단계 | 값 | 계산 |
|---|---|---|
| B1 4h 추세 z | +1.2 | > 0.5 → **bias = +1 (롱만 허용)** 🟢 |
| B2 ATR 백분위 | 45% | 5~70% → **정상 거래** 🟢 |
| T1 15m RSI | 38 | (50−38)/15 = **+0.80** |
| T2 5m 모멘텀 z | +0.50 | 0.50/(1.5+0.50) = **+0.25** |
| T3 거래량 비율 | 1.35배 | ≥1.2 → **× 1.00** |
| **trigger** | | squash(0.5×0.80 + 0.5×0.25) × 1.00 = 0.525/(1.5+0.525) = **+0.26** |
| **direction** | | bias(+1)와 부호 같음 → **+0.26** |
| **long_score** | | 50 × (1+0.26) = **63.0** |
| 진입 판정 | | 63.0 < 70 → ❌ **진입 안 함** (임계값은 Phase 4에서 재조정) |

**비용 검사**

| 항목 | 값 |
|---|---|
| 예상 비용 | 진입 4.5bps + 청산 4.5bps + 슬리피지 4bps ≈ **13 bps** |
| 최소 요구 엣지 | 5 bps |
| 필요 기대수익 | 13 + 5 = **18 bps 이상** |
| 통과 시 | → 리스크 엔진으로 |

**리스크 엔진 → 주문** (손절 위치부터 거꾸로 계산)

| 단계 | 값 |
|---|---|
| ① 최대 허용 손실 | 10,000 × 1% = **100 USDT** |
| ② 손절 위치 (전략) | 최근 스윙 저점 98,000 |
| ③ 손절폭 | (100,000 − 98,000) / 100,000 = **2.0%** (최소 1% 이상 ✅) |
| ④ 비용률 | 진입 0.065% + 청산 0.085% |
| ⑤ **포지션 크기** | 100 / (0.02×1.00085 + 0.0015) = **4,647 USDT** |
| ⑥ 수량 | 4,647 ÷ 100,000 = 0.046 BTC (0.001 단위 내림) |
| ⑦ 증거금 상한 | 10,000 × 10% = 1,000 USDT |
| ⑧ **레버리지** | ceil(4,647 / 1,000) = **5x** (자동, 상한 10x 이내 ✅) |
| ⑨ 실제 증거금 | 4,647 / 5 = 929 USDT |
| ⑩ 청산가 | 약 80,300 (손절가보다 **9.8배 멀다** ✅) |
| **손절 시 총손실** | 가격 92.9 + 수수료·슬리피지 6.9 = **99.8 USDT** ≤ 100 ✅ |
| 익절가 (2R) | 100,000 × 1.04 = **104,000** → 이익 약 186 USDT |

> **손절폭이 바뀌면 포지션 크기와 레버리지가 자동으로 바뀐다.**
> 손절 1%면 → 크기 8,690 / 레버리지 9x. 손절 5%면 → 크기 1,940 / 레버리지 2x.
> 손절 10%면 → 크기 984 / 레버리지 1x. **잃는 금액은 언제나 100 USDT 로 같다.**
>
> 단 이 거래가 점수 청산으로 −0.3% 에서 끝나면 손실은 4,647 × 0.003 + 비용 ≈ **21 USDT** 다.
> 손절까지 가는 경우가 오히려 드물다.

## 5. 지금은 쓰지 않는 지표 (그리고 이유)

> 이 목록은 **"넣으면 좋아진다"가 증명되면 추가**합니다. 추가 방법은 §7 참고.

### 5.1 상관관계 때문에 뺀 것

RSI·MACD·모멘텀·ROC는 서로 **0.8 이상 상관**인 경우가 흔합니다.
넷 다 넣으면 **같은 신호를 4번 세는 것**이고, 오차만 4배가 됩니다.

| 지표 | 제안 규칙 (참고용) | 왜 뺐나 |
|---|---|---|
| **MACD** | MACD선이 시그널선을 아래→위 교차 시 매수 | T2 모멘텀과 상관 0.8+ 예상. 둘 중 하나만 |
| 스토캐스틱 | %K < 20 에서 반등 시 매수 | T1 RSI와 거의 동일한 정보 |
| ROC / 모멘텀 | N봉 수익률 > 0 | T2와 동일 |
| Williams %R | −80 이하에서 반등 | T1과 동일 |

### 5.2 파라미터가 늘어서 뺀 것

| 지표 | 제안 규칙 (참고용) | 왜 뺐나 |
|---|---|---|
| 볼린저밴드 | 하단 터치 후 복귀 시 매수 | 기간+표준편차 2개 파라미터 추가. ATR과 정보 중복 |
| 일목균형진 | 구름대 위/아래 | 파라미터 5개. 4h EMA와 정보 중복 |
| 피보나치 확장 | 1.618 도달 시 익절 | 익절은 % 고정으로 단순화 |
| 다중 EMA 배열 | 20>50>200 정배열 | B1 하나로 충분 |

### 5.3 검증이 불가능해서 뺀 것

| 항목 | 왜 뺐나 | 언제 다시 볼까 |
|---|---|---|
| **Elliott Wave 파동 카운팅** | 룩백이 1봉만 달라져도 카운트가 바뀜(repainting). 백테스트를 믿을 수 없음 | Phase 13 실험 |
| **뉴스 + AI 분석** | 지금 AI에게 과거 기사를 주면 **그 사건의 결과를 이미 알고 있음**. 백테스트가 원리적으로 불가능 | Phase 11, **진입 신호가 아니라 "위험하면 거래 차단" 용도로만** |
| **경제지표 서프라이즈** | 과거 시점의 시장 예상치(consensus) 데이터를 구할 수 없음 | Phase 10, 지금부터 직접 수집해서 1~2년 쌓은 뒤 |

### 5.4 지금도 쓰는 것 (지표는 아니지만)

| 항목 | 용도 | 설정 |
|---|---|---|
| **경제지표 발표 블랙아웃** | FOMC/CPI 등 발표 전후 **진입만 금지** | FOMC 전60분~후30분, CPI 전30분~후15분 |
| **Funding rate** | 극단값(±0.1%/8h)이면 진입 금지 | `EXTREME_FUNDING` |
| **호가 스프레드** | 5bps 넘으면 진입 금지 | `WIDE_SPREAD` |
| **스윙 고/저점** | 구조적 손절 위치 계산용 (신호 아님) | `features/structure.py` |

## 7. 지표를 추가하고 싶을 때 — 통과해야 하는 4가지

새 지표를 넣기 전에 **반드시** 아래를 확인합니다. 하나라도 실패하면 넣지 않습니다.

| # | 조건 | 확인 방법 |
|---|---|---|
| 1 | 기존 지표와 **상관 0.7 미만** | 백테스트 리포트의 `correlation_matrix.md` |
| 2 | **혼자서도** 랜덤보다 나음 | 단일 지표 백테스트 |
| 3 | 넣은 후 **out-of-sample 성과 개선**이 잡음 수준을 넘음 | A/B 백테스트 (validation 구간) |
| 4 | 파라미터가 늘어난 만큼 **표본이 충분** | 거래 수 ≥ 100 유지 |

> **왜 이렇게 까다로운가**: 지표를 늘릴수록 백테스트 성적은 *반드시* 좋아집니다.
> 그건 전략이 좋아진 게 아니라 과거 데이터에 맞춘 것뿐입니다(과최적화).
> 실거래에서는 그 개선이 사라집니다.

| 하고 싶은 것 | 고칠 곳 |
