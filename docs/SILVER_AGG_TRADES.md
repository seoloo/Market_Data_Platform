# Silver 체결 감사 (README 4-1)

> Bronze 의 체결 원본(aggTrades zip)을 Spark · Delta Lake 로 정제 · 감사한다.
> 코드: [`src/mdp/silver/`](../src/mdp/silver) · 실행 환경: [`docker/spark/Dockerfile`](../docker/spark/Dockerfile)

## 한눈에

```text
Bronze zip ──(체크섬 다시 대조)──▶ 임시 CSV ──▶ Spark ──▶ Delta 표 5 개 (silver/)
 (F: 하드디스크)                   (Docker 볼륨)            ├ agg_trades             깨끗한 체결
                                                            ├ agg_trades_quarantine  못 쓰는 줄 + 이유
                                                            ├ agg_trades_audit_file  원본 파일마다 결함 집계
                                                            ├ agg_trades_gaps        빈 곳 · 역행 위치
                                                            └ agg_trades_audit_daily 날마다 행 수 · 1 분봉 대조
```

실행 (한 달치)::

```bash
docker compose --profile spark build
MDP_BRONZE_ROOT=F:/mdp/bronze docker compose run --rm spark python -m mdp.silver.agg_trades --symbol BTCUSDT --month 2024-03
```

## 규칙

| 단계 | 규칙 | 왜 |
|---|---|---|
| 출처 | 그 달 월 파일이 기본, **Bronze 에 일 파일이 있는 날은 일 파일이 이긴다** | 일 파일은 사람이 `sync --days` 로 일부러 받은 교체본 (연구 216 방식) |
| 검증 | 읽기 직전 Bronze zip 의 SHA-256 을 체크섬 목록과 다시 대조 | 받은 뒤 디스크에서 바뀌었을 수 있다 |
| 읽기 | 모든 칸을 글자로 읽고 `try_cast` 로 타입을 맞춤 | 형식이 틀린 줄 하나로 작업 전체가 죽지 않고, 그 줄은 격리된다 |
| 타입 | 가격 · 수량은 `decimal(18,8)`, 시각은 UTC ms (마이크로초 표기는 1000 으로 나눔) | float 합은 더하는 순서에 따라 값이 달라진다 |
| 격리 | `parse_error`(못 읽음) · `outside_period`(파일 기간 밖) · `conflicting_duplicate`(같은 번호, 다른 내용) | 버린 줄도 이유와 함께 남겨야 나중에 판단을 바꿀 수 있다 |
| 중복 | 내용까지 같은 중복은 하나만 남기고 몇 개였는지 감사 표에 센다 | 2022-09 '모든 체결이 두 번' 같은 결함을 숫자로 보이게 |
| 빈 곳 · 역행 | 번호 순으로 이웃한 두 체결을 비교 (번호를 100 만 단위 칸으로 나눠 여러 스레드가 정렬, 칸 경계는 따로) | 한 줄로 정렬하면 스레드 하나가 6,651 만 줄을 혼자 정렬한다 |
| 날 대조 | 그날 거래량을 공식 1 분봉 합계와 비교, **0.5 %** 넘게 다르거나 번호가 비면 의심일 | 연구 216 의 0.5 % 기준 |
| 쓰기 | 그 달 칸만 바꿔 끼움 (Delta `replaceWhere`) | 같은 달을 다시 돌리면 그 달만 바뀌고(멱등), 이전 내용은 Delta 이력에 남는다 |

## 결과 — BTCUSDT 2024-03

| 항목 | 값 |
|---|---|
| 출처 | 월 파일 1 개 + 3 월 5 일 일 파일(3-3 에서 백필한 것) |
| 깨끗한 체결 | **66,512,993 행** (월 파일 행 수와 같음 — 3 월 5 일 일 파일 5,270,260 행이 월 파일의 그날과 행 수가 같다) |
| 격리 · 빈 곳 · 역행 · 중복 | 모두 0 |
| 날 대조 | 31 일 모두 통과 — 1 분봉 합계와 차이 최대 0.00046 %, 9 일은 정확히 같음 |
| Delta 표 크기 | `agg_trades` 1.8 GB (원본 zip 847 MB · 압축 푼 CSV 4.4 GB) |

날 대조에서 '정확히 같지 않은' 날이 있는 이유는 **확인 필요**다(분 경계 체결 배정이 공식 봉과 다를 수 있다 —
연구 216 도 1 분 단위로는 1,440 분 중 1,110 분만 정확히 맞았다고 적었다).

## 검증

### 1. 연구 216 추출기와 같은가

`python -m mdp.verify.compare_216 --symbol BTCUSDT --month 2024-03` — 같은 월 zip 을 연구 216 추출기로도 처리해 비교.

| 항목 | 검산용 전수 추출 `extract_full` | 빠른 추출 `extract` (연구에서 쓴 것) |
|---|---|---|
| 행 수 · 첫/끝 번호 · 첫/끝 시각 · 머리줄 · 시각 단위 · 빈 곳 · 역행 | 모두 같음 | 모두 같음 |
| 매시 00 분 744 개 [거래량 · 공격 매수량 · 체결 수] | **모두 같음** (상대 오차 최대 1.2e-13) | **1 분 다름** — 2024-03-15 09:00 |

빠른 추출의 1 분 차이는 연구 스크립트의 덩어리 경계 버그다 →
[docs/findings/2026-10-21-qflow216-check-minute-chunk-boundary.md](findings/2026-10-21-qflow216-check-minute-chunk-boundary.md).
합격 기준은 검산용 전수 추출이다(비교 도구도 그것으로 종료 코드를 정한다).

### 2. 최적화가 결과를 바꾸지 않았는가

첫 판(Delta v0)과 최적화 판(v1)을 시간여행으로 열어 행 단위로 비교(`exceptAll` 양쪽, `run_id` 제외):
`agg_trades` 66,512,993 행 · `agg_trades_audit_file` · `agg_trades_audit_daily` 모두 **한쪽에만 있는 행 0**.

### 3. 결함을 일부러 넣은 시험

`docker compose run --rm spark python -m pytest tests/mdp/spark -q` — 7 개. 머리줄 · 깨진 줄 · 기간 밖 줄 · 빈 곳 ·
같은 내용 중복 · 다른 내용 중복 · 시각 역행 · 마이크로초 시각 · 일 파일 우선 · 1 분봉 대조 · 같은 달 두 번 쓰기.

## 걸린 시간 (단일 PC, Docker 에 Spark `local[8]`, 드라이버 6 GB)

| 판 | 시간 | 무엇이 달랐나 |
|---|---:|---|
| 첫 판 | 3,887 초 (65 분) | 표 5 개 · 행 수 세기 · 보고서마다 CSV 읽기부터 다시 계산(Spark 지연 실행) |
| 최적화 | **1,059 초 (18 분)** | 형식 맞춘 줄 · 깨끗한 체결을 임시 Parquet 으로 한 번 써 두고 재사용, 보고서는 쓴 Delta 에서 읽음 |
| (참고) 연구 216 빠른 추출 | 22 초 | 감사 값만 뽑음 — 표를 만들지 않고, 덩어리 경계 버그가 있다 |
| (참고) 연구 216 전수 추출 | 260 초 | 감사 값만 뽑음 — 표를 만들지 않는다 |

- 연구 추출기는 '값 몇 개' 만 뽑고 버리지만, Silver 는 6,651 만 행 전체를 타입 있는 표로 남긴다 — 같은 일을
  비교하는 것이 아니다. 같은 조건의 비교는 README 4-3 벤치마크에서 한다.
- 실행 기록의 '최대 메모리'(약 60 MB)는 **파이썬 프로세스만** 잰 값이다. 실제 계산을 하는 Spark 자바
  프로세스는 `docker stats` 로 약 9.5 GB 까지 썼다. 4-3 에서는 컨테이너 메모리로 잰다.
