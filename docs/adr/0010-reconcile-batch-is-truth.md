# 0010 — 대사: 배치가 정답, 원인은 원문 토픽으로 가르고, 결과는 더하기만

- 상태: 채택 · 2026-10-24
- 관련: [대사 기록](../RECONCILE.md) · [`mdp.reconcile.daily`](../../src/mdp/reconcile/daily.py)

## 맥락

PC가 늘 켜져 있지 않으니 스트림은 반드시 끊긴다. 목표는 '24시간 무중단'이 아니라 **빈 곳을 정확히 찾아 메우기**다.
'다르다'만으로는 고칠 수 없다 — 끊김이면 감시 · 재연결, 늦음이면 워터마크, 중복이면 코드가 할 일이다.

## 결정

- **배치 봉(바이낸스 일 파일 → Silver → Gold)이 정답**이다. 스트림 봉을 분마다 맞댄다.
- 원인을 **원문 토픽**으로 가른다: 빠진 묶음 수 = 배치 − 스트림, 그중 원문 토픽에 없는 것 = 받지 못함(`stream_gap`),
  나머지 = 받았지만 버림(`late`). 스트림이 더 세면 `duplicate`, 수는 같은데 값이 다르면 `other`.
- `--repair`면 원인이 있는 분을 배치 봉으로 MERGE하고 `repaired`로 표시한다. 그 분은 일치율에 넣지 않는다.
- 결과 표(PostgreSQL)는 **더하기만** 한다 — 메우기 전에 찾은 원인과 메운 뒤 상태가 둘 다 남는다.

## 다른 안

| 안 | 버린 이유 |
|---|---|
| 스트림 봉에 체결 번호 목록을 남겨 비교 | 봉이 무거워진다. 수의 차이와 '원문에 있나'만으로 정확히 나눌 수 있었다 |
| 공식 1분봉을 정답으로 | 분 경계 체결 배정이 달라 정확히 맞지 않는다(연구 216: 1,440분 중 1,110분만 일치) |
| 결과를 날마다 덮어쓰기 | 메운 뒤에는 원인이 사라진다 |

## 치르는 값

- 원문 토픽 보관(7일) 안에 대사해야 원인을 가를 수 있다. 지나면 원인은 '알 수 없음'이 된다.
- 배치는 다음 날 일 파일이 나와야 돈다 — 대사는 하루 늦다.
- 스트림 몫의 일치율과 '메워서 같은 분'을 따로 세야 한다(섞으면 스트림이 좋아 보인다).

## 근거

- PC 잠듦 · 30분 지연 · 중복을 섞은 하루: 끊김 21분 · 받지 못한 체결 **13,897 = 재생이 건너뛴 13,897**, 늦음 426분 ·
  **678 = Spark가 워터마크로 버렸다고 보고한 678**, 중복 0. 메운 뒤 993 + 447 = 1,440분.
- 같은 원문을 큰 묶음으로 처리하면 늦음 0 · 일치율 98.5%, 작은 묶음이면 69.0% — 대사가 없었다면 몰랐을 차이.
