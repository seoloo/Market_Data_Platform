## 맥락

지금까지의 파이프라인(3-1 ~ 6-3)은 바이낸스 선물 체결로 만들었다. 원래 저장소가 코인 자동매매였고, 바이낸스는
체결 원본을 **키 없이 · 파일마다 체크섬과 함께** 공개해서 '받은 그대로 보관 → 체크섬으로 증명' 이 쉬웠다.

포트폴리오의 중심은 주식이어야 한다(사용자 결정). 사용자는 이미 한국투자증권 계좌가 있고, 원본 저장소에서
한국투자증권 API 로 받아 둔 국내 · 미국 일봉이 있다. 6-3 에서는 '실계좌 키로 접속하는 것 자체가 실계좌 연동'
으로 읽어 한국투자증권 연결 코드를 지웠는데, 사용자가 "주문만 안 하면 되지 않나" 라고 규칙을 다시 정했다.

먼저 미국 주식(Alpaca 무료 · IEX)을 검토했지만, 사용자가 쓰지 않기로 했다 — 증권사 가입이 새로 필요하고
한국 거주자 가입이 확실하지 않았으며, 이미 있는 한국투자증권 계좌 · 자료를 두고 새 원천을 들일 이유가 약했다.

## 결정

1. **주 원천은 국내 주식, 한국투자증권 Open API.** 실시간 체결 웹소켓(`H0STCNT0` KRX · `H0UNCNT0` 통합)과
   일봉 · 분봉 조회를 쓴다.
2. **시세 조회만.** 접속 창구는 허용한 (방법, 경로, TR)만 보낸다 — 토큰 · 접속키 발급과 시세 조회 4 개.
   주문 · 잔고 · 계좌 경로는 목록에 없어서 **보내기 전에 멈추고**, 시험이 그것을 확인한다. 계좌 번호는 읽지 않는다.
3. **기본 환경은 모의투자.** 모의투자 키로 시세가 되면 그 키를 쓴다 — 돈 있는 계좌와 키부터 떨어진다.
   모의투자에서 안 되는 조회만 실전 키(조회 전용)로.
4. **바이낸스는 지우지 않고 두 번째 원천**으로 둔다. 이미 잰 근거(재처리 · 스트림 = 배치 · 대사)는 그 원천의 기록이다.
5. Bronze 는 **응답 본문을 받은 그대로** 보관하고, 원천이 체크섬을 주지 않으므로 **받을 때 우리가 SHA-256 을
   매겨** 체크섬 목록에 남긴다(0001 · 0005 그대로).

## 다른 안

| 안 | 버린 이유 |
|---|---|
| 미국 주식 · Alpaca 무료(IEX) | 새 증권사 가입 필요 · 한국 거주자 가입 확실하지 않음 · IEX 는 시장 일부. 사용자가 되돌림 |
| 키 없는 주식 일봉만 | 실시간 원천이 없어 스트림 · 대사를 진짜로 못 한다 |
| 한국투자증권 연결을 원본처럼(주문 코드 포함, 설정으로 끔) | 주문 경로가 코드에 있으면 설정 실수 하나로 실계좌 주문이 나간다. 공개 저장소에 둘 수 없다 |
| 바이낸스를 걷어 내고 주식만 | 이미 잰 근거가 사라진다 |

## 치르는 값

- **과거 체결(틱) 이력이 없다.** 바이낸스처럼 '과거 체결 파일 = 정답' 을 쓸 수 없다. 장 중에 받은 실시간 체결로
  스트림 1분봉을 만들고, 장 마감 뒤 **분봉 조회**를 정답으로 맞댄다. 분봉은 원천에 최대 1 년만 남는다(공식 예제).
- 키가 필요하다 — 키 없이 도는 것은 합성 시연뿐.
- 같은 키로 주문을 '부를 수는' 있다. 막는 것은 코드의 허용 목록이다. 그래서 허용 목록은 시험으로 지키고,
  기본을 모의투자 키로 둔다.
- 원천이 체크섬을 주지 않아 '받은 것이 원천과 같다' 를 원천 쪽 값으로 증명할 수 없다 — 받은 뒤의 손상 · 변조만 잡는다.
- 한도: 토큰 발급 1 분에 1 번, 초당 호출 한도(모의가 더 낮음 — 공식 예제 간격 실전 0.05 초 · 모의 0.5 초, 정확한
  숫자는 확인 필요), 실시간 구독 종목 수는 확인 필요. 재배포 조건 확인 필요 → 받은 자료는 커밋 · 공개하지 않는다.
- 실시간 웹소켓 주소가 공식 설정에서 `ws://`(암호화 없음)다 — 접속키가 평문으로 간다(확인 필요).
