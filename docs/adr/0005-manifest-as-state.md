# 0005 — '이미 받았나'는 커밋한 체크섬 목록으로 판단한다

- 상태: 채택 · 2026-10-21
- 관련: [`manifests/bronze/binance.csv`](../../manifests/bronze/binance.csv) · [`mdp.bronze.sync`](../../src/mdp/bronze/sync.py)

## 맥락

증분 받기 · 백필은 '무엇을 이미 받았는가'를 알아야 한다. 데이터 파일은 커밋하지 않는다(재배포 조건 확인 전).
그러면 다른 PC에서 받은 사람이 같은 파일을 받았는지는 무엇으로 아나?

## 결정

- 받은 파일마다 `상대 경로 · 크기 · SHA-256` 한 줄을 체크섬 목록 CSV에 남기고, **그 목록을 저장소에 커밋한다**.
- '이미 받았나'(받기), '무엇을 읽나'(Silver 출처 계획), '받은 뒤 바뀌지 않았나'(읽기 직전 재대조)를 모두 이 목록으로 한다.
- 실행 기록 DB(PostgreSQL)는 '언제 누가 돌렸나'를 남길 뿐, 판단에는 쓰지 않는다.

## 다른 안

| 안 | 버린 이유 |
|---|---|
| 실행 기록 DB를 상태로 | DB가 꺼져 있거나 다른 PC면 판단이 달라진다. 기준이 둘이 된다 |
| 디스크를 뒤져 판단 | 반쯤 받은 파일 · 바뀐 파일을 구분할 수 없다 |

## 치르는 값

- 목록 파일과 실제 디스크가 어긋날 수 있다(예: Bronze 위치를 잘못 연결). 이때 받기는 '목록에 있으니 건너뜀'으로
  판단하고, 읽는 쪽이 파일이 없거나 SHA-256이 다르면 멈춘다 — 조용히 틀리지 않고 시끄럽게 멈춘다.
- Airflow를 처음 켤 때 Bronze 위치가 기본값(빈 폴더)으로 연결된 것을 돌리기 전에 발견해, 켜는 방법을 문서에
  적었다(4-6).

## 근거

- Airflow로 같은 달을 다시 돌렸을 때(4-6) 받기 두 작업이 `skipped_known`으로 끝나 내려받기 0, 3초 · 2초.
- 샘플 시연(6-1)의 합성 Bronze도 같은 형식의 목록을 만들어, Silver · Gold · 재생이 진짜와 같은 코드로 돌았다.
