# 0011 — 공개 시연은 합성 데이터 + 정답지

- 상태: 채택 · 2026-10-24
- 관련: [샘플 시연 기록](../SAMPLE.md) · [`mdp.sample`](../../src/mdp/sample)

## 맥락

저장소를 받은 사람이 바로 돌려 볼 수 있어야 한다. 그런데 진짜 데이터는 한 달 체결만 850MB이고, 바이낸스 데이터의
재배포 조건은 확인 전이라(확인 필요) 저장소에 넣을 수 없다. 또 진짜 2024-03은 결함이 0개라 감사 규칙이 무엇을
잡는지 보이지 않는다.

## 결정

- 합성 종목 `DEMOUSDT` 3일치를 **바이낸스 아카이브와 같은 모양**(zip · 체크섬 목록)으로 만든다. 늘 같은 씨앗 ·
  zip 안 파일 시각 고정 → 몇 번 만들어도 같은 바이트.
- 결함 5종을 정해진 자리에 넣고, **만드는 쪽이 정답지를 함께 적는다**.
- 시연기는 순서만 알고, 각 단계는 **진짜 데이터에 쓰는 명령 그대로** 부른다(다른 것은 레이크 위치와 종목뿐).
- 확인은 만든 엔진(Spark)과 다른 DuckDB로 Delta 표를 직접 읽어 한다([0003](0003-spark-writes-duckdb-reads.md)).
- `data/sample/` 아래에만 쓰고, 다시 돌릴 때 지우기 전에 그 폴더가 `data/` 아래이고 정답지가 있는지 확인한다.

## 다른 안

| 안 | 버린 이유 |
|---|---|
| 진짜 데이터 일부를 저장소에 | 재배포 조건 확인 전 |
| 시연 전용 작은 파이프라인 | '시연은 되는데 진짜는 안 되는' 일이 생긴다 |
| 결함 없는 합성 데이터 | 감사가 일하는 것을 보여 줄 수 없다 |

## 치르는 값

- 합성 시장은 진짜 시장의 분포(체결 몰림 · 가격 점프)를 흉내 내지 않는다 — 성능 숫자는 진짜 데이터로 따로 잰다.
- 정답지도 틀릴 수 있다: 처음 '중복 줄 3'으로 적었는데 Silver의 정의(`줄 수 − 서로 다른 번호 수`)로는 4였다. 이때
  파이프라인이 아니라 정답지를 고쳤고, 그 이유를 기록에 남겼다.
